## 一、目标

把现有「五组平级词表」重构为与主流背词产品一致的两层结构，并让学习状态成为跨单词本唯一的一份：

1. **单词本**（共用 / 私人，各自多本）成为页面主体唯一组织对象；**待整理生词**改为右上角圆形按钮进入的抽屉，不作并列项。
2. **组合只存成员编号**，多层指针读取，不扁平化，可无限嵌套，对外与普通单词本无差别。
3. **教材词升级为知识点**，与手动录入的词共用一套去重与学习状态。
4. 录入时提供**「加入学习」开关**（模式按钮），默认值取当前模式基线并按录入方式记忆；去重后超过 30 条改为询问。
5. 提供**正在学习**的查看入口与汇总，回答“当前正在学的所有单词在哪里看”。

## 二、需求口径（已确认）

| # | 口径 | 结论 |
|---|---|---|
| 1 | 一级结构 | 页面主体只有**单词本**一类（共用 ↔ 私人，各自多本）；**待整理生词不做并列项**，改为页面右上角圆形按钮进入的页面内插入区（抽屉） |

| 6 | 组合成员 | 单个单词与单词本/组合视为同一层级，可混排、保序；嵌套不限层数 |
| 7 | 默认层级 | 新建单词本默认是一层基层本（词直接在 `wordlist_items`） |
| 8 | 组合创建 | 可把多个单词、多本单词本、多个组合同步合成为新组合 |
| 9 | 教材词 | 进入学习时升级为知识点（`origin='wordlist'`），`is_solidified=1` |

| 12 | 正在学习 | `user_learning` 中 `is_active=1` 且 `proficiency_level < 5` |

**2）新建 `wordlist_children`（组合成员，只存指针）**

```sql
CREATE TABLE IF NOT EXISTS `wordlist_children` (
  `id`         BIGINT NOT NULL AUTO_INCREMENT,
  `parent_id`  INT NOT NULL COMMENT '组合 wordlists.id',
  `child_type` VARCHAR(8) NOT NULL COMMENT 'list=单词本/组合 / word=单个词条',
  `child_id`   BIGINT NOT NULL COMMENT 'list→wordlists.id；word→wordlist_items.id',
  `order_no`   INT NOT NULL DEFAULT 0,
  `created_at` DATETIME NOT NULL DEFAULT CURRENT_TIMESTAMP,
  PRIMARY KEY (`id`),
  UNIQUE KEY `uk_child` (`parent_id`, `child_type`, `child_id`),
  KEY `idx_parent_order` (`parent_id`, `order_no`),
  KEY `idx_child` (`child_type`, `child_id`)
) ENGINE=InnoDB DEFAULT CHARSET=utf8mb4 COLLATE=utf8mb4_unicode_ci COMMENT='组合成员指针';
```

**3）`knowledge_points` 增列 + 唯一键**

```sql
`origin`     VARCHAR(16) NOT NULL DEFAULT 'manual' COMMENT 'manual=用户录入 / wordlist=词表升级'

UNIQUE KEY `uk_user_norm` (`user_id`, `normalized_key`)
```

**4）`user_learning` 增唯一键**

```sql
UNIQUE KEY `uk_user_kp` (`user_id`, `knowledge_id`)
```

| 步 | 动作 |

## 五、关键实现规则

### 5.1 组合递归展开

```
expand(listId, depth, visited):
  if depth > 32        → 报错“组合层级超过 32 层”
  if listId in visited → 报错“检测到组合环路”
  wl = get(listId)
  if wl.kind == 'book':
      yield wordlist_items(listId)
  else:
      for child in children(listId) order by order_no:
          if child.type == 'list': yield expand(child.id, depth+1, visited+[listId])
          else:                   yield wordlist_item(child.id)
```

- 去重键：`normalized_word`，保留首次出现。
- 错误码：层级超限 / 环路 → `400`，文案直接给用户看。
- 写入成员时向上遍历祖先链，若 `child` 是自身或祖先 → `400` 拒绝。

### 5.2 计数

- `wordlists.item_count`：基层本 = `COUNT(wordlist_items)`；组合 = 展开去重后的数量。
- 组合成员变动时置 `count_dirty=1`；读取时若 `count_dirty=1` 则重算并清零。
- 子节点变动不向上冒泡扫描，靠读取时按 `count_dirty` + 深度重算兜底；组合列表页只在 `count_dirty=1` 时重算该本。

### 5.3 教材词升级为知识点

```sql
-- 逐词执行（批量用事务包裹）
INSERT IGNORE INTO knowledge_points
  (user_id, user_input_content, standard_content, normalized_key, identity_snapshot,
   is_solidified, origin, source_ref, solidify_time)
VALUES (?, ?, NULL, ?, '', 1, 'wordlist', ?, NOW());

-- 取 id 后写释义（仅当该知识点无释义时）
INSERT IGNORE INTO kp_definitions (knowledge_id, pos, meaning, display_order) VALUES (?, ?, ?, 0);

-- 回填词条映射
UPDATE wordlist_items SET knowledge_id=? WHERE id=?;

-- 开关开启时建学情
INSERT IGNORE INTO user_learning (user_id, knowledge_id, proficiency_level, review_mode,
  review_times, error_times, next_review_time, last_review_time, create_time)
VALUES (?, ?, 0, 'daily', 0, 0, NOW(), NULL, NOW());
```

- `is_solidified=1`：教材词已有标准词面与释义，不进固化队列。
- `standard_content` 留 NULL，读取时按 `COALESCE(NULLIF(standard_content,''), user_input_content)` 兜底（现有查询已如此）。

### 5.4 「加入学习」开关

**默认值 = 模式基线 + 同模式下该方式的用户覆盖**

| T004 模式 | 语义 | 开关基线 |
|---|---|---|
| `function` 功能模式 | 随手学、单点任务 | **关**（先收录，需要时再学） |
| `plan` 计划模式 | 长期计划、按天安排 | **开**（按计划录入即进学习） |

| 方式键 | 入口 | 记忆键 | 开关 |
|---|---|---|---|
| `manual` | 手动录入单个词 | `entryStudy:<uid>:<mode>:manual` | 有 |
| `bulk` | 粘贴 / 文件 / AI 生成 | `entryStudy:<uid>:<mode>:bulk` | 有，> 30 转询问 |
| `copy` | 共用单词本复制到私人 | `entryStudy:<uid>:<mode>:copy` | 有，> 30 转询问 |
| `combo` | 组合创建 | — | 无（不产生新词条） |
| `textbook` | 教材整册录入 | — | 无（必然 > 30，直接询问） |

- 读取顺序：`localStorage[键]` → 该模式基线。
- 用户切到另一模式时，按该模式的键/基线重新取值，不沿用上一模式的选择。
- 询问弹窗不读、不写默认值。
- 关闭只影响本次新建，不删除已有学情。

### 5.5 待整理生词入口（非并列）

- 位置：单词管理页标题区右上角，圆形按钮（FAB），内部显示计数徽标。
- 点击：打开抽屉（`drawer-overlay`，不整屏覆盖），内容为待整理单词列表 + 搜索 + 排序 + 「全部放进生词本」。
- 不进入左侧导航、不做页签、不与其他单词本卡片混排。
- 计数来源沿用 `GET /api/wordlists/my-words` 的 `total`。

### 5.6 30 条阈值

```
先调 /api/kp/preview 或 /api/wordlists/:id/expand 取 to_create
to_create > 30 → 弹「本次将新建 N 个单词，是否加入学习？[加入学习][仅录入]」
to_create ≤ 30 → 用该方式的记忆默认值
```

判定基于**去重后待新建数**，不是解析行数。

### 5.7 归一化统一

把 `wordlist_items.normalized_word` 与 `knowledge_points.normalized_key` 的生成收敛到同一个后端函数（现状：SQL `REGEXP_REPLACE` 与 C++ 各写一份），C++ 侧统一调用后再落库；SQL 迁移脚本保持同规则。

### 5.8 UI 落地要求（依据 `00-设计指导总纲.md`）

| 要求 | 落地 |
|---|---|
| 令牌集中 | 颜色/间距/圆角/动效只用 `style.css :root` 变量；新增变量先落 `:root`，页面禁止魔法值与行内样式 |
| 扩展内容用浮层 | 待整理生词、新建、组合成员选择、30 条询问全部走 `drawer` / `overlay`，不整屏跳转 |
| 六态覆盖 | 每块区域实现：默认 / 加载（骨架）/ 空（引导行动）/ 错误（可重试）/ 成功 / 边界（0 条、超长标题、数千条） |
| 一屏一焦点 | 单词管理页主行动是“新建单词本”；待整理按钮为次级悬浮按钮，不与主按钮争夺视觉 |
| 图形化优先 | 进度用数字 + 细进度条；标签用 `pill`；组合路径用面包屑而不是纯文字说明 |
| 离线与非框架 | 不引入三方库；沿用本地 woff2；装饰用纯 CSS/SVG |
| 明暗主题 | 只用语义变量，`html[data-theme="dark"]` 下自动生效，不写死颜色 |
| 人工修改渠道 | 新增样式在 `components.css` 分段注释标注可调变量 |
