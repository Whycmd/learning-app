## 四、验收标准

- [x] 导航问「能不能练日语听力」→ 回复含「暂不在本应用范围」类文案、无编号，`dev_backlog` 落 `rejected/out_of_scope`
- [x] 导航报「导出单词卡点了没反应」→ 回复末尾 `#G{id}`，`dev_bugs` 落 `new`，`category=export`、`page_path` 为当前页
- [x] 提「想要横版单词卡」→ 回复末尾 `#B{id}`，`dev_backlog` 落 `new/in_scope`
- [x] 普通学习提问（如「decay 怎么记」）→ 正常回答，两表无新增
- [x] Mock 返回低置信判定 → `triage` + `#T{id}` 回执
- [x] Mock 返回纯文本/坏 JSON → 正常回复、不记录、不报错（降级）
- [x] 同标题重复提交 → 行数不变、`occurrences+1`、`last_seen_at` 更新、编号不变、状态不变（D7）
- [x] 游客提交 → 落表 `user_id=0`、`source_message_id` NULL，回执正常
- [x] 非 admin（含未登录）访问 5 条接口 → 403（未登录 401）；`dev.html` 显示不可访问提示，不显示数量
- [x] admin 在看板改状态/优先级/严重度/备注/`duplicate_of` → 保存成功、刷新保留；非法枚举 400；`duplicate_of` 指向不存在 id 返回 400
- [x] 待分拣页签合并两表 `triage`，按 `last_seen_at` 降序；徽标与 summary 一致
- [x] 界面零机制说明文字、零技术术语（中文状态映射，P6 口径）
- [x] `users.role` 加列幂等；既有登录/会话回归不受影响
- [x] stage34 全绿；全量回归全部套件通过（HOME-NAV stage33 因 prompt 改动需重点复跑，区分网络抖动与缺陷）

## 五、风险与应对

| 风险 | 应对 |
|---|---|
| 模型不按 JSON 契约输出，判定缺失 | 降级路径为默认行为（不记录、不阻断）；prompt 给输出示例；测试覆盖坏 JSON/纯文本 |
| 修改 `AI_NAV_SYSTEM` 影响 HOME-NAV 已验收的回复质量 | stage33 全量复跑；`plainText` 保留对旧格式（reply/answer/text/content 键）的兼容 |
| 判定 JSON 挤占 `max_tokens`（现 600） | 上调至 800 并落 `config/ai_nav.json` 可配；回复长度约束保留 |
| 游客不限次 + 自动落表被刷 | 现有 6 次/分节流 + 精确去重只计数不增行；看板按 occurrences 排序天然暴露刷量条目；不新增限额 |
| `users.role` 加列触及其他读 `users` 全列的语句 | 加列带默认值；排查 `SELECT *` 使用点，回归 stage3/stage20 认证套件 |
| 与 HOME-NAV 收口顺序纠缠（其未收口） | 本任务基于其已验收代码继续开发；两任务各自收口时分别同步文档，登记表补录 `v1.5.1-T005` 完成与 `v1.5.2-T001` 取号 |
