## 一、用户流程

```
用户在 AI 导航提问（任意页面，登录/游客均可）
  → 导航 AI 单次调用同时输出：回复文本 + 结构化判定（kind/title/category/confidence）
  → 代码按判定表处置：
      answerable      → 不记录，正常回复
      feature_request → 写入 dev_backlog，回复末尾附 #B{id}
      bug             → 写入 dev_bugs，回复末尾附 #G{id}
      out_of_scope    → 写入 dev_backlog（rejected），不附编号
      低置信          → 对应表 status='triage'，附 #T{id}
      解析失败        → 降级：只回复文本，不记录、不编号（对话不阻断）
  → 重复反馈：同 dedupe_key 只 occurrences+1、更新 last_seen_at，编号不变、状态不变

开发者（admin）浏览器直接访问 /pages/dev.html
  → 三页签查看台账 → 行内改状态/优先级/严重度/备注 → 保存（PUT）→ 刷新后保留
非 admin 访问：接口一律 403；页面显示「此页面仅开发者可访问」，不显示任何条目数量
```

## 三、判定契约（AI 输出）

`AI_NAV_SYSTEM` 要求模型输出单个 JSON 对象：

| 字段 | 类型 | 说明 |
|---|---|---|
| `reply` | string | 给用户的自然语言回答（保持现有导航语气与长度约束） |
| `kind` | enum | `answerable` / `feature_request` / `bug` / `out_of_scope` |
| `title` | string | ≤30 字短标题（非 answerable 必填；归一化后用于去重） |
| `category` | string | 需求：`feature`/`enhancement`；Bug：`ui`/`api`/`data`/`export`/`content`；可缺省（D8） |
| `confidence` | 0–1 | 模型自评置信度 |

判定规则写入 prompt（与 PRD R45/R47 一致）：
- 现有功能能回答 → `answerable`；
- 做不到但与英语学习/讲解/练习/词表/导出/计划相关 → `feature_request`；
- 应用异常（报错、白屏、按钮无反应、数据不显示、导出失败、讲解内容错误）→ `bug`；**用户答错、不会做、要求换题不算 Bug**；
- 与产品定位无关（日语、游戏、社交等）→ `out_of_scope`。

代码侧处置表（阈值 `confidence_threshold` 默认 0.6，可配）：

| kind | confidence | 落表与初始状态 | 回执 |
|---|---|---|---|
| answerable | — | 不记录 | 无 |
| feature_request | ≥ 阈值 | `dev_backlog` `new`、`in_scope` | 回复末尾「已记录 #B{id}」 |
| feature_request | < 阈值 | `dev_backlog` `triage` | 「已记录，待开发者确认 #T{id}」 |
| bug | ≥ 阈值 | `dev_bugs` `new` | 「已记录 #G{id}」 |
| bug | < 阈值 | `dev_bugs` `triage` | 「已记录，待开发者确认 #T{id}」 |
| out_of_scope | ≥ 阈值 | `dev_backlog` `rejected`、`out_of_scope` | 无编号；回复含「暂不在本应用范围」 |
| out_of_scope | < 阈值 | `dev_backlog` `triage`、`out_of_scope` | #T 回执 |
| 缺失/非法/解析失败 | — | 不记录（降级纯文本回复） | 无 |

回执 = 编号 + 通俗处理说明（如：会逐条看、合适就做进应用 / 开发者会尽快排查 / 需开发者确认具体情况），以证明开发者诚意、把话说清楚、通俗易懂（2026-11-19 用户裁决更新，取代原「只给编号与已记录」口径）。**不承诺上线时间、不给优先级** 保持不变。回执文案模板全文见 `config/dev_intake.json`；上表回执列为简写示意。

## 四、数据设计（`scripts/sql/22_dev_intake.sql`，幂等）

InnoDB、utf8mb4、无外键。字段与 PRD §3.13 一致，类型落地：

**`dev_backlog`**

| 字段 | 类型 | 说明 |
|---|---|---|
| `id` | INT PK AI | 编号即 `#B{id}` |
| `source_message_id` | BIGINT NULL | 登录用户取 `ai_nav_messages` 用户消息 id；游客 NULL |
| `user_id` | INT NOT NULL DEFAULT 0 | 0=游客 |
| `title` | VARCHAR(200) | AI 短标题（原文） |
| `detail` | TEXT | 触发消息片段（≤500 字，复用导航 `max_chars` 上限） |
| `category` | VARCHAR(12) | feature / enhancement |
| `scope_fit` | VARCHAR(12) | in_scope / out_of_scope |
| `confidence` | DECIMAL(3,2) | 判定置信度 |
| `dedupe_key` | CHAR(40) UNIQUE | sha1(kind+'\|'+归一化标题)；归一化=小写、去标点、合并空白 |
| `occurrences` | INT DEFAULT 1 | 被提次数 |
| `status` | VARCHAR(12) | new / triage / accepted / planned / shipped / rejected |
| `priority` | VARCHAR(4) NULL | P0 / P1 / P2 |
| `admin_note` | VARCHAR(500) NULL | 备注 |
| `created_at` / `updated_at` / `last_seen_at` | DATETIME | |

**`dev_bugs`**：同结构，差异字段：`category`（ui/api/data/export/content）、`page_path` VARCHAR(100)、`error_code` VARCHAR(32) NULL（本期无采集来源，恒 NULL，留 admin 补录）、`severity`（blocker/major/minor）、`status`（new/triage/confirmed/fixing/fixed/closed/duplicate）、`duplicate_of` INT NULL（自关联，代码校验存在性）。

**`users` 增列**：`role VARCHAR(10) NOT NULL DEFAULT 'user'`（D4）。

**隐私边界**（PRD 已裁决）：只存触发消息片段、页面路径、`user_id`；不存完整对话；两表不出现在任何普通用户页面与接口。

## 五、接口（全部仅 admin，非 admin 403，未登录 401）

| Method | Path | 说明 |
|---|---|---|
| GET | `/api/dev/backlog` | 默认排除 `rejected`；支持 `status` / `scope_fit` / `priority` 过滤；排序 `occurrences DESC, last_seen_at DESC` |
| PUT | `/api/dev/backlog/:id` | 白名单字段：`status` / `priority` / `admin_note`；枚举校验，非法 400 |
| GET | `/api/dev/bugs` | 默认排除 `duplicate`；支持 `status` / `severity` / `category`；排序 `severity(blocker>major>minor), occurrences DESC` |
| PUT | `/api/dev/bugs/:id` | 白名单：`status` / `severity` / `admin_note` / `duplicate_of` |
| GET | `/api/dev/summary` | 各状态计数（页签徽标 + 页面可访问性探测） |

admin 校验：按当前会话 `user_id` 查 `users.role`，`uid<=0` 或非 admin 一律 403，不泄露条目数量。

## 六、dev.html 样稿

**入口**：无前台入口，admin 直接访问 URL（D4 裁决的既有口径）。
**不新增页面的理由**：PRD #34/D79/#92/#124 已裁决独立页且与 `admin.html` 职责分离；开发者台账面向 admin，不能混入用户页面；同类先例为各产品独立后台看板页。

```
┌ 顶栏（复用现有 nav.js）─────────────────────────────────────┐
│ 开发者看板                                                   │
│ [ 开发计划 ⑫ ]  [ Bug 列表 ⑤ ]  [ 待分拣 ③ ]   ← 页签+徽标  │
├─────────────────────────────────────────────────────────────┤
│ 筛选：状态▾ 优先级▾            （Bug 页签：状态▾ 严重度▾ 分类▾）│
│ ┌─────────────────────────────────────────────────────────┐ │
│ │ #B12  支持日语听力练习                        被提 3 次  │ │
│ │ 状态[新提交▾] 优先级[P1▾] 备注[__________] [保存]        │ │
│ │ 最近 11-18 14:02 · 首次 11-15 · 用户 2        [展开▾]    │ │
│ │  └ 展开：详情（触发消息片段）、分类、置信度              │ │
│ ├─────────────────────────────────────────────────────────┤ │
│ │ #B9   导出单词卡想要横版                       被提 1 次  │ │
│ │ …                                                       │ │
│ └─────────────────────────────────────────────────────────┘ │
│ 空态：「暂无记录」                                           │
└─────────────────────────────────────────────────────────────┘

待分拣页签 = 两表 status='triage' 合并，按 last_seen_at 降序；
行内标注来源（需求/Bug），操作列按来源走各自 PUT 接口。
```

**信息取舍**（P6 口径）：
- 界面显示：编号、标题、被提次数、最近/首次时间、用户 ID、状态、优先级/严重度、备注、详情片段、置信度（仅展开区，供分拣参考）；
- 不显示：`dedupe_key`、`source_message_id`、`scope_fit` 原始值（rejected 条目只在筛选「已拒绝」时可见）、任何机制说明文字；
- 状态/优先级/严重度用中文展示（新提交/待分拣/已采纳/已排期/已上线/已拒绝；阻断/严重/轻微），代码内部保留英文枚举。

**操作→接口映射**：页签徽标→`GET /api/dev/summary`；列表→`GET /api/dev/backlog|bugs`；筛选→同接口参数；保存→`PUT /api/dev/:id`；待分拣合并→两接口 `status=triage` 前端合并。全部为需新增接口（现无同类可复用）。

## 七、异常兜底（PRD 已裁决，实现口径）

| 场景 | 处置 |
|---|---|
| AI 输出非 JSON / 缺 kind | 整段作为 `reply` 返回（兼容现有 `plainText` 逻辑），不记录 |
| 入库失败（DB 异常） | 对话不阻断、不显示编号；返回纯回复 |
| 并发同标题提交 | 唯一键兜底：INSERT 冲突后重查并按重复路径处理 |
| `duplicate_of` 指向不存在 id | 400 |
| 列表为空 | 空态「暂无记录」 |
| 非 admin | 页面/接口 403 口径见 D5、§5 |
