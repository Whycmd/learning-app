# v1.5.0-T004 UI-MODES 开发计划

> 状态：计划待确认 | 创建日期：2026-11-09
> 代号：`UI-MODES` | 任务名：功能模式 / 计划模式

## 零、需求裁决（2026-11-09）

| 项 | 裁决 |
|---|---|
| 默认模式 | **功能模式**（随手学），界面以功能入口为主 |
| 模式切换 | 顶栏提供**显著、常驻**的切换按钮，随时可改 |
| 记忆方式 | **账号级**；游客用本机 `localStorage` 兜底，登录后以账号为准 |
| 作用范围 | **仅首页 + 顶栏**；其他页面结构与内容不改 |
| 计划模式入口 | 功能模式下保留显著标签与适时提醒，不强制、不弹窗打断 |
| 功能完整性 | **只折叠、不删除**：所有页面仍可直达，深链不 404、不强制跳回 |

命名约定：UI 文案用「功能模式 / 计划模式」，代码与数据库用 `function` / `plan`。

## 一、目标

新用户默认进入功能模式，以最少入口完成“AI 讲解、定制练习、复习、小测、词表”等单点任务；需要长期计划时，通过顶栏显式切换到计划模式，获得课规、周报、目标、错题等完整链路。两套模式共用同一套功能与数据，只在首页与顶栏产生展示差异。

## 三、任务分解

### T1 数据库迁移

- 新增 `scripts/sql/13_ui_mode.sql`，用存储过程判断列是否存在后追加，保证可重复执行。
- 字段：`ui_mode VARCHAR(16) NOT NULL DEFAULT 'function' COMMENT '界面模式：function=功能模式，plan=计划模式'`，放在 `learner_identity` 之后。
- 不做存量回填：默认值即功能模式；系统账号 `user_id=1` 同样适用。

### T2 后端接口

- `AuthService::Result` 增加 `std::string ui_mode;`
- `userInfo()` 的 SELECT 增加 `ui_mode`，返回给上层。
- `updateProfile(userId, displayName, learnerIdentity, uiMode)`：
  - `ui_mode` 为空 → 不改；
  - 只接受 `function` / `plan`，其他值返回 400；
  - 响应回显实际生效值。
- `handleAuthMe`：游客返回 `{"user_id":0,"guest":true,"ui_mode":"function"}`；登录用户追加 `ui_mode`。
- `handleAuthProfile`：解析 `ui_mode` 并透传；旧客户端只传 `display_name` / `learner_identity` 时行为不变。
- 不新增路由，不修改路由注册顺序。

### T3 顶栏模式切换

- `nav.js` 顶部先读 `localStorage.eng_ui_mode`，立即给 `<html>` 加 `data-ui-mode`，避免闪烁；随后用 `/api/auth/me` 的 `ui_mode` 校正。
- 顶栏右侧、主题按钮左侧增加模式胶囊：
  - 文案：`功能模式` / `计划模式`；
  - 点击展开两项菜单，含一句差异说明与当前选中态；不使用单击直接切换，避免误触。
- 登录用户切换 → `PUT /api/auth/profile {"ui_mode":"plan|function"}`；乐观更新，失败回滚并提示。
- 游客切换 → 写 `localStorage`，并提示一次「登录后可跨设备同步」。
- 功能模式顶栏保留：首页、学习（知识点录入/详情/单词本）、练习（每日复习/每日小测）、模式胶囊、激励区、用户区、主题。
- 功能模式隐藏：文章阅读、学情中心；这两页仍可通过直接 URL、模式菜单中的「计划模式专属入口」到达。
- 计划模式顶栏维持现状。

### T4 首页双模式

- `index.html` 的 `<html>` 预设 `data-ui-mode="function"`。
- 计划模式区块加 `plan-only`：五幕叙事轴、本周课规卡、今日所得卡、登阶、留印。
- 功能模式区块加 `function-only`：在 `.hall` 内新增与计划模式同款的 **`.hall__wing` + `.wing-card` + `.task-list`** 厢房卡，五个 `.task-item` 入口：
  - AI 讲解 → `/pages/kp-entry.html`
  - 定制练习 → `/pages/review.html`
  - 每日复习 → `/pages/review.html`
  - 每日小测 → `/pages/daily-quiz.html`
  - 词表库 → `/pages/wordbook.html`
- 不新增独立卡片视觉：不添加 `start-panel` / `start-card` 等新样式，全部复用 `wing-card`、`task-item`、`btn`、`state-line` 既有组件与令牌。
- 提醒卡同样复用 `wing-card`，作为功能模式西厢的第二张卡，默认 `hidden`。
- 两种模式都保留：圣殿主屏（熟练度/称谓/四技能外观）、观卷、AI 服务状态。
- 显隐用 CSS：`[data-ui-mode="function"] .plan-only { display:none }`，`[data-ui-mode="plan"] .function-only { display:none }`；不复制首页文件。
- 页面初始化脚本按模式跳过被隐藏区块的数据请求，避免无谓接口调用和报错。

### T5 适时提醒

- 仅在首页显示一条可关闭提示条，`function-only`，不弹窗、不遮挡内容。
- 触发条件（同时满足）：
  1. 已登录且为功能模式；
  2. 当前无进行中的本周课规（`GET /api/treasury/weekly-goal` 返回空）；
  3. 完成过至少 3 次 AI 讲解或已使用产品满 3 天（本机计数）。
- 频率：关闭后 7 天内不再出现；`localStorage` 记录关闭时间，不使用服务端新表。
- 文案示例：「你在功能模式。设定课规后，可以按天安排复习与新词。」按钮「看看计划模式」→ 切换到计划模式并打开课规抽屉。

### T6 测试

  - `PUT /api/auth/profile` 可切换 `function` / `plan`，非法值 400，空值不改；

## 五、风险与应对

| 风险 | 应对 |
|---|---|
| 模式混淆，用户不知道自己在哪套界面 | 顶栏常驻文字胶囊；切换菜单含差异说明；不靠图标或颜色单独表达 |
| 功能模式藏入口导致“功能消失”误解 | 功能模式提供五入口卡；模式菜单保留「计划模式专属入口」；深链始终可达 |
| 游客偏好与账号偏好冲突 | 游客用本机值；登录后以账号值覆盖，并提示一次；不做自动合并写回 |
| 首页闪烁或布局跳动 | `<html>` 预设 `data-ui-mode="function"`；`nav.js` 先读本机值再校正；CSS 只做显隐 |
| 双份回归成本 | 不复制页面，只加显隐类；测试覆盖两模式首页关键区块与深链 |
| 提醒变成骚扰 | 仅提示条、可关闭、7 天冷却、首次不弹；不使用服务端新表 |
| 数据库迁移在已有库不生效 | 幂等存储过程；开发库手动执行一次；测试库由 `tests/run_all.js` 重建时自动执行 |

## 六、不在本次范围

- 不改其他页面内部结构（仅顶栏由 `nav.js` 统一收敛）。
- 不做按使用行为自动切换模式。
- 不做移动端 `/m/` 适配。
- 不调整 AI 提示词、出题、批改、导出逻辑。
