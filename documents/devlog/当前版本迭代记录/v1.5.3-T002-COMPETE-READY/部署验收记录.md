## 二、实施步骤

1. 系统初始化：设置时区、创建 2G swap、确认磁盘与内存（内存 1.7 GiB 可见 / swap 2 GiB）。
2. 安装容器运行时：`apt-get install -y docker.io docker-compose-v2`
   （Docker 29.1.3 / Compose v2.40.3；云镜像未预装 Docker，`systemctl enable --now docker` 会报 Unit 不存在）。
3. 上传代码到 `/opt/english-app`；写入 `.env.prod`（权限 `600`），包含 MySQL root/应用密码与 `ZHIPU_API_KEY`。
4. 构建并启动：
   `docker compose --env-file .env.prod -f docker-compose.prod.yml up -d --build`
5. 验证容器状态：`elf-db` 健康、`elf-app` 运行；`80 → 8088`；3306 未映射到宿主机；`restart: always` 生效。
6. 线上功能回归（见第四节）。

## 三、过程中遇到的问题与处理

| 问题 | 现象 | 处理 |
|---|---|---|
| Docker 未预装 | `Failed to enable unit: Unit file docker.service does not exist.` | 改用 `apt-get install -y docker.io docker-compose-v2` 安装 |
| Debian 软件源不可达 | 构建阶段 `apt-get update` 卡在 `deb.debian.org`（握手约 4 秒、下载停滞） | 在服务器端 `Dockerfile` 两个阶段的 `apt-get update` 前，把 `/etc/apt` 下源文件中的 `deb.debian.org` 替换为 `mirrors.aliyun.com`（`mirrors.aliyun.com` 实测 0.1 秒可用），重建成功 |
| AI Key 格式错误 | 网关调用智谱返回 `401 令牌已过期或验证不正确`；首次填入的 Key 为 51 位且无点 | 改用 `~/.config/eng-app/ai.key` 中的有效 Key（49 位、含一个点），网关自测返回 `{"choices":[...{"content":"正常"}]}` |
| SSH 自断连接（exit 255） | `pkill -f "docker compose"` / `pkill -f "http.server 80"` 匹配到 SSH 命令自身 | 改用 `pgrep -f "[d]ocker compose"`、`fuser -k 80/tcp`；禁止用会匹配自身命令行的 `pkill -f` |
| 临时探针占用 80 | 部署前健康探针监听 80 端口 | 用 `fuser -k 80/tcp` 关闭后再启动 compose |

> 说明：服务器端 `Dockerfile` 的镜像源补丁目前只存在于服务器，仓库内 `Dockerfile` 未改动，已登记为遗留事项。
