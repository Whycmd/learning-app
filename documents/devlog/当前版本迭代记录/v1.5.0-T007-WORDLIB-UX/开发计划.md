## 一、目标

在不新增 AI 能力的前提下，修复教材搜索与教材词详情的显示缺陷，并把单词本页重排为「Tab + 分类筛选 + 折叠 + 数量控制」，让私人单词本、新建组合、待整理生词入口一屏可达。

## 二、需求口径（已确认）

| # | 反馈 | 本轮结论 |
|---|---|---|
| 1 | 搜索框输入教材名字没有显示 | 搜索框同时匹配单词与单词本/教材名称；结果分「单词本」与「单词」两组 |
| 2 | 对讲解不满意时重新生成 | **不在本轮**；转入 `v1.5.0-T006` AI 讲解范围，列入总开发计划 |
| 3 | 教材内部词汇界面显示异常 | 修复“选择词条”页为空/红字报错；修复单元词条卡无释义、右侧溢出 |
| 4 | 共用单词本篇幅过大、随数量增长 | 顶部「共用 / 私人」Tab；共用按官方/教材/社区筛选；册/组可折叠；每组默认限量 + 显示更多 |
| 5 | 私人单词本在最下方找不到 | 私人 Tab 一键直达；登录用户默认选中私人 |
| 5b | 待整理按钮看似可拖动 | 加入拖拽并记忆位置；位移阈值内仍视为点击 |
| 6 | 找不到新建组合入口 | 私人区显式提供「新建组合」；成员可混合选择单词本/组合/单词；详情页可管理成员 |

### 已核实的事实

- 搜索接口 `GET /api/wordlists/search` 只匹配 `wordlist_items.normalized_word`，不匹配词表/教材标题，导致输入教材名无结果。
- 教材种子 `backend/data/textbook_wordlists/pep2019.tsv` 只有 `word` 列；实测 `wordlist_items` 共 2982 条，`meaning` 非空 **0 条**。因此“缺释义”是数据缺口，不是渲染丢失。
- `kp-detail.html` 只从 `GET /api/kp?size=1000`（当前账号知识点）构建下拉；`?id=` 不在列表时仅提示“词条 #xxx 不存在或已被合并”，列表为空时页面只剩红字。
- 前端目前没有调用 `POST /api/wordlists/compose` 的入口，也没有成员增删/排序界面；只有教材“合并单元为组合词表”。

> 释义补全不在本轮伪造：本轮只把无释义呈现为明确空态。完整释义需进入 `T006`（AI 按需生成）或单独数据补全任务。

## 四、任务分解

### T1 搜索增强
1. `lib-search` 输入后，同时在 `state.builtin / state.user / state.range / state.wordbooks` 中按标题、册、单元、名称做本地匹配。
2. 结果区先显示「单词本」分组（可点击进入），再显示原有「单词」结果。
3. 两组都为空时提示“没有匹配的教材、单词本或单词”，不再只显示“没有匹配单词”。

### T2 教材词详情与词条卡
1. `kp-detail.html`：有 `?id=` 时先 `GET /api/kp/:id`；成功即渲染，并把它补进下拉或隐藏下拉。
2. 404/已合并：回退到当前账号列表；列表为空时显示“该词条不在当前账号，去教材页「开始学习」后查看”，移除误导性红字。
3. 单词本详情词条卡：`meaning` 为空时显示中性空态“释义待补充”，不再只留词面和“已固化”；教材词标签改为「教材词」，用户已加入学习的才显示「已固化」。
4. 修复卡片右侧溢出：容器 `min-width:0`、长词 `overflow-wrap:anywhere`、网格与内边距在窄屏收敛。

### T3 单词本页布局
1. 顶部控件：`共用单词本 | 私人单词本` 两个 Tab；登录用户默认私人，游客默认共用，`localStorage` 记忆上次选择。
2. 共用 Tab：`官方 / 教材 / 社区提供` 筛选；教材册可折叠，默认展开第一册，其余收起；`展开全部 / 收起全部`。
3. 私人 Tab：`自建词表 / 组合 / 生词本` 筛选；每组默认显示 6 张，超出显示「显示更多（共 N）」；工具栏固定「+ 新建单词本」「+ 新建组合」。
4. 卡片压缩为紧凑样式（标题 + 词数 + 标签 + 操作），保留原悬浮与键盘可达性。

### T4 待整理生词 FAB 拖拽
1. Pointer 事件拖拽，限制在视口安全区；松手吸附到最近左右边缘。
2. `localStorage` 记忆位置（按用户隔离），刷新后恢复。
3. 位移 ≤ 6px 视为点击，仍打开抽屉；提供键盘 Enter/Space 打开。
4. 拖动时显示抓取光标与轻微缩放，明确“可拖动”。

### T5 新建组合与成员管理
1. 私人 Tab 工具栏新增「+ 新建组合」，抽屉内说明“只记录成员，不复制词条”。
2. 成员选择器三块：我的单词本、我的组合、单个单词（先选一本词表再搜索/勾选）。
3. 已选成员区支持移除与上移/下移，保存调用 `POST /api/wordlists/compose`。
4. 组合详情页新增「管理成员」，复用同一抽屉：加载 `GET /:id/children`，保存时按差异调用 `POST /:id/children`、`DELETE /:id/children/:childId`、`PUT /:id/children/order`。
5. 组合卡片与普通单词本保持同外观，不新增“组合”徽标；仅详情页标题下显示成员数。

### T6 自测、回归与文档
1. 新增 `tests/stage25_wordlib_ux.test.js`：静态结构（Tab/筛选/组合入口/拖拽钩子）、教材词条空释义不报错、组合成员增删/排序接口回归。
2. 浏览器自测：搜索教材名、教材词详情、Tab/筛选/折叠、FAB 拖拽与点击、新建组合混合成员、成员管理。
3. 全量 `node tests/run_all.js` 全绿后同步 devlog 与登记表；版本维持 v1.5.0。

## 八、追加需求（2026-11-12）：整本加入改为层级成员

**反馈**：「进入单词界面使用整本加入后，无法看到结果」；「加入后，原单词本应该可以显示目标内部单词本，采用层级框架可以查看内部单词，否则需要使用户收到可复用的结果」。

**已确认口径**（AskUserQuestion）：

1. 方向：**别的本加入当前本**。在当前单词本 A 详情点「整本加入」→ 选择 B → B 作为层级成员出现在 A 中，点进去可查看 B 的内部单词。
2. 当前本若是普通单词本，**自动升级为可嵌套**：保留原有词条，新增整本作为层级成员展示。

**影响面**

| 层级 | 文件 | 变更 |
|---|---|---|
| 后端 | `backend/include/wordlist_service.h` | `importWhole` 统一挂成员指针，不再复制词条；`addChildren/removeChild/reorderChildren` 放开普通单词本；`detail()` 对有成员的普通本返回 `children`；`expandInto/recount/recountDirty` 计入子成员；`remove()` 清理本本作为父级的成员行 |
| 前端 | `frontend/static/wordlib.js` | 抽屉候选改为「教材 + 我的单词本 + 合并本」，提交为 `POST /api/wordlists/<B>/import-whole {target_id: A}`；成功后原地刷新 A；普通本详情新增「包含的单词本」层级区 + 「本书词条」分区，可下钻；有成员时提供「管理成员」 |
| 前端 | `frontend/pages/wordbook.html` | 抽屉文案改为「选择一本要加入当前单词本的单词本」 |
| 测试 | `tests/stage25_wordlib_ux.test.js` | 第 4 段改为层级语义：不复制词条、返回 `children`、成员计入词数、共用教材可加入、环路拒绝；静态契约 17 项 |

**验收**：普通单词本整本加入后立即出现「包含的单词本」并可下钻；词数=自身词条+成员展开去重；重复加入不重复；环路被拒。

**共用词表自动转私有（2026-11-12 第三轮反馈）**：在私有单词本里整本加入「共用」词表时，先执行「复制到自建词表」生成私有副本（标题「原名（副本）」），再挂该副本为成员；同一本共用词表只保留一份副本（`wordlists.scope_key='copy_of:<id>'` 复用），重复加入不会重复复制。`importWhole` 回传 `copied_id/copied_title`，前端提示「已复制为私有本…」。

**UI 细化（2026-11-12 第二轮反馈）**：成员行右侧三角号改为可点按钮，**就地展开**该成员本的内部单词（支持多层递归，不再跳转）；点标题仍进入详情；详情「返回」按钮在层级下钻后变为「返回上一级」，逐级回退后再回列表。涉及 `wordlib.js`（`toggleMember`/`memberRowsHtml`/`btn-back-label`）、`components.css`（`.member-row__toggle`/`.member-sub`/`.member-word`）、`wordbook.html`。
