# prompts.h 人工修改指南（提示词写作版）

> 文件：`backend/include/prompts.h`
> 你只负责修改提示词文字；编译、重启、自测、回归、文档同步交给 AI 开发者。
> 更新日期：2026-10-27

---

## 一、先记住三条底线

1. **只改双引号里的文字**：常量名、函数、括号、逗号、分号一律不动。
2. **保留所有 `{占位符}` 原样**（如 `{LEARNER_IDENTITY}`、`{USER_INPUT}`），不要翻译、不要删除。
3. **不新增字段、不新增占位符**：这类修改会牵动后端解析代码，写好后交给 AI 一起改。

---

## 二、文件长什么样

整个文件是若干 C++ 字符串常量，形如：

```cpp
static const std::string KP_SIX_SECTIONS =
  "第一行文字\n"
  "第二行文字\n";
```

- 相邻的引号内容会自动拼接，`\n` 表示换行，**不要换成真实回车**。
- JSON 示例里的引号写成 `\"`，反斜杠不要删。
- 文件从上到下固定分为 5 段：

| 顺序 | 区段 | 主要常量 | 作用 |
|------|------|----------|------|
| 1 | System 提示词 | `KP_SOLIDIFY_SYSTEM`、`KP_SOLIDIFY_BATCH_SYSTEM`、`EXERCISE_GENERATE_SYSTEM`、`SUBJECTIVE_GRADE_SYSTEM`、`DAILY_QUIZ_SYSTEM` | 角色、只输出 JSON、中英文语言规则 |
| 2 | 学习者身份 | `DEFAULT_LEARNER_IDENTITY` | 游客/未设置时的默认身份 |
| 3 | 固化共享段 | `KP_SIX_SECTIONS`、`KP_RULES`、`KP_REMARK_RULE`、`KP_MARKDOWN_RULES`、`KP_MARKDOWN_EXAMPLE`、`KP_HYBRID_JSON_SCHEMA` | 单条与批量固化共用 |
| 4 | User 任务模板 | `KP_SOLIDIFY_ONE_USER`、`KP_SOLIDIFY_BATCH_USER`、`EXERCISE_GENERATE_USER`、`SUBJECTIVE_GRADE_USER`、`DAILY_QUIZ_USER` | 具体任务说明与输出要求 |
| 5 | 辅助函数 | `replace`、`buildTemplate`、`getLearnerIdentity` | 占位符替换，**不要动** |

`KP_JSON_SCHEMA` 是历史遗留，当前未被引用，不要修改。

## 三、如何找到要修改的部分

直接用编辑器搜索常量名最快。按“我想改什么”查下表：

| 我想改…… | 搜索/修改这个常量 |
|-----------|-------------------|
| 单词精讲要讲哪些内容维度 | `KP_SIX_SECTIONS` |
| 精讲的章节结构、Markdown 写法、篇幅 | `KP_MARKDOWN_RULES` |
| Markdown 课件的排版样板、章节颗粒度 | `KP_MARKDOWN_EXAMPLE` |
| AI 返回哪些字段、字段示例长什么样 | `KP_HYBRID_JSON_SCHEMA` |
| 内容怎么取舍、怎么去套话、短语怎么解析 | `KP_RULES` |
| 用户备注如何影响讲解 | `KP_REMARK_RULE` |
| 单条固化的任务说明 | `KP_SOLIDIFY_ONE_USER` |
| 批量固化的任务说明 | `KP_SOLIDIFY_BATCH_USER` |
| 复习出题 | `EXERCISE_GENERATE_SYSTEM` + `EXERCISE_GENERATE_USER` |
| 主观题批改 | `SUBJECTIVE_GRADE_SYSTEM` + `SUBJECTIVE_GRADE_USER` |
| 每日小测 | `DAILY_QUIZ_SYSTEM` + `DAILY_QUIZ_USER` |
| 默认学习者身份 | `DEFAULT_LEARNER_IDENTITY` |
| 只输出 JSON、中英文语言规则 | 对应任务的 `*_SYSTEM` |

只改一个任务时，**不要动共享段**；共享段一改，单条固化、批量固化会同时变化。

## 四、每一部分怎么改

### 1. System 提示词（5 个 `*_SYSTEM`）

- 只写三件事：AI 的角色、只输出 JSON、展示文本中文 / 目标词和英文例句保持英文。
- 不写具体章节、题型、篇幅，这些属于 User 模板。
- 保持简短，不要在这里重复大段规则。

### 2. `DEFAULT_LEARNER_IDENTITY`

- 只改默认身份字符串，例如 `"高中生"` 改为 `"CET-4 考生"`。
- 单个用户的实际身份来自数据库，不在这里改。

### 3. `KP_SIX_SECTIONS`（讲什么）

- 列出希望 AI 覆盖的内容维度（核心含义、词根词源、同源词、搭配、辨析、语域文化等）。
- 必须与 `KP_MARKDOWN_RULES` 一致：**不能一边写“最多 2 个二级标题”，一边列十几个维度**，否则模型会随机只写一节。
- 极简单词可以少写，但不要允许“只写核心含义与例句”。
- 不适用项让 AI 省略，不要要求写“无”。

### 4. `KP_RULES`（怎么取舍、怎么表达）

- 空值/不适用项：必须整项省略（字段留空、数组用 `[]`、章节连标题一起删），禁止输出“无 / 没有 / 暂无 / 未找到 / 不适用 / none”，也禁止“无固定搭配 / 无同义词 / 无相关典故”等任何“无……”式占位说明。
- 去套话：保留“删除‘是一个 / 指的是’等结构词，只留实质信息”的要求。
- 控制篇幅，但不写“越短越好”这类会压缩内容的表述。
- `standard_content` 必须是目标词本身，不能换成近义词。
- 长短语要额外解析其中的核心词与子短语。
- 不要写与章节数、Markdown 结构冲突的上限。

### 5. `KP_REMARK_RULE`（备注怎么用）

- 备注只影响讲解侧重与义项取舍，**不能因为备注就压缩章节**。
- 不要写“无关维度省略”，这正是熟词生义词条只剩一节的直接原因。
- `{REMARK}` 占位符必须保留。

### 6. `KP_MARKDOWN_RULES`（怎么写）

- 规定 Markdown 语法：`#` 标题、`**粗体**`、`>` 例句引用、`-` 列表。
- 规定最低章节要求（例如除极简单词外至少 3 个二级标题，每节至少 2 条要点或 1 段说明）。
- 规定篇幅：说明性文字上限，英文例句不计。
- 强调 `markdown_content` 是**字符串数组，一行一个元素，元素内不能有真实换行**。
- 没有内容的章节必须**整节删除**（标题与正文一起删），禁止出现“## 固定搭配”后只写“无固定搭配 / 暂无 / 没有”的占位说明。
- 展示说明用中文；目标词、英文例句保持英文。

### 6.1 `KP_MARKDOWN_EXAMPLE`（写作样板）

- 来源：`知识点拓展输出文档示例.docx` 的单词语料，当前以 `venture` 为例。
- 只示范**章节顺序、Markdown 排版、内容颗粒度**；开头和结尾都写明“不得照抄单词与例句”。
- 修改时保持：`# 单词精讲：词` → 音标/使用频率 → `## 核心释义与真题例句` → 词根词源 → 同源词汇 → 固定搭配 → 同义词辨析 → 重点补充。
- 示例展示几节，模型就倾向写几节；**删减示例章节会直接导致输出缩水**。
- 示例篇幅偏详，末尾已提示“实际输出按 `KP_MARKDOWN_RULES` 的汉字上限压缩”；改短示例时同步调整这句。
- 示例中的英文例句、目标词保持英文，说明文字用中文；短语词条可增加“固定用法与语法考点”章节。
- 该常量通过 `{KP_MARKDOWN_EXAMPLE}` 注入单条与批量模板，**占位符不能删**。

### 7. `KP_HYBRID_JSON_SCHEMA`（返回什么字段、示例）

- 字段名被后端直接解析，**不能改名**：
  `standard_content`、`difficulty`、`definitions`、`collocations`、`synonyms`、`antonyms`、`markdown_content`。
- 示例会强烈影响模型输出：**想让它写几节，示例就展示几节**；示例只有一节，模型通常只写一节。
- 示例不要堆得太长，避免模型照抄或超出 token。
- `markdown_content` 示例必须是数组，一行一个字符串元素。
- 只调整示例文字与结构，不要增删字段。

### 8. 固化任务模板（`KP_SOLIDIFY_ONE_USER` / `KP_SOLIDIFY_BATCH_USER`）

- 这里写任务说明、学习者身份引用、共享段占位符、目标词/词表、输出要求。
- 不要删除任何 `{...}` 占位符；共享段的占位符名也不能改。
- 单条与批量的差异：
  - 单条：输出 JSON 对象，使用 `{USER_INPUT}`、`{REMARK_LINE}`、`{EXTRA_NOTE}`、`{KP_MARKDOWN_EXAMPLE}`；
  - 批量：输出 JSON 数组，使用 `{WORD_LIST}`、`{KP_MARKDOWN_EXAMPLE}`，不包含备注行。
- 批量模板要强调“每个词都要完整精讲”，避免模型对简单词偷懒。
- 如果希望“精讲必须多节”，把要求写进共享段，单条和批量会同时生效。

### 9. 出题模板（`EXERCISE_GENERATE_USER`）

- 可改：复习模式说明、掌握要求、页数、题型顺序、题型思路。
- 不可改：输出字段名与结构 `exercises[]`、`quick_memo.items[]`，以及题型标识
  `word_match`、`word_form_fill`、`context_blank_fill`、`cn_to_en_translation`、`cloze_choice`、`sentence_imitation`。
- `quick_memo` 用于核心释义速记，保留。

### 10. 批改模板（`SUBJECTIVE_GRADE_USER`）

- 可改：评判尺度、评语风格。
- 不可改：输出字段 `score`、`correct`、`error_analysis`、`reference_answer`。
- 参考答案为空时由代码传入“无固定标准答案”，不要改这个约定。

### 11. 每日小测模板（`DAILY_QUIZ_USER`）

这一节与解析器强耦合，改动前先确认：

- 固定 5 题、严格 3+1+1（3 已固化 + 1 熟词生义 + 1 新知）。
- 题干必须用 **6 个下划线** 挖空，题干中不能出现答案词。
- 选择题 4 个选项，不带 `A)` 前缀；`answer` 为 A/B/C/D。
- 第 4、5 题必须给 `word`、`meaning`、`example`；`example` 不含挖空、不能照抄题干。
- 末尾 JSON 仅作格式示例，必须写明“内容需重新创作”。
- 这些是解析器硬依赖，改坏会导致小测功能失败；如拿不准，交给 AI 评估。

### 12. 辅助函数

- 不要改。需要新增占位符、改字段或改调用逻辑时，交给 AI 开发者。

## 五、写作提示词的通用规范

- 一条规则一行，短句、可执行，避免大段散文。
- 展示性说明用中文；目标词、英文例句、英文原文保持英文。
- **禁止自相矛盾**：上限、章节数、篇幅要求要互相对齐。
- 示例是“目标形态”，不是“随便举例”；示例过短会直接导致输出缩水。
- 不写“无 / 没有 / none / 不适用”这类占位话。
- 不要求 AI 输出真实换行；`markdown_content` 必须一行一个数组元素。
- 新增要求优先写进共享段，让单条与批量行为一致，减少两套提示词不一致。

---

## 六、改完后的交付方式

把以下信息告诉 AI 开发者即可，不需要自己编译：

1. 改了哪个常量（可贴常量名）。
2. 改前/改后各是什么要求。
3. 期望输出有什么变化（章节数、字段、篇幅、语气等）。

AI 负责：编译、重启、自测、受影响套件、全量回归、文档同步。
若改的是共享段，提醒 AI **单条固化与批量固化都要测**；若动了字段或占位符，AI 还要同步改代码与测试。

## 七、提交前快速检查

- [ ] 只改了双引号里的文字，常量名、函数、分号没动
- [ ] `{占位符}` 全部保留且拼写未变
- [ ] `\n`、`\"` 没有被替换成真实回车或裸引号
- [ ] 章节要求、篇幅要求、示例结构三者一致
- [ ] 示例展示的结构就是期望的输出结构
- [ ] 没有新增字段/占位符；如有，已交给 AI 处理
