### 7 个 API 接口

| 方法 | 路径 | 功能 |
|------|------|------|
| GET | `/api/article/my` | 当前用户文章列表 |

### 核心实现要点

- **分句**：规则分句（45+ 缩写词表），不调 AI，避免误切英文缩写。
- **词汇难度分析**：分词 → EFLLex 查表 → A1→C1 顺序取首个词频 > 0.01 的等级；生词 = cefr > user_cefr+1；边缘词 = cefr == user_cefr+1。
- **EFLLex TSV 解析**：只取前 7 列（word, tag, f_a1~f_c1），剩余列合并到最后，防止长尾列干扰。
- **用户 CEFR**：当前硬编码 B1（后续可从 learner_identity 推断）。
- **文章整体 CEFR**：取各等级词数众数。

## 二、本轮修复的 Bug（详细）

### Bug-1：splitTab off-by-one（阶段 1 引入）

**文件**：`backend/src/articles_vocab_service.cpp` 第 56-76 行

**根因**：原始代码在 `break` 之前先 `cur.clear()`，导致最后一列（f_c1）丢失。且 `size_t col` 计数方式判断 `col >= max_cols - 1` 有 off-by-one。

**旧代码（错误）**：
```cpp
for (char c : line) {
  if (c == '\t') {
    cur += c;
    if (col >= max_cols - 1) break;  // off-by-one
    result.push_back(std::move(cur));
    cur.clear();  // 在 break 之前 clear 丢数据
    col++;
  } else cur += c;
}
```

**新代码（修复后）**：
```cpp
for (char c : line) {
  if (c == '\t') {
    if (result.size() + 1 >= max_cols) cur += c;  // 合并剩余 tab
    else { result.push_back(std::move(cur)); cur.clear(); }
  } else cur += c;
}
result.push_back(std::move(cur));
```

**效果**：EFLLex 加载从 10,140 → **13,546** 词条。sophisticated → C1 ✓

### Bug-2：difficulty-report 缺 vocab_cefr（阶段 1 引入）

**文件**：`backend/src/articles_service.cpp` 第 428-458 行

**根因**：`difficultyReport()` 函数序列化 JSON 时漏掉了 `report.vocab_cefr` 字段。

**修复**：在 `level_counts` 和 `new_words` 之间新增：
```cpp
JsonObject vocab_cefr_map;
for (auto& kv : report.vocab_cefr) vocab_cefr_map[kv.first] = JsonValue::makeString(kv.second);
o["vocab_cefr"] = JsonValue::makeObject(vocab_cefr_map);
```

### Bug-3：历史遗留 — 查重只用 standard_content 导致合并失败（v1.2.0-T004 引入）

**文件**：`backend/include/knowledge_service.h` 两处

**根因**：AI 固化会润色 `standard_content`（如 start → venture / strategic），但 `tryCrossUserCache()` 和 `applySolidify()` 的查重 SQL 只匹配 `standard_content`，导致重复固化无法命中合并条件。

**修复**：两处查重 SQL 都加上 `OR user_input_content` 条件：
```cpp
"(standard_content='" + Db::escape(stdContent) + "' "
 " OR user_input_content='" + Db::escape(userInput) + "') "
 "AND is_solidified=1 AND id<>" + std::to_string(id)
```

**效果**：stage2 从 30/31 失败 1 → **31/31 全过**

### Bug-4：历史遗留 — exercise_types 从未赋值（v1.1.0 引入）

**文件**：`backend/include/question_service.h` generate() 方法

**根因**：`handleExerciseGenerate` 里确实有序列化 `exercise_types`，但底层 `QuestionService::GenerateResult.exerciseTypes` 从未被赋值 — 空数组直接返给前端。

**修复**：generate() 末尾新增提取逻辑：
```cpp
// 从 AI 返回 JSON 里挖 exercises 数组，提取每道题的 type 字段（去重）
// 兜底：如果 AI 没返回 type，按 mode 给默认值
if (r.exerciseTypes.empty()) {
  if (r.mode == "weekly") r.exerciseTypes = {"word_match","word_form_fill","context_blank_fill","cn_to_en_translation","cloze_choice","sentence_imitation"};
  else r.exerciseTypes = {"word_match","word_form_fill","context_blank_fill"};
}
```

**效果**：stage4 从 24/26 失败 2 → **26/26 全过**

### Bug-5：历史遗留 — 旧 articles 表被 DROP+CREATE 丢了 match_threshold（本轮引入）

**根因**：创建 06_articles_cefr.sql 时，旧表有但新表没补 `match_threshold` 字段，导致 stage1_env_db 字段检查失败。

**修复**：`ALTER TABLE articles ADD COLUMN match_threshold INT NULL DEFAULT NULL;` + SQL 脚本同步补上。
