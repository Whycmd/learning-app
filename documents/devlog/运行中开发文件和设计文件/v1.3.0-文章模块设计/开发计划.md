### 架构

```
ai_http.h（工具层：URL/转义/分块/路径拼接）
    ↑ 被包含
ai_provider.h（接口层：IAiProvider + 工厂 + 配置/请求/响应结构）
    ↑ 被包含
ai_client.h（兼容层：AiClient 保留原 postChat 签名，内部路由到 Provider）
    ↑ 被编译
ai_provider.cpp（实现层：OpenAiCompatibleProvider + AgnesProvider）
```

### 关键约定

- **向后兼容**：`AiClient::postChat(messages, wantJson, maxTokens, temperature)` 签名不变，业务 Service 层零改动；
- **默认值兜底**：`config/ai.json` 缺失 `provider_type` 时按 `openai_compatible` 处理；
- **路径拼接**：`base_url` 已含 `/v1` 时通过 `ai_http::apiPath()` 避免出现 `/v1/v1/...`；
- **新增模型步骤**：① `ai_provider.h` 增加枚举值 → ② `ai_provider.cpp` 增加 Provider 子类 → ③ 工厂注册 → ④ `config/ai.json` 设置 `provider_type`；
- **Agnes 现状**：`AgnesProvider` 为预留实现，`postChat` / `ping` 当前委托给 OpenAI 兼容实现，待 Agnes API 规格确定后填充（`TODO` 已标注）。

#### 方案决策记录

| 项 | 选择 | 理由 |
|----|------|------|
| Service 组织方式 | **.h + .cpp 分离** | EFLLex 加载涉及 10,000 词条哈希表构建，放头文件会臃肿；`src/*.cpp` 通配自动包含 |
| 旧 articles 表 | **DROP + CREATE** | 前端从未开放录入，无真实数据；干净彻底 |
| EFLLex 词性过滤 | **仅保留 NN/VB/JJ/RB 前缀** | 学习关注名词/动词/形容词/副词；用前缀匹配覆盖 NNS/NNP/VBD/JJR/RBR 等派生标签 |
| MySQL socket 路径 | **db.json 和 12 个测试文件均改为 `/Users/junwang/.local/run/mysql.sock`** | 对齐 start_mysql.sh 的实际启动路径；沙箱限制 /tmp 路径下写 data 目录 |

#### 关键实现细节

- **路由注册顺序**：`/api/article/my` 必须在 `/api/article/:id` 之前注册，否则 "my" 会被当作 :id 参数捕获
- **CEFR 难度判定**：用户等级推断为 B1（默认）；生词 = cefr > user+1，边缘词 = cefr == user+1
- **文章整体 CEFR**：取各等级词数众数（哪个等级出现次数最多）
- **分句缩写处理**：内置 45+ 常见缩写词表 + 启发式单大写字母检测（如 "I."）
- **文章创建自动处理**：创建 → 自动分句 → 逐词查 EFLLex → 计算难度 → 写入 article_vocabulary → 判定 is_new_word
- **词汇归一化回退**：EFLLex 查不到时先查 130+ 不规则动词表，再尝试 -s/-ed/-ing 后缀剥离

#### T1.3.4 — 后端：推荐文章列表（子功能 M）

GET /api/article/recommend

  返回：文章标题、来源、URL、预览摘要、预估 CEFR 等级
  不调 AI，纯数据返回
```

```
POST /api/article/recommend/fetch
  手动触发一次推荐刷新（拉取最新头条，存入 article_recommend_queue）
```

```
POST /api/article/recommend/:id/save
  用户保存某篇推荐文章
  → 后端抓取文章全文（source_url）
  → 走完整处理流程（分句、CEFR 难度标注、习题生成）
  → 写入 articles 表，标记 import_method='ai_recommended'

### 6.3 具体任务

#### T1.5.1 — 后端：图片导入文章（子功能 K）

```
POST /api/article/import/image
  → 接收图片文件（JPG/PNG）
  → 调 AI 网关 OCR（智谱 GLM-4-Flash 视觉能力）
  → 提取文本存入 article_import_records.extracted_text
  → 返回 job_id

GET /api/article/import/:job_id
  → 查询处理状态（pending/processing/completed/failed）

POST /api/article/import/:job_id/confirm
  → 用户确认 OCR 文本无误
  → 触发完整处理流程（分句、CEFR 难度标注、习题生成）
  → 写入 articles 表，删除 import_record
```

#### T1.5.2 — 后端：AI 生成文章（子功能 L）

```
POST /api/article/generate-by-ai
  body: { topic, cefr_level, type }
  → 调 AI 网关生成符合难度的英文文章
  → prompt 中注入用户正在学习的单词列表（结合生词本）
  → 生成后自动走完整处理流程（分句、难度标注、习题生成）
  → 写入 articles 表，标记 import_method='ai_generated'
```

#### T1.5.3 — 前端：导入弹窗 + 生成表单

**图片导入**：
- 点击「上传文章」按钮 → 弹出文件选择框
- 选择图片后显示预览 + OCR 进度条
- OCR 完成后显示提取文本，用户可编辑修正
- 确认 → 触发完整处理 → 跳转至文章详情页

**AI 生成文章**：
- 点击「AI 生成」按钮 → 弹出表单
- 输入：主题（必填）、CEFR 等级（下拉）、文章类型（下拉）、目标词汇（可选，默认从生词本取）
- 生成后显示进度提示，完成后跳转详情页
