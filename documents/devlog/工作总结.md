## 一、项目概述

一款轻量化英语学习软件，采用「**学习数据全部本地化 + AI 能力在线调用**」的混合架构：

- 知识点、学情、文章等学习数据存储于**本地 MySQL**，不上传云端；
- AI 能力在线调用**智谱 AI BigModel（GLM-4-Flash，完全免费）**，经本地 Node.js 网关转发；
- 围绕遗忘曲线实现：知识点 AI 固化拓展、定时复习推送、AI 出题、自动批改、学情统计与数据维护。

软件版本：**v1.4.0**，包含 C++ 后端、原生前端 9 个页面、14 个测试套件。

## 二、已完成的工作

### 阶段 1：环境部署与数据库

- 在 macOS 本地完成 **MySQL 8.0** 单机部署，仅监听本机 Socket，端口不对外；
- 本地安装 Node.js 运行环境（网关、脚本、Word 生成）；
- 设计并初始化数据库表，统一 InnoDB 引擎、utf8mb4 字符集，不设外键约束，表间关联一致性由代码保证；
- 编写 C++ 编译器与目录结构的环境校验。

### 阶段 2：知识点录入与 AI 固化

- 知识点单条录入、录入自动查重；
- **AI 结构化固化**：返回 JSON，精简写入主表与各子表；
- **整段提示词一次发送**：按六板块完整叙述（核心含义与例句／词根与词源／同源词汇／典故俗语与固定搭配／同义词及辨析／补充相关知识）构造提示，一次请求、一次完整返回，软件不切割提示词、不分段调用再拼接；批量与单条固化均遵循同一结构；
- **批量固化**：一次 AI 调用处理多个知识点（显著减少对接次数与等待时间）；
- 固化内容覆盖：标准词条、难度、音标、英文释义与经典例句、词根词源、同源词汇、固定搭配（含例句）、典故俗语、近义词、反义词、同义词辨析、短语解析、使用频率、语域、文化延伸、同类词语；
- **不适用板块自动省略**：提示词要求 AI 对不适用项留空，代码侧过滤 "no/none/无此内容" 类空话；固化前精确查重命中即直接合并，免 AI 调用；
- 人工兜底：手动修改标准词条、知识点**合并 / 拆分**；
- 知识点 Word 导出（单个 / 多知识点合并一个文档），文档按六板块结构编排。

### 阶段 3：学情算法与选题

- **0–5 级熟练度**体系，满级（L5）后终止复习；
- **双模式遗忘曲线**（公式已在代码中实现）：
  - 按周模式：下次复习 = 当日 + `2 × (1 + 2^熟练度)` 天；
  - 按日模式：下次复习 = 当日 + `0.4 × (1 + 3^熟练度)` 天；
- **待复习候选池**自动筛选（到期且未满级），按熟练度排序；
- 人工选题、选题后熟练度调整、答题记录、学情自动创建；
- 学情统计（总数、熟练度分布、到期数量等）。

### 阶段 4：AI 出题与自动批改

- **6 大固定题型**：词义匹配综合题（含阅读短文）、词性转换填空、语境选词填空、中译英翻译、词汇辨析完形选择、例句仿写；
- 按「会读 / 会写」分层抽题（会读重辨析理解，会写重变形与输出）；
- 习题实时生成、**以 Word 文档输出**，不入库、不固化、不复用；
- 客观题本地代码比对，主观题（翻译 / 仿写）AI 批改；
- 支持单题批改与批量批改，批改结果同步更新学情（答错累计错误次数）。

### 阶段 5：前端页面与联调

- 原生 HTML + CSS + JavaScript 实现，由 C++ 后端直接托管（端口 8088），无需独立前端服务；
- 共 9 个可交互页面，对接真实 API。

### 阶段 6：系统维护

- **数据库备份**：导出全量 `.sql` 文件到 `backups/`；
- 学情重置：单条重置、全量清空；

### 阶段 16：固化链路缺陷修复（v1.4.0-T001，2026-10-25）

用户先反馈「录入知识点，点固化，详情页没有显示」。我没有直接改代码，先用接口和浏览器复现：新建一个正常词条走到详情页，页面正常；再用同名词条触发合并，然后打开旧 id 的详情页——页面完全空白，控制台干净。问题不在后端返回，而在详情页把 URL 里的 id 直接塞进下拉框，选中项落空后 `loadDetail()` 提前返回。修复补了兜底：id 失效时回退显示最新词条并提示"已被合并"，列表为空给引导文案；录入页也把合并目标 ID 显示出来，避免用户把"合并"理解成"丢失"。

第二次反馈更难：「录入 appopriate，固化的却是 venture」。这条真实数据比任何猜测都有用——venture 的音标 `/ˈventʃər/` 正是固化提示词 schema 里的示例值。模型把示例词当成了目标词，而入库代码完全信任 `standard_content`。修法两手：清掉提示词里的示例词，再加一道入库校验。

校验上我走过弯路。第一版按词形容错（编辑距离、前缀），全量回归立刻暴露副作用：benefit→beneficial、测试合成词 t002retryword→retry 都被判成"无关词"，5 个套件失败。于是放宽为包含关系，并补上原计划没有的两件事：错配时带纠正说明重试一次；批量固化数组与词表错位时逐条重试。另外把单条 `max_tokens` 从 2048 提到 4096——多义词 JSON 被截断会表现成 `AI returned no JSON`，极易被误当成网络抖动。

最终 14 套件 437 项通过（另 2 项跳过），实机复核 appropriate 的释义与音标正确。两处决策由用户拍板：测试套件编号顺延为 stage13（stage12 已被点金圣殿占用），版本号保持 v1.4.0 不升 PATCH（T002~T010 尚未完成）。我也如实告知：既有套件执行前会清空 `knowledge_points`，跑全量回归会清掉本机真实词条。

收尾时用户点出了这个隐患，要求一并解决：测试不能碰真实数据。于是把 stage2/3/4/5/6 与 e2e 六个套件统一改为"专用测试用户"模式——套件启动时先按用户名前缀（`t2user_`/`t3user_`/`t4user_`/`t5user_`/`t6user_`/`e2euser_`）清掉自己上次留下的数据，再注册登录一个本套件专属账号，后续所有请求带该账号的 Cookie，SQL 断言按 `user_id` 过滤，清理只走 JOIN `users` 的前缀匹配。跑完全量回归后核对：真实账号与词条零变化，数据库里只剩测试账号。顺带修掉 `learning-center.html` 的 `limit=1000`（后端分页参数是 `size`，写成 `limit` 会静默返回默认条数）。

这一轮还暴露了批量固化的偶发失败：AI 偶尔返回不可解析的 JSON，而批量分支原先没有重试，一次抖动就让整批失败。已补为解析失败重试一次，并在响应里加 `failed_reasons`，失败时能看到具体是哪个词、什么原因，不必再靠日志猜。

### 阶段 17：知识点固化 Markdown 重构（v1.4.0-T010，2026-10-25）

目标是把音标、词根、同源词、典故、短语解析、频率、语域、文化延伸、同类词这九类讲解内容整块交给 AI 以 Markdown 输出，只落一条 `kp_extras(extra_type='markdown_content')`；definitions/collocations/synonyms/antonyms 仍写结构化子表，旧数据继续按原 `<br>` 渲染。

编码前的计划核对发现三处过期引用：`frontend/static/kp-detail.js` 已不存在（详情逻辑内联在 `kp-detail.html`）；测试入口是 `node tests/run_all.js`；`kp_extras.content` 实为 TEXT 而非 MEDIUMTEXT。按真实代码修正计划后开工，未改表结构。

实现中遇到两个实际问题：GLM 会把 Markdown 的真实换行写进 JSON 字符串，导致 JSON 非法，于是把 `markdown_content` 定义为“字符串数组、每元素一行”，入库前拼接，并加控制字符修复兜底；精讲内容使单条固化变慢，批量串行易超时，于是把篇幅约束为 250 汉字、最多两个二级标题（T014 已调整为 2–6 个有价值维度），并收紧结构化字段和 token 预算。前端没有引入 CDN，而是把 marked v12.0.2 下载到 `frontend/static/marked.min.js`，配合 `md-render.js` 做标签/属性白名单消毒；marked 不可用时降级为换行渲染。

回归：stage2 扩到 34 项，按 T001 基线 437 推算全量为 440 通过 / 2 跳过 / 0 失败；浏览器实机确认新词标题、粗体、列表、引用正常，旧词条不受影响。

### 阶段 18：异步批量固化与渐进展示（v1.4.0-T012，2026-10-25）

批量词数一多就慢且容易整批失败。定位后确认根因不是“调用次数多”，而是单次响应被 `maxTokens` 截断：`1024 * min(N,4)` 封顶 4096，新 Markdown 每词约 450–600 token，7 词以上必被截断，随后两次重试仍失败，整体耗时 2–3 分钟且无结果。

对比分片并发、纯并发单条、异步任务三种方案后，用户选定“异步任务 + 分片并发”，要求生成中也能看到已完成词条，并保留任务历史与断点续跑以应对断网。实现为：`POST /api/kp/solidify/async` 立即建任务并返回；后台每片 ≤4 词、默认 2 路并发；每个词固化成功即独立事务提交，任务明细状态同步更新，前端 1.5s 轮询并把新完成词条直接显示为可点链接；任务与明细落 `solidify_jobs` / `solidify_job_items` 两表，服务重启把遗留 `running` 置为 `interrupted`，用户点“继续”只重跑失败/未完成项；并发数放入 `config/ai.json` 的 `max_concurrency`（1–16，异常回落 2），换模型时无需改代码。

过程中还修掉一个真实缺陷：批量词表拼接原代码第二个词起发送的是字面量 ` << kp <<`，不是真实单词；这很可能也是单词本批量导入只有核心内容的原因之一。

回归：stage2 扩到 50 项（异步提交、渐进可见、历史、复用、断点续跑），全量 14 套件 **456 通过 / 2 跳过 / 0 失败**。并发配置以 2→3→2 重启验证日志生效。尚未自动化覆盖并已记入开发说明的项：真实断网、运行中重启、单片异常隔离、双用户异步并发、异常配置值。浏览器 UI 因登录凭据限制未做自动化，待人工验收。

### 阶段 19：Word 导出 Markdown 精讲（v1.4.0-T013，2026-10-28）

目标：让单词详情页已有的 Markdown 精讲在 Word 中正常呈现，同时不破坏旧格式词条。

对比方案后选定 `markdown-docx` + 适配层：`scripts/md_to_docx.js` 负责标题去重、`<script>/<style>` 清理、`\(...\)`/`\[...\]` 归一化，以及 KaTeX→OMML；`gen_word_kp.js` 保留页脚、分页、单词标题，有 `markdown_content` 走新渲染，否则走原 `appendLegacyBody`。关键坑：标题段落引用了 `MdHeading2` 等样式，必须把转换器的 `paragraphStyles/characterStyles/numbering` 注入 `Document`，否则标题退化；`docx` 必须与 `markdown-docx` 依赖统一为 9.14.0，否则内容丢失。`docx` 8.5.0→9.14.0，新增 `markdown-docx` 1.7.1。

验证：stage2 增加 Word XML 断言（公式 `<m:oMath>`≥3、粗体、列表编号、无 `**`/`##`/`\frac`/`<script`、H1 去重、新旧格式与批量并存），65 项通过；合成样本人工可查 `word_tmp/t013_markdown_formula_sample.docx`。

### 阶段 20：精讲提示词与生成性能调优（v1.4.0-T014，2026-10-28）

针对“部分单词精讲只有核心含义与例句一项”，先用数据库与 `ai_tasks` 原始返回定位：不是前端截断，而是提示词自相矛盾（“最多 2 个二级标题”与十余维度清单、单节 JSON 示例、备注“无关维度省略”），模型随机只写一节。随后按用户要求连续调整：

- 增加 `venture` Markdown 示例，按“音标/频率→核心释义→词根→同源词→搭配→同义辨析→补充”示范；
- 禁止“无固定搭配 / 暂无 / 不适用”等占位，无内容整节删除；
- 按学习者水平调整难度与英文占比，高中/高考英文≥50%，多给英文例句；
- 不求齐全，2–6 个有价值维度，逻辑清晰、语言生动；
- 压缩提示词至约 5.9KB，并调整性能参数：每片 3 词、默认 3 路并发、`request_timeout_sec`=180；
- 相应放宽测试等待：stage11 考后固化 30s→130s，stage2 异步轮询 160s→300s。

实测：单条约 18–38s，3 词批量约 28s（压缩前 4 词 118.6s）；全量回归 **14 套件 471 通过 / 2 跳过 / 0 失败**。已知局限：英文占比、每节例句数仍由模型自行把握，未做后端强制校验；旧词条不会自动重写。

## 附录：开发经验索引（详见 `documents/开发经验总结.md`）

| 编号 | 类别 | 核心经验 |
|------|------|---------|
| ENV-01 | 环境部署 | MySQL 仅本地 socket 连接，TCP 默认不通；连接配置用 socket 字段 |
| ENV-02 | 环境部署 | 密码存本地文件，config 用 password_file 引用，读取后 trim |
| ENV-03 | 环境部署 | LocalAI 离线推理兼容性差，改为在线免费大模型（智谱 GLM-4-Flash） |
| BLD-01 | 编译构建 | MySQL 头文件/库找不到；安装 mysql-client 并配置 CMake find_package |
| HTTP-01 | HTTP 接口 | 路由注册顺序重要：长路径在前，短路径（如 /api/article/my 在 /api/article/:id 前） |
| HTTP-02 | HTTP 接口 | JSON 请求解析需容错：body 为空、content-type 缺失、非 JSON 格式 |
| HTTP-03 | HTTP 接口 | 静态文件 MIME 需显式注册（woff2、docx 等） |
| HTTP-04 | HTTP 接口 | 中文路径/文件名需 URL decode，否则找不到文件 |
| CRS-01 | 并发崩溃 | libmysqlclient 非线程安全，共享 MYSQL* 会导致堆损坏崩溃；修复：互斥锁 + mysql_thread_init() + 禁用 SSL |
| CPP-01 | C++ 后端 | 字符串拼接用 std::string，避免 C 风格 strcpy/strcat |
| CPP-02 | C++ 后端 | HTTP 请求行解析需处理 \r\n，不能只 split 空格 |
| CPP-03 | C++ 后端 | 文件读写前判断是否存在，避免崩溃 |
| CPP-04 | C++ 后端 | 多线程环境下智能指针需共享，不能用 unique_ptr 跨线程传递 |
| AI-01 | AI 与后端 | AI 返回字段可能是字符串或数组，需容错（flexStr 工具函数） |
| AI-02 | AI 与后端 | 不适用项 AI 会返回 "There are no..." 类文字，需提示词强化省略 + 代码侧空话过滤 |
| AI-03 | AI 与后端 | AI 超时处理：130s 放宽超时，失败标记"待固化" |
| AI-04 | AI 与后端 | AI 返回 JSON 解析失败时整卷拒绝，不落库 |
| AI-05 | AI 与后端 | 掌握程度（master_require）以代码规则为准：difficulty ≥ 5 → 会读，否则 → 会写 |
| TOOL-01 | 工具流程 | run_in_background 包装器会连带杀进程，改用 nohup ... & disown 常驻服务 |
| TOOL-02 | 工具流程 | SQLite 不适用本项目，全程 MySQL；不要引入 SQLite 作为备选 |
| TOOL-03 | 工具流程 | AI 网关本地转发 HTTPS，不向云端暴露本地数据 |
| TOOL-04 | 工具流程 | 定时清理脚本用 cron 或 Node.js 定时器，避免临时文件堆积 |
| TTS-01 | 前端 TTS | 浏览器 Web Speech API 无需额外服务，原生可用 |
