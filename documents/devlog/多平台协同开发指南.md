# 多平台协同开发指南

> 版本：draft-v0.1 | 创建：2026-10-04
> 目标：让持有 macOS 和 Windows 的开发者在同一代码库上并行开发，互不干扰。
> 核心思路：**代码平台无关，脚本按平台分流，构建系统统一。**

---

## 一、当前阻塞点（需要解决的问题）

| 问题 | 现状 | 影响 |
|------|------|------|
| 编译工具链不同 | `build_backend.sh` 硬编码 `clang++` | Windows 无法编译 |
| 启动脚本仅 bash | 全部 `.sh` / `.command` | Windows 无法直接运行 |
| 路径硬编码 | `main.cpp` 内写死 `/Users/junwang/...` | 换人换机即失效 |
| 无构建抽象层 | 没有 CMake / Makefile 通用配置 | 每个平台需手动维护编译命令 |
| Git 行尾符 | macOS 用 LF，Windows 用 CRLF | 冲突时 diff 混乱 |

---

## 二、解决方案总览

```
macOS 开发者 ─┐
              ├─→ 同一代码库（Git）─→ 各自平台跑各自脚本
Windows 开发者 ┘
                ↑
    统一构建：CMake（一份配置，两平台自动适配）
    统一配置：config/*.json（机器无关的相对路径）
    统一测试：前端 Node.js 测试套件（两平台一致）
```

---

## 三、具体操作步骤

### 步骤 1：引入 CMake 构建系统（核心）

创建一个 `backend/CMakeLists.txt`，内容覆盖以下要点：

- 检测编译器：MSVC（Windows）或 clang/g++（macOS/Linux）
- 找 MySQL 头文件和库文件（两平台路径不同，CMake 自动处理）
- 条件编译宏：`_WIN32` 分支处理 socket/mkdir/随机数/crypto 差异
- 输出：`eng_app_server`（macOS）或 `eng_app_server.exe`（Windows）

**交付物**：`backend/CMakeLists.txt`

---

### 步骤 2：启动脚本按平台分流

在 `scripts/` 下新增：

```
scripts/
├── start_all.sh          ← macOS/Linux 保留（不变）
├── start_all.bat         ← Windows 新增
├── start_all.ps1         ← Windows PowerShell（可选，推荐）
├── stop_all.sh           ← macOS/Linux 保留（不变）
├── stop_all.bat          ← Windows 新增
└── detect_os.sh          ← 通用工具，返回 "macos" 或 "windows"
```

**`start_all.bat` 核心逻辑**：
1. 读取 `config/app.json` 获取项目根目录
2. 启动 MySQL（调用 `mysqld.exe`，路径从 `config/db.json` 读）
3. 启动 AI 网关（`node scripts/local_ai_server.js`）
4. 启动后端（`.\backend\build\eng_app_server.exe`）

**交付物**：2 个新 `.bat` + 1 个 `.ps1`，原有 `.sh` 不动

---

### 步骤 3：路径配置化（让所有人不用改代码）

将硬编码路径全部从代码中抽到 `config/app.json`：

```json
{
  "backend_port": 8088,
  "version": "v1.4.0",
  "project_root": "./",
  "frontend_static_dir": "frontend/static",
  "frontend_pages_dir": "frontend/pages",
  "word_tmp_dir": "word_tmp",
  "log_dir": "logs",
  "mysql_data_dir": "data/mysql",
  "backup_dir": "backups"
}
```

- `main.cpp` 启动时读取此 JSON，所有路径从变量获取，不再硬编码
- Windows 用户可在 `config/app.json` 自行修改 `word_tmp_dir` 等路径

**交付物**：`config/app.json` 字段扩充 + `main.cpp` 路径读取逻辑

---

### 步骤 4：Git 行尾符统一

在项目根目录创建 `.gitattributes`：

```
# 文本文件统一 LF，不随平台变化
* text=auto eol=lf
*.js eol=lf
*.html eol=lf
*.css eol=lf
*.json eol=lf
*.md eol=lf
*.sql eol=lf
*.cpp eol=lf
*.h eol=lf
*.sh eol=lf
*.bat eol=crlf
*.ps1 eol=crlf
```

并在仓库根目录的 `.git/config` 中设置：

```ini
[core]
    autocrlf = input   # Windows checkout 时转 LF，commit 时保持 LF
```

**交付物**：`.gitattributes` 文件

---

### 步骤 5：统一开发环境要求文档

在 `README.md` 或新增 `DEVELOPERS.md` 中说明：

| 环境 | 必装软件 | 版本要求 |
|------|---------|---------|
| macOS | Xcode Command Line Tools、Homebrew、Node.js | clang、brew、node ≥18 |
| Windows | Visual Studio Build Tools（含 MSVC）、Git for Windows、Node.js | cl.exe、git、node ≥18 |
| 共用 | MySQL 8.0（本地） | Connector/C for Windows / macOS |

**交付物**：`DEVELOPERS.md` 文件

---

### 步骤 6：测试套件跨平台验证

现有测试均用 Node.js 编写（`frontend/tests/run_all.js`），**天然跨平台**。

需要额外做：
- 在 Windows 上运行一次全量测试，记录任何失败项
- 检查是否有测试依赖 macOS 路径（如 `~/...`）
- 如有，改为从环境变量或相对路径读取

**交付物**：测试通过报告（两平台各一份）

## 四、日常工作流（两人如何协作）

```
macOS 开发者                     Windows 开发者
      │                                │
  git pull                        git pull
      │                                │
  修改 macOS 专用脚本              修改 Windows 专用脚本
  （只动 .sh）                      （只动 .bat/.ps1）
      │                                │
  git commit                       git commit
      │                                │
  git push ←─────────────────────→ git push
      │                                │
  CI（GitHub Actions）             CI（GitHub Actions）
  自动在 macOS runner 上跑测试       自动在 windows-latest runner 上跑测试
      │                                │
  合并前确认两平台测试均通过          合并前确认两平台测试均通过
```

---

## 五、关键原则

| 原则 | 说明 |
|------|------|
| 代码平台无关 | 所有 `.cpp`/`.h`/`.js`/`.html`/`.css` 两平台完全相同，不改 |
| 脚本按平台分 | `.sh` 只给 macOS，`.bat`/`.ps1` 只给 Windows |
| 配置可覆盖 | 路径、端口等机器相关值放 `config/*.json`，每人自行修改 |
| 构建统一入口 | 用 CMake 代替手写编译命令，两平台同一套配置 |
| 测试驱动 | 任何改动必须让现有测试 + 对应平台新增测试均通过才能提交 |

## 六、时间估算（参考）

| 任务 | 工作量 |
|------|--------|
| 新增 CMakeLists.txt | 1 天 |
| 新增 Windows 脚本（.bat/.ps1） | 0.5 天 |
| 路径配置化（app.json + main.cpp） | 0.5 天 |
| 添加 .gitattributes | 0.25 天 |
| 编写 DEVELOPERS.md | 0.25 天 |
| Windows 上跑全量测试并修复 | 视失败情况，预计 0.5~2 天 |
| **合计** | **约 3~4 人天** |
