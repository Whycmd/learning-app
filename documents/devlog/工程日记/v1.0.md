# v1.0：地基

> 时间：2026-09（首版，记录日期 09-25）
> 版本：v1.0
> 状态：已完成

第一版没有设计。几页白底，录词、固化、出题、批改，跑通就算数。

## 一、六段

先立环境。MySQL 装本机，只听 socket；Node 管脚本和 Word；C++17 后端一个入口。建表统一 InnoDB、utf8mb4，不设外键。这是有意为之：单机场景，外键的约束成本高于收益，表间一致性交给代码。

再做闭环。录入、查重、AI 固化、批量固化、人工合并拆分、Word 导出，一样不能少。学情分 0 到 5 级，满级停复习；遗忘曲线备两套，按周 `2×(1+2^熟练度)` 天，按日 `0.4×(1+3^熟练度)` 天。待复习池、人工选题、答题记录、学情统计，串成一条线。

录入不摆架子。逐条敲，或整段粘贴，AI 负责拆成词条。查重过两道：词形相同就合并，音标不同再另立。合并之前给人看一眼，不偷偷吞词条。

学情统计给三张脸：遗忘分布、ROC、薄弱点。候选池分全部、近期、薄弱三档，人自己挑。机器排的序，只是建议。

出题六型，按“会读”“会写”分层。题目实时生成，进 Word，不入库、不固化、不复用。客观题本地比对，主观题交 AI 批改，结果回写学情。

前端是原生 HTML、CSS、JS，由后端直接托管，没有第二个服务。备份、学情重置、临时 Word 清理，一并塞进维护功能。

## 二、AI 换三回

第一套是本地 LocalAI 加 Mock 规则引擎，离线，零 Token。后来按需求改为在线调用。先试通义千问，最后定智谱 GLM-4-Flash，经本地 Node 网关转发。网关做 HTTP 到 HTTPS 的转接，再把 Key 注入请求头。

理由三条：免费、稳定、数据不出本机。学习数据留在自己库里，只有提问出门。这条底线，后来一直没破。

AI 爱写空话。“无此内容”“暂无”这类句子，代码侧一律过滤，不落库。

## 三、一条规矩

六块知识，一次发，一次收。软件不切提示词，也不把分段回答拼起来。模型的输出是一整块，读起来才连贯。这条规矩，后来几版都守着。

维护也不是边角料：备份、学情重置、临时 Word 清理，都要能一键做完。数据是本地唯一的一份，丢了没处找。

## 结果

收尾时一百九十六项测试。接口按模块收口，表结构一次立稳。后面几版加人、加文章、加奖励，都没有推翻这张底图。
