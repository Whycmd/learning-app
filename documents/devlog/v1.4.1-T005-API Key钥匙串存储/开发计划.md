## 三、设计

### 3.1 密钥文件

| 项 | 取值 |
|---|---|
| 默认路径 | `~/.config/eng-app/ai.key`（XDG 用户配置目录，仓库外） |
| 路径覆盖 | 环境变量 `ENG_AI_KEY_FILE`（测试与特殊部署使用） |
| 文件权限 | `0600`；若组/其他用户可读（`mode & 0o077` 非 0），视为无效并回退下一来源 |
| 内容 | 单行 Key，忽略首尾空白与末尾换行；必须为可打印 ASCII（复用现有 `isPlaceholderKey` 规则） |
| 写入方式 | `umask 077` + 临时文件 + `rename` 原子替换，避免半写与权限泄漏 |

### 3.2 读取优先级

| 顺序 | 来源 | 条件 |
|---|---|---|
| 1 | 密钥文件 | 文件存在、权限合规、内容为合法 ASCII |
| 2 | 环境变量 | `ZHIPU_API_KEY` 非空且合法 |
| 3 | `config/ai.json` | `api_key` 非空且合法 |
| — | 均无 | 网关 `/readyz` 返回 `no-api-key`，业务提示 Key 未配置，不崩溃 |

- 读取在每次 `loadConfig()` 时进行：文件读取成本低，无需缓存，换 Key 后重启网关即可生效；
- 非 Linux/macOS、文件不可读、权限不合规时静默回退；
- 日志只输出 `api_key=configured/MISSING (source=file|env|config|none)`，不回显值。

### 3.3 迁移与日常维护

新增 `scripts/ai_key_store.sh`：

| 子命令 | 行为 |
|---|---|
| `migrate` | 从 `config/ai.json` 读出现有 Key → 写入密钥文件（0600）→ 把配置字段置空；输出长度，不输出内容 |
| `set` | 从标准输入读取 Key，写入/覆盖密钥文件 |
| `check` | 检查路径、存在性、权限、ASCII、长度，只打印状态 |
| `delete` | 删除密钥文件 |

- Key 只经 stdin 传入，不进入 `argv`；
- 不修改配置中的其他字段；
- Windows/Docker 内无用户配置目录时，提示改用 `ZHIPU_API_KEY`。

### 3.4 人工修改渠道

- 更换 Key：`bash scripts/ai_key_store.sh set`；
- 更换路径：`ENG_AI_KEY_FILE`；
- Docker：`.env` 的 `ZHIPU_API_KEY`；
- 临时兜底：`config/ai.json` 的 `api_key`（不推荐长期使用）。

## 七、风险与应对

| 风险 | 应对 |
|---|---|
| 密钥文件被同机其他用户读取 | 强制 0600；权限不合规拒绝读取并告警；默认放仓库外 |
| 密钥文件被误提交 | 默认路径在 `~/.config`；文档提示自定义路径勿放仓库；必要时在 `.gitignore` 加 `*.key` |
| 迁移脚本把 Key 放进 argv | `set`/`migrate` 只经 stdin 与 shell 变量写入，Key 不进参数 |
| 磁盘未加密 | 本任务只做权限隔离；整盘加密属于系统层，文档注明 |
| 换 Key 不生效 | 每次请求读取文件，重启网关即可；`check` 可即时校验 |
| Docker 无用户配置目录 | 自动回退 `ZHIPU_API_KEY`，文档明确容器内用环境变量 |
| 测试污染真实 Key | 测试用 `ENG_AI_KEY_FILE` 指向临时目录，`finally` 删除 |
| 配置兜底长期保留明文 | 验收项强制迁移后置空；文档标注不推荐 |

## 八、回滚方式

1. 代码回滚：`git checkout -- scripts/local_ai_server.js dev config/ai.example.json tests/`，删除 `scripts/ai_key_store.sh`、`tests/stage18_ai_keyfile.test.js`；
2. Key 回滚：把 `~/.config/eng-app/ai.key` 内容手工填回 `config/ai.json` 的 `api_key`；
3. 文件清理：`bash scripts/ai_key_store.sh delete`；
4. 环境回滚：不设置 `ENG_AI_KEY_FILE` 即使用默认路径；Docker 侧无需改动；
5. 运行回滚：重启网关与后端即恢复原读取逻辑。
