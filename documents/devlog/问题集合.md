
## 五、存在的不足（如实记录）

### 1. 文章阅读模块阶段 2 尚未启动
**阶段 1 已完成（v1.3.0-T000，2026-09-28）**：EFLLex 预置 13,546 词条、文章 CRUD 7 接口、规则分句（45+ 缩写词）+ CEFR 难度分析；修复 splitTab off-by-one / 查重 OR 条件 / exercise_types 空返回 / match_threshold 字段丢失 4 个 bug。全量回归 12 套件**全部通过**。
**遗留**：阶段 2 核心阅读功能待启动（分句展示 + 点词查义 + 生词高亮 + TTS 朗读 + 中英对照），阶段 3 背景知识解析 + 推荐文章。交接文档见 `documents/v1.3.0-T000-文章模块/阶段1-交接文档.md`。

### 2. 强依赖在线 AI 的网络稳定性
固化、出题、批改均需联网。AI 调用耗时偶发较长（实测单次固化可接近 2 分钟），涉及 AI 的接口/测试超时已放宽至 130s；目前无离线降级能力（旧 Mock 引擎已移除），网络抖动 / 限流 / Key 失效会直接造成对应功能不可用。

### 3. 测试隔离性不足
各测试套件共用同一个数据库，依赖套件开头的 `DELETE` 语句清理；缺乏独立 schema 或事务级隔离，连续运行时可能受前序数据残留或 AI 瞬时超时影响，存在偶发不稳定。

### 4. 手写 HTTP 服务器仍较简陋
并发崩溃问题已通过线程安全修复（互斥锁 + `mysql_thread_init`，见阶段 8），但根本架构未变：每个请求新建线程（无线程池）、无连接复用（keep-alive）、不支持 HTTPS、请求解析的边界情况和错误处理有限。

### 5. 无外键，存在孤儿数据风险
表间不设外键，关联一致性完全依赖代码；若绕过 Service 直接删改数据，可能产生孤儿子表记录。

### 6. 前端工程化与适配较弱
无构建工具与组件化，原生 JS 存在重复代码；响应式适配较基础，移动端体验未专门打磨。

### 7. 密钥与日志安全
API Key 以明文存于 `config/ai.json`（仅本地读取，但未加密）；日志较简陋，无日志轮转，长期运行文件会持续增长。

### 8. 无团队合作与权限管理
当前系统为单用户/多用户模型，无团队概念、无角色分级（教师/学生）、无共享资源机制，无法满足教学场景下的协作需求。

### 9. 仅支持 macOS，未适配 Windows
当前后端为 macOS/Unix 专属编译产物，使用 CommonCrypto、/dev/urandom、unix socket 等 macOS 专属 API，Windows 平台需独立适配 CMakeLists、头文件引用与路径分隔符。此外 `main.cpp` 中存在约 17 处硬编码绝对路径（如 `/Users/junwang/.local/...`），是 Windows 适配的核心障碍。

### 10. 架构瓶颈：无连接池、无中间件链、无 WebSocket
- DB 层：`Db` 类持有单个 `MYSQL*`，无连接池，多客户端并发时成为瓶颈；
- HTTP 层：Crow 源码内嵌于 `http_server.h`，仅支持基础 GET/POST/PUT/DELETE 路由，无中间件链，无 WebSocket 支持，实时协作功能（教师推送通知、多人共编文章）无法实现；
- 数据隔离：所有业务查询均靠 `AND user_id=?` 拼接，无表级权限概念，加团队功能需大改 Service 层每一处 SQL。

### 11. 安全漏洞：密码弱加密 + SQL 拼接风险
- 密码存储使用 `CommonCrypto SHA-256` 单次哈希（无迭代），无盐值长度限制，应升级为 bcrypt 或 argon2id；
- 部分 SQL 查询使用 `Db::escape()` 手动拼接，存在遗漏风险，非全部预编译，有注入隐患。

### 12. AI 网关单 Key 无配额管控
`local_ai_server.js` 全局共享一把 API Key，无租户隔离，多用户共用无配额限制，成本不可控。

### 13. 无新用户引导（新手体验差）
代码中无任何 tutorial / onboarding / tooltip 逻辑。新用户进入页面后面对仪表盘、知识点录入、播放复习、点金圣殿等多个模块，无法快速理解各功能用途与操作路径，缺乏引导层。

### 14. 知识点录入与固化为两步操作，UX 不友好
当前流程：新建知识点 → 手动点击"固化"按钮 → AI 处理后入库，两步操作。现代单词 App（如墨墨、Anki）均为"输入即自动扩充"的单步体验。此外固化流程历史 bug 较多（AI 润色导致查重 miss、exercise_types 未赋值等，均已修复，但 UX 设计本身仍偏重）。

### 15. 单词本导出 Word 无预览
导出 Word 时直接触发下载，无预览环节。用户无法在导出前确认格式是否符合预期，需要重新导出的概率较高。

### 16. 课规功能文案对用户不友好
首页"本周课规"区域文案为"圣殿为你订下每周课规，钟响达成，即落印为证"，文学化表达对 unfamiliar 用户理解门槛高；"课规"名称本身也无直观含义（实际是"本周学习量目标"）。

### 17. 备份依赖手动操作，无自动备份
系统仅提供手动备份接口 `POST /api/maint/backup`，无定时自动备份机制。用户需主动执行备份，存在数据丢失风险。

### 18. 无听力和口语模块
系统目前仅覆盖读、写、记三个维度，缺失听力输入训练与口语输出练习，不完整覆盖语言学习四要素。

### 19. 无智能体学习规划与督促功能
系统无学习路径规划、无目标设定引导、无进度督促提醒，纯靠用户自主驱动。

## 六、修正方案（与不足一一对应，可落地）

### 针对 1：补全文章模块（优先级：高）
1. 实现文章阅读阶段 2 核心功能：分句展示、点词查义、生词高亮、TTS 朗读、中英对照；
2. 复用知识点固化框架，实现 **AI 文章结构化固化**（分段、重难点词标注、难度评估）；
3. 实现**自适应匹配**：依据用户平均熟练度与文章 `match_threshold` 推送难度合适的文章。

### 针对 2：AI 稳定性与降级（优先级：高）
1. 完善**指数退避重试**与更友好的超时 / 限流提示；
2. 对固化类请求做**本地结果缓存**，失败时保留"待固化"状态并支持一键重试；
3. 可选保留一个**极简规则兜底引擎**，断网时客观题与基础流程仍可用；
4. 在前端明确提示"该操作需联网"。

### 针对 3：测试隔离（优先级：中）
1. 每个套件使用独立测试库或在事务中执行并回滚；
2. 对 AI 层引入可切换的 Mock，使不依赖真实网络的用例可离线稳定运行；
3. 为偶发超时的用例增加有限重试与明确标注。

### 针对 4：HTTP 服务健壮性（优先级：中）
1. 引入**线程池**替代"一请求一线程"，支持连接复用与 keep-alive 回收；
2. 加固请求解析（超长请求、畸形头部、body 边界）；
3. 如需对外访问，再引入 HTTPS（本地使用可维持 HTTP）。

### 针对 5：数据完整性（优先级：中）
1. 所有删除操作收敛到 Service 层并做子表级联清理；
2. 增加一个**一致性校验脚本**（定时或手动），扫描并报告孤儿记录。

### 针对 6：前端工程化（优先级：低）
1. 视规模引入轻量构建（Vite）或轻框架（Vue），抽取公共导航 / 卡片 / 列表组件；
2. 完善移动端响应式布局与触控交互。

### 针对 7：密钥与日志（优先级：低）
1. API Key 改为存入**macOS 钥匙串（Keychain）**，程序运行时读取，配置文件不再明文保存；
2. 增加日志分级与按大小 / 日期轮转。

### 针对 8：团队合作版（优先级：中，已规划）
详见 `documents/合作版开发工作计划.md`（draft-v0.1，11 模块 56 项工作），核心包括：
- 新增 `teams` / `team_members` 表，users 加 role 字段；
- 三层角色（Super Admin / Teacher / Student）；
- 共享知识点池、共享单词本、文章分配；
- 团队看板（学习排行、达成进度、词币发放统计）。

### 针对 9：Windows 适配（优先级：中，已规划）
详见 `documents/Windows适配流程.md`（draft-v0.1），核心包括：
- CMakeLists.txt 跨平台构建配置；
- CommonCrypto → OpenSSL / Crypto++ 替换；
- unix socket → TCP 连接；
- PowerShell / .bat 启动脚本；
- Git LF 行尾符统一；
- 预编译 exe + setup_db 脚本实现零配置使用。

### 针对 10：架构瓶颈改造（优先级：高，已规划）
详见 `documents/团队版改造分析.md`（draft-v0.1），核心改造项：
- **DB 连接池**：将 `Db` 类改为持有连接池（如 mysqlxx PooledConnection），替代单 `MYSQL*`；
- **WebSocket 支持**：短期通过 Nginx 反向代理 + 独立子服务实现通知推送；远期换框架；
- **表级权限**：新增 `team_id` 字段到业务表，所有查询加 `AND team_id=?` 双重过滤；
- **MVP 路线**：不做语言切换，先做数据库加 team 字段 + 路由 `/api/team/*`（约 15 人天可上线基础团队功能）。

### 针对 11：安全加固（优先级：高）
1. 密码算法迁移至 **bcrypt** 或 **argon2id**（需设计迁移策略：双写过渡期）；
2. 全面梳理 SQL 拼接点，改用预编译语句（`mysql_stmt_prepare`）或 ORM；
3. 增加 CORS 白名单与前端 XSS 统一转义覆盖。

### 针对 12：AI 网关多 Key（优先级：中）
1. `config/ai.json` 改为按租户/团队分配 Key 的数组结构；
2. 增加每月调用配额限制，超限返回明确错误码；
3. 可选：增加备用模型 fallback（glm-4-flash → glm-4-flashx）。

### 针对 13：新手引导（优先级：中）
1. 在首页仪表盘首屏增加**步骤式浮层引导**（首次登录展示，可关闭）；
2. 各功能模块入口增加 `title` 或 `data-tooltip` 简短说明；
3. 在知识点录入页和每日复习页增加"操作提示"小字说明。

### 针对 14：固化 UX 优化（优先级：低，需评估）
1. 可考虑在录入表单增加"录入并立即固化"单按钮，一步完成；
2. 保留现有两步流程作为"先录入、后选择固化"的备选路径；
3. **不建议删除固化功能**：固化是 AI 结构化拓展的核心环节，删掉后将失去六板块完整知识扩充能力，改为一键存储等同于存单词列表，价值大幅下降。

### 针对 15：Word 导出预览（优先级：低）
1. 导出前先调 `GET /api/kp/:id/export-word` 获取 Blob，用 `<iframe>` 或 PDF 预览组件展示，用户确认后再触发下载；
2. 或简化：导出时打开新标签页预览 docx（浏览器内置预览有限，主要靠下载）。

### 针对 16：课规文案优化（优先级：高，改动小）
1. 将"课规"改为"本周目标"或"学习任务"；
2. 首页文案改为："你为本周定了「复习 N 条」的目标，达成可得 X 金桂"；
3. 在课规设置弹窗增加简要说明文字。

### 针对 17：自动备份（优先级：中）
1. 后端增加定时任务：每次启动时自动备份，或每小时增量备份至 `backups/`；
2. 在维护页面增加"上次自动备份时间"显示。

### 针对 18：听力和口语模块（优先级：低，远期）
1. 听力：可利用现有 TTS 模块 + 音频录制，实现"听音选词"题型；
2. 口语：接入语音识别 API（如讯飞或 Whisper），实现跟读打分；
3. 需额外后端服务或第三方 API 集成，工作量较大。

### 针对 19：智能体学习规划（优先级：低，远期）
1. 可基于现有学情数据（熟练度分布、遗忘曲线）推荐学习路径；
2. 通过每日小测结果自动调整后续推送难度；
3. 可作为 v1.5.0 远期规划，暂不纳入短期迭代。
