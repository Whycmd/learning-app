## 三、设计

### 3.1 测试库隔离（选择「独立库 + 独立后端」而非事务回滚）

原因：现有测试通过 HTTP 访问后端，后端使用独立 MySQL 连接，事务回滚无法覆盖跨连接写入；独立库最稳。

1. `run_all.js` 读取 `TEST_DB_NAME`（默认 `eng_app_test`）：
   - `DROP DATABASE IF EXISTS` → `CREATE DATABASE ... utf8mb4`；
   - 按文件名顺序执行 `scripts/sql/01~09` 建全量表（含 05 的 `DELIMITER` 存储过程）；
   - 每轮重建，保证两次运行起点完全一致。
2. 用 `TEST_API_PORT`（默认 `18088`）启动**独立后端实例**：
   - 环境变量：`ENG_DB_NAME=eng_app_test`、`ENG_AI_MOCK_MODE=success`、`ENG_WORD_TMP`、`ENG_BACKUP_DIR` 指向测试临时目录；
   - `--root` 仍为项目根（前端静态文件正常托管）；
   - 启动前探测端口占用，占用则明确报错，不抢占 8088。
3. 所有测试子进程继承上述环境变量，经 `_env.js` 统一读取。
4. 跑完后停止后端；默认删除测试库（`KEEP_TEST_DB=1` 可保留排查）；清理测试临时目录。

**开发库零污染**：
- 测试连接串全部指向 `eng_app_test`；
- Word/备份产物指向 `tests/.artifacts/`（运行后可清理），不写 `word_tmp/`、`backups/`；
- `run_all.js` 在开始/结束各做一次开发库**逐表行数快照**并对比，不一致则判定失败并打印差异表。

### 3.2 后端启动期环境变量覆盖（仅测试用，默认值不变）

| 环境变量 | 作用 | 生产默认 |
|---|---|---|
| `ENG_DB_NAME` | 覆盖 `config/db.json` 的 database | 不设置，仍用配置值 |
| `ENG_AI_MOCK_MODE` | 覆盖 `ai.json` 的 `mock_mode` | `off` |
| `ENG_WORD_TMP` | 覆盖 Word 临时目录 | `root/word_tmp` |
| `ENG_BACKUP_DIR` | 覆盖备份目录 | `root/backups` |
| `ENG_AI_RETRY_TIMES` / `ENG_AI_RETRY_INTERVAL` | 缩短 Mock 失败重试等待（仅测试） | 用 `ai.json` 值 |

实现位置仅在 `main.cpp` 加载配置后；不改路由、不改中间件、不改 Service。

### 3.3 AI Mock 设计

`MockAiProvider` 在 `AiClient::setConfig` 时按 `mock_mode` 创建，`postChat` 不发网络请求，直接返回 `AiResponse{ok, status, extractedJson}`。

| 场景识别 | 依据 | 成功 fixture |
|---|---|---|
| 知识点固化（单条/批量） | system 提示词含 `English learning assistant` + user 含 `目标词`/`词表` | 对象/数组：`standard_content`、`difficulty=3`、`definitions[]`、`collocations[]`、`synonyms[]`、`antonyms[]`、`markdown_content[]` |
| 复习出题 | `exercise generator` | `{exercises:[6 种固定题型], quick_memo:{items:[...]}}`，`knowledge_id` 从提示词 JSON 中提取真实 ID |
| 主观题批改 | `grading assistant` | `{score:100, correct:true, error_analysis, reference_answer}` |
| 每日小测 | `daily-quiz generator` | 5 题 3+1+1，前 3 题 `knowledge_id` 取自提示词 JSON，第 4/5 题含 `word/meaning/example` |

三种 fixture 行为：

| `mock_mode` | 行为 | 用途 |
|---|---|---|
| `success` | 返回上述合法 JSON，`status=200`、`ok=true` | 全部业务套件离线跑通 |
| `timeout` | 延迟 300ms 后返回 `status=0, ok=false, body="mock timeout"` | 验证超时/重试/降级路径 |
| `5xx` | 返回 `status=503, ok=false, body="mock upstream 503"` | 验证服务端错误重试与兜底 |

- fixture 内容存 `config/ai_mock.json`，占位符 `{WORD}`、`{KNOWLEDGE_IDS}`、`{USER_ANSWER}` 由代码替换；
- Mock 不写数据库、不读网络、输出确定；
- `mock_mode=off` 时完全走现有 Provider，生产行为不变。

### 3.4 测试用例适配原则

- 只改「连接参数」与「前置数据」，不改断言含义；
- `stage1` 的 AI 网关 `5340` 直连断言在 Mock 模式下标记 `~` 跳过，成功/超时/5xx 由 `stage17` 覆盖；
- `stage11` 前置插入 1 条游客（user_id=1）已固化知识点及子表，避免新库无数据导致小测无法出题；
- 其余套件保持「自建测试用户 + 仅清理本用户名下数据」的现状，叠加独立库后即天然隔离。

### 3.5 人工修改渠道

- Mock 内容：`config/ai_mock.json`；
- Mock 开关：`config/ai.json` 的 `mock_mode` 或环境变量 `ENG_AI_MOCK_MODE`；
- 测试库名/端口/产物目录：`TEST_DB_NAME`、`TEST_API_PORT`、`_env.js`；
- 测试数据库结构唯一来源：`scripts/sql/`。

## 六、风险与应对

| 风险 | 应对 |
|---|---|
| 测试库初始化脚本包含 `DELIMITER` 存储过程 | 用 mysql 客户端按文件输入执行，不用 `-e` 拼接；初始化后校验表数量/关键表 |
| 测试端口 18088 被占用 | 启动前探测，明确报错并提示改 `TEST_API_PORT` |
| Mock fixture 与真实 AI schema 漂移 | fixture 以 `prompts.h` schema 为准；`stage17` + 业务套件双重校验字段完整性 |
| 测试期间用户同时操作开发库，行数快照误报 | 快照只覆盖业务表并打印差异；回归时保持开发库空闲；误报提示为「开发库被外部写入」而非测试污染 |
| 部分套件隐含依赖开发库存量数据 | 逐套件在空测试库运行，失败项补最小前置数据（不改断言） |
| Mock 超时/5xx 触发重试导致测试变慢 | 测试环境用 `ENG_AI_RETRY_INTERVAL` 缩短等待；默认生产参数不变 |
| 备份/临时文件写入真实目录 | 独立后端用 `ENG_WORD_TMP`/`ENG_BACKUP_DIR` 指向测试临时目录 |
| 数据库备份服务文件名固定 `english_learning_*` | 仅文件名前缀差异，落在测试目录，不影响隔离；本任务不改业务逻辑 |

## 七、回滚方式

1. 代码回滚：`git checkout -- backend/include/ai_provider.h backend/src/ai_provider.cpp backend/include/ai_client.h backend/src/main.cpp config/ai.json tests/`，删除 `config/ai_mock.json`、`tests/stage17_ai_mock.test.js`；
2. 数据回滚：本任务不修改开发库；测试库 `eng_app_test` 直接 `DROP DATABASE`；
3. 环境回滚：不设置任何 `ENG_*`/`TEST_*` 环境变量即恢复原行为；
4. 生产影响：`mock_mode` 默认 `off`，即使代码保留也不会走 Mock。
