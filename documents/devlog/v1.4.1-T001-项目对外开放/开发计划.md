## 一、目标

在不改动任何业务功能的前提下，把项目从「仅作者 macOS 可运行」变为「任意机器 `git clone` → `docker compose up` 即可完整使用」，并补齐对外开源物料。

## 四、任务分解

### T1 Linux 编译与 MySQL 初始化 Spike（不产出正式资产，只验证）
1. 用 `mysql:8.0` 容器验证：`MYSQL_DATABASE=english_learning` + 挂载 8 个 SQL 自动导入，表数 29；`--lower-case-table-names=2` 仅能在空数据卷首次初始化生效；
2. 在 Ubuntu 24.04 容器内验证后端编译：`g++ -std=c++17 src/*.cpp -lmysqlclient`（无 rpath，跑 `ldd` 确认库可达）；
3. 记录结论（Go/No-Go）到本目录 `Spike结论.md`。

**Go 条件**：编译通过、29 表建立、容器内 `mysql` 客户端可连、后端能启动并响应 `/api/health`。

### T2 去硬编码（后端 + 脚本）
1. `main.cpp`：root 默认值改为「`APP_ROOT` → 可执行文件上级目录 → 当前目录」三级回退，保留 `--root`；静态资源改用同一 root；
2. 2 处 `NODE_BIN` 硬编码与 `knowledge_service.h:629` 统一；
3. 6 个脚本 + `local_ai_server.js` 去绝对路径；
4. `grep -rn "/Users/junwang" backend scripts start_all.command` 结果清零（`tests/` 的 48 处归 T6 参数化）。

### T3 Docker 化
1. `Dockerfile`（多阶段：builder 编译后端 → runtime 装 Node 20 + `npm ci` + 运行库）；
2. `docker-compose.yml`：`db`（mysql:8.0，volume、init SQL、healthcheck）+ `app`（依赖 db 健康后启动；端口仅发布 `127.0.0.1:${APP_PORT}:8088`；挂载 `config/ai.json`）；
3. `docker/entrypoint.sh`：渲染 `config/db.json`（TCP + 环境变量密码，不使用 socket）、前台同时托管 Node 网关与后端、退出时一并停止；
4. `.env.example` + `.dockerignore`（排除 `config/ai.json`、`backups/`、`logs/`、`node_modules/`、`word_tmp/`、`documents/`）。

### T4 Codespaces
`.devcontainer/devcontainer.json` 复用 compose 服务，附「填 Key → 启动 → 打开 8088」说明。

### T5 对外物料
README 重写（中文为主 + 英文摘要）、MIT LICENSE、3 个 Issue 模板、CONTRIBUTING 增补 Docker 与测试章节。

### T6 测试改造与自测
1. `tests/_env.js` 统一读取 `MYSQL_BIN`/`MYSQL_PW_FILE`/`MYSQL_SOCKET`/`DB_HOST`/`DB_PORT`，现有 15 个测试文件接入；
2. 新增 `stage16_docker_assets.test.js`（与 stage14 一致性巡检、stage15 HTTP 加固不重号）；
3. 宿主机回归：`node tests/run_all.js` 17 套件全通过；
4. 容器内回归：`docker compose exec app node tests/run_all.js`；
5. 手工闭环：注册 → 录入固化 → 生成 Word 导出 → 下载 `.docx` → `docker compose down/up` 数据保留。

### T7 文档同步与变更记录
D13/D14 修正；《方案说明》补 D1–D14 决议；更新 `产品现状.md`、`开发计划.md`、`核心参数.md`、`工作总结.md`；版本号在发布环节按规范判定（本任务无新增接口/表）。

## 六、风险与应对

| 风险 | 应对 |
|---|---|
| **本机未安装 Docker（已实测 `docker` 不可用）** | T1 起需 Docker Desktop 或 Linux 主机；无环境则只能做代码与静态校验，验收条款暂停 |
| `lower_case_table_names=2` 与 `mysql:8.0` 初始化冲突 | T1 Spike 先验证；不通过则改 `=0` 并核查代码中表名大小写一致性 |
| `01_schema.sql` 含 `DROP TABLE` | 仅在空数据卷首次初始化执行；禁止对已有数据挂载初始化目录 |
| 测试 15 个测试文件均写死 macOS 的 mysql 路径 | T6 统一改为环境变量，默认值保持 macOS 原样 |
| Linux 下 `mysqlclient` 链接方式与 rpath 不同 | Docker 内用 apt 库、不写 rpath；`ldd` 验证 |
| AI 网关与后端同容器进程管理 | entrypoint 用 supervisor 式前台等待，任一进程退出即整体退出，便于 `docker compose` 观察 |
| Word 导出依赖 Node 与 npm 包 | 镜像构建期 `npm ci`；测试覆盖单个/批量导出 |
| 密钥泄露 | `.dockerignore` 排除 `config/ai.json`；仅运行时挂载或走 `ZHIPU_API_KEY` |
| 阶段一被误暴露公网 | 端口映射限定 `127.0.0.1`；README 明确「阶段一不对外」 |

### 遗留与偏差

1. `docker compose down` 会保留卷；只有 `down -v` 才清空数据 —— 已写入 README 与指南。
2. 阶段二（阿里云 99 计划在线站点）未启动，按 D9 留待后续版本。
3. 本机 `clang++` 曾因 Apple CLT 安装器缺陷不可用（`machdep.cpu.features` 为空导致 `cpuFeatures.split` 报错）；已用组件包 `installer -pkg` 绕过修复，详见《工作总结》「五·补」章节。
4. 宿主机的 `config/db.json` 仍保留 `~/.local` 路径，属本机模式配置；Docker 模式不读取该路径。
