## 二、设计决策

| # | 决策 | 理由 |
|---|------|------|
| 1 | **kp-entry：单列 `.page` + `.section-title` + 三个 `.wing-card`** | 录入页信息密度低（表单+列表），用三开间 `.hall` 反而拥挤；单列 wing-card 即可形成清晰分区 |
| 2 | **kp-detail：单列 `.page` + `.section-title` + 六板块 `.wing-card` + 顶部 `<select>` 选择器** | 详情页需要快速切换词条；`<select>` 下拉在 1000 条以内足够好用（超大量可后续改为可滚动列表）；选择器独立 wing-card |
| 3 | **朗读按钮融入 `.wing-card__cap` 与词条标题同行** | 视觉更紧凑；用 `.u-push-end` 推到右侧；TTS 事件通过事件委托绑定（避免内联 onclick） |
| 4 | **所有内联 style/onclick 清零**，JS 统一 IIFE 封装 + 事件委托 | 符合 AGENTS.md 规范 |
| 5 | **6 个 extra 板块按 EXTRA_ORDER 固定顺序渲染** | 与 AI 固化管道输出顺序一致（音标→词根→同源→典故→近义辨析→短语解析→重点补充→频率→语域→文化延伸→同类词语） |

## 四、页面结构

### kp-entry.html
```
#topbar-slot                          ← T102 nav.js
.page
├─ .dougong-bar 斗拱装饰
├─ h1.section-title「录入知识点」
├─ p.section-sub「单条录入 · 批量 AI 固化 · 实时查重」
├─ .wing-card「新建词条」              ← 录入表单（content + remark + 按钮 + msg）
├─ .wing-card「AI 一键固化」           ← 固化/导出 Word 按钮
└─ .wing-card「语言包 · 知识点」       ← 搜索 + .pack 列表（每个词条 图标式 三按钮）
```

### kp-detail.html
```
#topbar-slot                          ← T102 nav.js
.page
├─ .dougong-bar 斗拱装饰
├─ h1.section-title「知识点详情」
├─ p.section-sub「选择词条 → 六板块结构化呈现 · AI 朗读」
├─ .wing-card「选择词条」              ← <select> + 条数
├─ .wing-card「核心释义 & 例句」        ← .kp-title + .speak-btn + pill + .entry
├─ .wing-card「固定搭配」              ← .entry 列表（可选）
├─ .wing-card「近义 / 反义」           ← .kp-synonym（可选）
└─ .wing-card「词根与词源 / 同源词汇 / 典故 / 同义词辨析 / …」
                                       ← 按 EXTRA_ORDER 顺序，缺省不渲染
```
