## 八、v1.2 现行方案：宝库改为抽屉浮层（2026-10-02）

### 为什么改

用户指出宝库不该是独立页，且不该重复仪表盘已有的功名 / 朱砂印 / 本周课规。总纲第七节验收标准第 4 条「扩展内容（次要页面/弹窗）优先以抽屉/浮层形式呈现」本就支持此方向。

### 现行结构

```
所有引入 nav.js 的页面（首页 + 8 个副页）
└─ 顶栏 .topnav 右侧激励区（激励区 3 个入口自 T103-v1.2 起为 <button data-treasury-open>）
   🪙 金桂余额 · 称谓 · 头像  ──点击──▶  #treasury-drawer 抽屉浮层（nav.js 注入 document.body）
                                          ├─ 标题「圣殿宝库」+ 关闭 ×
                                          ├─ 金桂余额（BALANCE_CAP=10000 → 9,999+）
                                          ├─ 三统计 .stat-card：累计收入 / 累计消耗 / 掌握词条
                                          └─ 圣殿账册（.task-item--static 双行：名目 + 时间 / ±N）

frontend/index.html（仪表盘页，独占）
├─ 西厢「本周课规」卡  ←─ 进度展示 + 卡脚「设定课规」按钮（data-goal-open）
│   └─ 登阶 / 朱砂印 / 课规进度（原本就在首页，不变）
└─ #goal-drawer 抽屉浮层（设定课规表单：类型 select + 目标 input + 保存）
```

### 数据与常量

| 项 | 位置 | 说明 |
|----|------|------|
| 宝库抽屉数据 | `nav.js` → `GET /api/treasury` | 用 `balance` / `total_earned` / `total_spent` / `mastery_count` / `txns` |
| 金桂名目中文 | `nav.js` `TREAS_REASONS`（10 条） | 与 `config/rewards.json` 同步 |
| 余额封顶 | `nav.js` `BALANCE_CAP = 10000` | ≥ 此值显示 `9,999+` |
| 课规类型文案 | `index.html` `GOAL_TYPES` | `review_items` / `new_words` / `quiz_count` |
| 课规保存 | `index.html` → `POST /api/treasury/weekly-goal` | 校验 >0，成功后 `load()` 并 0.7s 自动关抽屉 |

### 交互（三法关闭 + 键盘可达）

打开：点激励区任一入口（`[data-treasury-open]`）/ 点首页「设定课规」（`[data-goal-open]`）。
关闭：点抽屉「×」（`[data-treasury-close]` / `[data-goal-close]`）、按 `Escape`、点遮罩。
无障碍：`.drawer-overlay` 未加 `.open` 时为 `opacity:0 + pointer-events:none + visibility:hidden`（`visibility` 参与过渡），因此**关闭态不进入无障碍树也不可 Tab 聚焦**。

### 六态覆盖

| 态 | 方式 |
|----|------|
| 默认 | 抽屉壳层在 `DOMContentLoaded` 预热注入，关闭态不可见不可点 |
| 加载 | 账册区初始 3 条 `.skeleton--text` |
| 空 | 账册空态「暂无流水记录 —— 完成复习或小测即可得金桂。」 |
| 错误 | `#td-error` 输出 `.state-line--danger` + `[data-treasury-retry]` 重试按钮（仅重载抽屉数据，不触发页面 `load()`） |
| 成功 | 真实 API 数据 |
| 边界 | 余额 ≥10000 → `9,999+`；账册条数由后端 `getTxns(uid,10)` 固定 10 条 |
