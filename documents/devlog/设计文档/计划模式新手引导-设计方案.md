## 2. 目标与非目标

### 2.1 目标

1. 第一次进入计划模式首页的人，30 秒内知道三件事：先定课规、每天看观卷、每天看今日概览。
2. 引导只做「指路」，不改变首页结构，不新增常驻元素；关闭后页面与现状完全一致。
3. 与功能模式引导、子页导览、AI 向导抽屉、计划面板互不打架。
4. 全部本机记忆，零后端、零新增接口、零数据库改动。

### 2.2 非目标

- 不替代功能模式引导；两套引导按界面模式各管一套。
- 不介绍模式切换、不介绍导出中心；今日概览只做一句话指路，不展开内部机制。
- 不在计划模式里新增功能或改首页布局。
- 本轮不新增页面、不改后端、不改数据库、不升版本。

## 3. 五幕与三步的对应关系

### 3.1 分组原则

五幕是页面叙事，不等于五个必须打断用户的步骤。按「用户接下来要做什么」压缩为三步：

1. **入殿 + 课规**：进殿第一件事是定课规，所以第一步直接指向「本周课规」卡与「设定课规」。
2. **观卷**：每天最高频的动作是看今天要复习什么，单独一步。
3. **今日概览**：每天收尾看一眼今日到期、待学新词和今日小测；上方课规和观卷会跟着更新。留印、登阶不再单独引导。

### 3.2 逐步设计

| 步骤 | 覆盖五幕 | 聚光目标（现状选择器） | 指向入口 | 标题（待定稿） | 正文（待定稿） |
|---|---|---|---|---|---|
| 1 / 3 | 入殿 + 课规 | `.hall__wing.plan-only` 内第一张 `.wing-card`（本周课规卡） | 卡内「设定课规」按钮 `[data-goal-open]` | 先定这周的课规 | 课规就是这周的小目标。点「设定课规」，圣殿按周替你排好复习和新词。 |
| 2 / 3 | 观卷 | 东厢最后一张 `.wing-card`（观卷卡） | 卡内「前往复习 →」链接 `/pages/review.html` | 每天先看观卷 | 今天该复习的词都排在观卷里。点「前往复习」，几分钟就能过一遍。 |
| 3 / 3 | 今日概览（文案带一句上方栏目） | `.today-study` 今日概览卡 | 无点击入口；文案提示上方课规和观卷会更新 | 每天看一眼今日概览 | 今日到期、待学新词、今天要不要小测，都在这里；上方课规和观卷会跟着更新。 |

说明：

- 「入殿」没有独立可点区块，作为第 1 步的开场语境，不单独聚光，避免为一句氛围文案浪费一步。
- 第 3 步只聚光「今日概览」，文案带一句上方课规与观卷会联动；「留印」「登阶」不再单独引导，避免把演示注意力拉到长期成就上。
- 三步都只指路，不替用户点击；聚光期间底层页面不可操作，关闭后用户自己点。

### 3.3 卡片交互（沿用功能模式口径）

| 项 | 规则 |
|---|---|
| 计数 | `1 / 3`、`2 / 3`、`3 / 3`，右侧三圆点，已过步骤点亮 |
| 按钮 | 步 1「下一步 / 跳过」；步 2「上一步 / 下一步 / 跳过」；步 3「上一步 / 开始使用」 |
| 关闭 | Esc 等同「跳过」；最后一步「开始使用」等同完成 |
| 语义 | `role="dialog"`、`aria-modal="true"`、`aria-label="新手引导"` |
| 动效 | 复用 `.onboard-spot` 过渡；`prefers-reduced-motion` 下关闭位移动画 |
| 样式 | 全部复用 `.onboard-*`，不新增视觉语言 |

## 4. 触发条件与互斥

### 4.1 自动触发（仅一次）

同时满足才弹出：

1. 页面是首页 `index.html`。
2. 当前界面模式为 `plan`，且已「稳定」：游客以本机 `eng_ui_mode` 为准；登录用户等 `/api/auth/me` 返回并应用账号 `ui_mode` 之后再判断，避免本机 `function`、账号 `plan` 时误判。
3. 本机没有 `eng_onboard_plan_v1` 已读标记。
4. 当前没有其他浮层：计划面板、导出抽屉、AI 向导抽屉均未打开；页面上也不存在 `.onboard` 节点。
5. 首屏数据已发起且页面结构已就绪：沿用现有「首屏数据完成或 1.2s 超时兜底」口径；计划模式区块由 `load()` 渲染，目标卡即使仍是骨架也能定位。

**同页手动切换模式不立即弹出**：用户从功能模式切到计划模式时，正在操作页面，不打断；本次切换不弹，下次刷新进入计划模式再按上述规则判断。理由与功能模式「只在进入首页时弹」一致。

### 4.2 登录前后

| 场景 | 规则 |
|---|---|
| 游客首次进入计划模式首页 | 可以弹；文案不涉及登录。第 1 步指向「设定课规」，用户关闭引导后自己点，仍走现有 401 → 登录跳转 |
| 登录后回到首页且账号为计划模式 | 按 4.1 判断；同一浏览器已读则不再弹 |
| 同一浏览器先游客看过、再登录 | 已读状态共享，不再弹；不按账号区分 |
| 换浏览器 / 换设备 | 视为首次，会再弹一次；与功能模式引导行为一致 |

不按账号区分是有意取舍：现有新手引导、首用提示、子页导览都只存本机。若以后要求「每个账号各看一次」，再改为 `eng_onboard_plan_v1_u{user_id}`，不在本轮扩大范围。

### 4.3 与页面级导览（`tour.js`）的关系

- 首页不加载 `tour.js`；子页导览只在 `review`、`kp-entry`、`daily-quiz`、`wordbook` 四页出现。两者不在同一页，**天然不会同屏**。
- 记忆键各自独立：首页计划模式用 `eng_onboard_plan_v1`；子页继续用 `eng_tour_*_v1`。
- 不要求「看过首页引导就跳过子页导览」；保持 T003 已裁定口径「每页独立」。
- 若未来首页也接入 `tour.js` 或子页新增首页级引导，统一加一条前置：页面已存在 `.onboard` 时不再启动第二个导览；本轮不实施。

### 4.4 与 AI 向导抽屉、计划面板、导出抽屉

| 对象 | 规则 |
|---|---|
| AI 向导抽屉 | 不会自动打开；若触发前用户已手动打开，**推迟**到抽屉关闭后再判断是否弹；引导展示期间底层被遮罩覆盖，用户无法打开抽屉 |
| 计划面板（设定课规） | 同上：已打开则推迟；引导期间不可打开 |
| 导出抽屉 | 同上 |
| 层级 | 引导 `z-index: 500` 高于抽屉与顶栏（300 / 100）。即使出现极端叠加，引导在最上层；正常流程通过「推迟触发」避免叠加 |
| AI 向导「新手引导」动作 | 首页仍跳 `/?onboard=1`；进入后由当前模式决定重放功能模式或计划模式引导，不需要改动作配置 |

### 4.5 目标缺失兜底

- 目标元素不存在、被隐藏、宽高为 0 时，按功能模式现有兜底：全屏遮罩、卡片居中（桌面）/ 贴底（移动），不报错、不中断。
- 计划模式区块在 `function` 下是 `display:none`，但引导只会在 `plan` 下触发，正常不会命中隐藏目标；仍保留兜底。

## 5. 跳过、不再提示、重新播放与存储

### 5.1 行为

| 操作 | 结果 |
|---|---|
| 步 1/2 点「跳过」 | 关闭浮层，写入已读；不再自动出现 |
| 最后一步点「开始使用」 | 关闭浮层，写入已读 |
| 按 Esc | 等同「跳过」，写入已读 |
| 点遮罩空白 | 不关闭（与现有功能模式一致，避免误触） |
| 「不再提示」独立开关 | **不做**。跳过即代表不再自动提示；不增加复选框与额外文案 |
| 重放 | `?onboard=1` 可重放；重放**不写入**已读，不改变原有状态 |

### 5.2 localStorage 键名建议

| 键 | 用途 | 值 | 说明 |
|---|---|---|---|
| `eng_onboard_plan_v1` | 计划模式首页引导已读 | `'1'` | **新增，独立于功能模式** |
| `eng_onboard_v1` | 功能模式首页引导已读 | `'1'` | 保持不变，不复用、不改名 |
| `eng_tour_*_v1` | 子页导览已读 | `'1'` | 保持不变 |

**不复用 `ONBOARD_KEY` 的理由**：两套引导内容不同、触发模式不同。复用会导致「看过功能模式引导的人永远看不到计划模式引导」，而比赛演示账号恰好使用计划模式。

### 5.3 重放参数

- 沿用 `?onboard=1`，不新增 `?onboard=plan`。
- 页面读取参数后按当前稳定模式分流：
  - `plan` → 重放计划模式三步；
  - `function` → 重放现有功能模式三步。
- 重放时用 `history.replaceState` 去掉参数，避免刷新重复重放。
- 已读标记只在「非重放」关闭时写入。
- AI 向导动作、`config/action_rules.json` 与 `action_service.h` 的 `pageRoutes` 无需改动：首页仍回 `/?onboard=1`。

### 5.4 滚动位置

第 3 步会把页面滚到「今日概览」。关闭引导后建议恢复进入引导前的滚动位置（通常为顶部），避免用户被留在页面中部。重放同样恢复。若用户明确想继续看该区块，可自行下翻。

## 6. 375px 小屏表现与遮挡规则

| 规则 | 说明 |
|---|---|
| 卡片形态 | ≤640px 贴底；左右各 16px；宽度自适应；不出现横向滚动 |
| 按钮 | 主/次按钮最小高度 44px；文案单行不换行（沿用 T003 已修的 `.onboard-card__acts .btn` 规则） |
| 聚光定位 | 目标先滚到视口上部约 40% 区域，再挖孔；卡片固定在底部，不覆盖目标 |
| 目标过高 | 若目标高度超过可视区上方可用空间（约 45vh），或目标底部会落到卡片下面，降级为「全屏遮罩 + 不挖孔 + 卡片贴底」，目标滚到上部可见即可 |
| 目标过宽 | 聚光孔左右夹在 `0 ~ 100vw` 内，避免超出屏幕 |
| 页面中段目标 | 「今日概览」靠近页面下半部，滚动时预留卡片高度，优先把卡片放在其下方；空间不足时先滚动让位，再放卡片 |
| 底部安全区 | 建议卡片底部加 `env(safe-area-inset-bottom)`，避免被手机手势条压住 |
| AI 向导吸边入口 | 引导期间被遮罩压暗；若与贴底卡重叠，以卡片为准，不额外隐藏入口；关闭后入口恢复原样 |
| 深色模式 | 沿用 `html[data-theme="dark"] .onboard-spot` 的遮罩；不新增配色 |
| 减弱动效 | `prefers-reduced-motion` 下无过渡 |

## 7. 验收标准与人工检查步骤

### 7.1 验收标准（本次实施）

- [ ] 计划模式首次进入首页自动弹三步；聚光依次为「本周课规」卡、「观卷」卡、「今日概览」卡；「入殿」「登阶」「留印」不被单独聚光。
- [ ] 三步标题与正文与最终定稿逐字一致；不出现「计划模式」「localStorage」「接口」等机制词。
- [ ] 跳过 / 开始使用 / Esc 后写入 `eng_onboard_plan_v1`；刷新不再自动弹。
- [ ] 功能模式引导行为完全不变：`eng_onboard_v1` 独立，计划模式弹过不影响功能模式，反之亦然。
- [ ] `?onboard=1` 在计划模式重放三步、在功能模式重放原三步；重放不写入任何已读键。
- [ ] 计划面板 / 导出抽屉 / AI 向导抽屉打开时，引导推迟；引导展示时无法打开这些浮层。
- [ ] 子页导览不受影响，四页仍各自首访一次。
- [ ] 375px：卡片贴底、按钮 44px、无横向滚动、目标不被卡片遮挡；长目标按降级规则处理。
- [ ] 关闭引导后页面结构与导览前一致；滚动位置恢复到进入前。
- [ ] 全程无网络写请求；只写本机 localStorage。

### 7.2 人工检查步骤

1. 清空浏览器 localStorage，把界面切到计划模式，刷新首页 → 应自动弹第 1/3 步，聚光「本周课规」卡。
2. 依次点「下一步」→ 聚光「观卷」卡 → 再点「下一步」→ 页面滚到「今日概览」，聚光该卡，卡片在其下方且不遮挡。
3. 点「开始使用」→ 浮层消失，页面回到顶部，刷新 → 不再自动弹。
4. 清空 localStorage，重来一次，在第 1 步点「跳过」→ 刷新不再弹；按 Esc 再测一次，结果一致。
5. 保持已读，访问 `/?onboard=1` → 计划模式三步重放；关闭后刷新 → 不弹；检查 localStorage 仍为已读。
6. 切到功能模式，清空 `eng_onboard_v1`（保留计划键）后刷新 → 功能模式原三步正常弹；计划键不影响它。
7. 打开计划面板或 AI 向导抽屉后刷新页面 / 触发 → 引导不与其叠加；关闭抽屉后按规则出现。
8. 进入 `review` / `kp-entry` / `daily-quiz` / `wordbook` → 子页导览仍各自正常。
9. 浏览器窗口缩到 375px 宽，重复第 1–3 步 → 卡片贴底、按钮不换行、目标在卡片上方、无横向滚动。
10. 登录一个账号为计划模式的演示账号，换新浏览器首次打开 → 账号模式生效后弹出；同一浏览器第二次登录不再弹。
11. 打开系统「减弱动态效果」→ 引导无位移动画。
