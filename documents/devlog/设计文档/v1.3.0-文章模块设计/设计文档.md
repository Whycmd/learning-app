## 一、模块定位与整体架构

### 1.1 产品定位

文章模块是本次迭代（v1.3.0）的 **P0 级** 核心新增功能，目标是让学习者能够阅读完整的英语原文文章，并通过一系列辅助工具降低阅读门槛、提升吸收效率。

### 1.2 参考标杆与已有开源项目

| 参考项目 | 类型 | 可复用思路 | 代码能否复用 |
|---------|------|-----------|------------|
| **扇贝阅读** | 商业产品 | 点词即查 + 生词高亮 + 听书 + 中英对照 | ❌（商业闭源） |
| **WordNest** | 开源 WP 插件 | 纯前端 JS DOM tooltip，零依赖 | ❌（WP 架构），✅ 思路可借鉴 |
| **Read Frog** | 开源浏览器扩展 | 智能内容提取 + 综合解释 | ❌（架构不同），✅ 思路可借鉴 |
| **Lector** | 开源自托管 | EPUB/URL 导入、句子高亮、TTS、生词 SRS | ✅ 前端逻辑可参考其实现思路 |
| **Adaptive English Teacher** | 开源 GitHub | 推荐系统 + 高亮 + 词汇系统 + 测试 | ✅ 推荐逻辑可参考 |
| **Word Hunter** | 开源桌面应用 | PDF/OCR 导入、上下文取词、SRS 复习 | ✅ 导入流程 + 上下文取词思路 |
| **LinguaCafe** | 开源自托管 | YouTube 字幕导入、多视图词汇、TTS | ✅ 导入方式 + TTS 集成 |
| **CEFRLex / EFLLex** | 学术语料库 | 12.3 万词 CEFR 分级词频数据（CSV） | ✅ 直接下载作为难度数据源 |
| **gnews / open-news-api** | 开源 Python 库 | Google News 搜索 + 全文提取 | ✅ 思路可移植到 Node.js 网关 |

### 1.3 整体架构原则

```
┌──────────────────────────────────────────────────────┐
│                    前端 pages/                        │
│  articles.html（主入口）                               │
│    ├─ TTS 播放控制模块（Web Speech API，独立 JS）       │
│    ├─ 点词查词模块（基于 WordNest 思路，原生 JS）       │
│    ├─ 生词本联动模块（复用已有 wordbook API）           │
│    ├─ 习题模块                                         │
│    ├─ 背景知识/赏析/素材模块                           │
│    ├─ AI 推荐文章模块                                  │
│    └─ 阅读设置面板（字体/对照/模式）                    │
├──────────────────────────────────────────────────────┤
│                  C++ 后端（main.cpp）                  │
│  路由注册 /api/article*                               │
│  articles_service.cpp / .h（新建）                    │
│  articles_context_service.cpp（外部数据聚合）          │
│  articles_recommend_service.cpp（新）                  │
├──────────────────────────────────────────────────────┤
│                      MySQL 8.0                        │
│  articles / article_sentences /                       │
│  article_vocabulary / article_quizzes /               │
│  article_import_records /                             │
│  article_recommend_queue（新）                         │
└──────────────────────────────────────────────────────┘
```

**核心原则**：每个子功能对应独立的 Service 层文件 + 独立的前端 JS 模块；核心数据模型共享（articles 主表），业务逻辑隔离；**AI 调用最小化**（详见第八章）。

## 三、数据库设计

### 3.1 新表清单（6 张表，加表 = MINOR 变更）

#### `articles` — 文章主表

```sql
CREATE TABLE articles (
  id              INT AUTO_INCREMENT PRIMARY KEY,
  user_id         INT NOT NULL,                         -- 归属用户（NULL 表示公共推荐文章）
  title           VARCHAR(500) NOT NULL,
  source_url      VARCHAR(1000),                        -- 原文链接（URL 导入时保留）
  source_name     VARCHAR(200),                         -- 来源媒体（如 BBC、 The Guardian）
  category        ENUM('news','history','literature','science','culture','professional','other')
                  NOT NULL DEFAULT 'other',
  content         MEDIUMTEXT NOT NULL,                  -- 英文原文（段落用 <p> 标签分隔）
  content_cn      MEDIUMTEXT,                           -- 中文译文（中英对照用）
  image_data      MEDIUMBLOB,                           -- 图片导入时的原始数据（可选）
  import_method   ENUM('url','text','image','ai_generated','ai_recommended','manual')
                  NOT NULL DEFAULT 'text',
  ai_analysis     JSON,                                 -- AI 分析结果快照（背景/赏析/素材，缓存复用）
  cefr_level      VARCHAR(10) NOT NULL DEFAULT 'B1',    -- CEFR 难度等级（A1-C1）
  word_count      INT NOT NULL DEFAULT 0,               -- 字数缓存
  created_at      DATETIME NOT NULL DEFAULT CURRENT_TIMESTAMP,
  updated_at      DATETIME NOT NULL DEFAULT CURRENT_TIMESTAMP ON UPDATE CURRENT_TIMESTAMP,
  INDEX idx_user_id (user_id),
  INDEX idx_category (category),
  INDEX idx_cefr (cefr_level)
) ENGINE=InnoDB DEFAULT CHARSET=utf8mb4 COLLATE=utf8mb4_unicode_ci;
```

> **变更说明**：`difficulty_level TINYINT` 改为 `cefr_level VARCHAR(10)`，采用 CEFR 标准（A1/A2/B1/B2/C1）。

#### `article_sentences` — 文章句子表（TTS 分句用）

```sql
CREATE TABLE article_sentences (
  id           INT AUTO_INCREMENT PRIMARY KEY,
  article_id   INT NOT NULL,
  sentence_no  INT NOT NULL,                        -- 句子序号（从 1 开始）
  sentence_en  TEXT NOT NULL,                       -- 英文原文句子
  sentence_cn  TEXT,                               -- 中文翻译（可选）
  cefr_level   VARCHAR(10) NOT NULL DEFAULT 'B1',   -- 句子 CEFR 难度
  INDEX idx_article_id (article_id)
) ENGINE=InnoDB DEFAULT CHARSET=utf8mb4 COLLATE=utf8mb4_unicode_ci;
```

#### `article_vocabulary` — 文章词汇难度表

```sql
CREATE TABLE article_vocabulary (
  id           INT AUTO_INCREMENT PRIMARY KEY,
  article_id   INT NOT NULL,
  word         VARCHAR(100) NOT NULL,               -- 归一化（小写、去标点）
  position     INT NOT NULL,                        -- 在文章中出现的字符位置
  occurrence   INT NOT NULL DEFAULT 1,              -- 出现次数
  cefr_level   VARCHAR(10) NOT NULL DEFAULT 'B1',   -- 词汇 CEFR 难度（查 EFLLex 表）
  is_new_word  TINYINT(1) NOT NULL DEFAULT 0,       -- 是否对用户为"生词"
  user_id      INT,                                 -- NULL 表示全局标记
  INDEX idx_article_id (article_id),
  INDEX idx_word (word)
) ENGINE=InnoDB DEFAULT CHARSET=utf8mb4 COLLATE=utf8mb4_unicode_ci;
```

#### `article_quizzes` — 阅读理解题

```sql
CREATE TABLE article_quizzes (
  id           INT AUTO_INCREMENT PRIMARY KEY,
  article_id   INT NOT NULL,
  question_no  INT NOT NULL,
  question_type ENUM('reading_comprehension','vocabulary_in_context','inference','literary_device') NOT NULL,
  question_text TEXT NOT NULL,
  options      JSON,                                -- [{"text":"...","is_correct":false}, ...]
  correct_answer VARCHAR(200),                      -- 正确答案文本或选项标识
  explanation  TEXT,                                -- 答案解析
  cefr_level   VARCHAR(10) NOT NULL DEFAULT 'B1',
  created_by   ENUM('ai','manual') NOT NULL DEFAULT 'ai',
  INDEX idx_article_id (article_id)
) ENGINE=InnoDB DEFAULT CHARSET=utf8mb4 COLLATE=utf8mb4_unicode_ci;
```

#### `article_import_records` — 导入记录（图片导入追踪）

```sql
CREATE TABLE article_import_records (
  id             INT AUTO_INCREMENT PRIMARY KEY,
  user_id        INT NOT NULL,
  original_image BLOB,                             -- 原始截图/拍照
  extracted_text TEXT,                             -- OCR/AI 提取的文本
  status         ENUM('pending','processing','completed','failed') NOT NULL DEFAULT 'pending',
  article_id     INT,                              -- 处理后关联的文章 ID
  error_msg      VARCHAR(500),
  created_at     DATETIME NOT NULL DEFAULT CURRENT_TIMESTAMP,
  INDEX idx_user_id (user_id),
  INDEX idx_status (status)
) ENGINE=InnoDB DEFAULT CHARSET=utf8mb4 COLLATE=utf8mb4_unicode_ci;
```

#### `article_recommend_queue` — AI 推荐文章队列（新增）

```sql
CREATE TABLE article_recommend_queue (
  id           INT AUTO_INCREMENT PRIMARY KEY,
  user_id      INT NOT NULL,                       -- 目标用户（NULL 表示公开推荐）
  topic        VARCHAR(200) NOT NULL,              -- 推荐主题关键词
  cefr_level   VARCHAR(10) NOT NULL,               -- 目标 CEFR 等级
  status       ENUM('pending','fetched','processed','failed') NOT NULL DEFAULT 'pending',
  article_id   INT,                                -- 处理完成后关联
  error_msg    VARCHAR(500),
  created_at   DATETIME NOT NULL DEFAULT CURRENT_TIMESTAMP,
  INDEX idx_user_id (user_id),
  INDEX idx_status (status)
) ENGINE=InnoDB DEFAULT CHARSET=utf8mb4 COLLATE=utf8mb4_unicode_ci;
```

### 3.2 表间关系

```
articles (1) ──┬── (N) article_sentences
              ├── (N) article_vocabulary
              └── (N) article_quizzes

article_import_records (N) ── (1) articles
article_recommend_queue (N) ── (1) users
```

## 四、子功能详细设计（各自独立，核心集成）

### 4.1 子功能 A：点词即查（Word Lookup）

**参考实现**：[WordNest](https://github.com/Simon-xuan/Wordnest)（纯 JS/CSS，无依赖，tooltip 模式）

**设计要点**：
- 复用 WordNest 核心思路：**遍历 DOM text node，匹配术语列表，包裹 `<abbr>` 标签**
- 自行实现轻量级 DOM 解析（`TreeWalker`），不引入 WordPress 依赖
- 点击/悬停时弹出 tooltip，显示：单词、音标、CEFR 等级、释义、例句
- **数据来源优先级**：
  1. 本地 `knowledge_points` 库（命中则直接返回已固化数据，**不调 AI**）
  2. 本地 EFLLex CEFR 词频表（返回词频等级，**不调 AI**）
  3. AI 网关快速查询（仅当上面两者都无结果时调用）

**接口**：
```
GET /api/article/:id/words?word=xxx     # 查询单个词详情（命中知识库则返回已固化数据）
```

**前端模块**：`frontend/static/js/articles/modules/word_lookup.js`

**依赖**：无外部依赖；可提取 WordNest 前端核心逻辑移植为原生 JS

---

### 4.2 子功能 B：生词高亮（Vocabulary Highlight）

**设计要点**：
- **难度计算**：查询 EFLLex 语料库（本地 CSV 预加载）获取每个词的 CEFR 等级
- **生词判定逻辑**（用户 CEFR 等级记为 `user_cefr`）：
  - `word_cefr > user_cefr + 1` → 生词（绿色下划线虚线，参考扇贝）
  - `word_cefr = user_cefr + 1` → 边缘词（黄色下划线虚线）
  - `word_cefr <= user_cefr` → 已掌握（正常文本）
- **CEFR 等级映射**：A1 < A2 < B1 < B2 < C1，按此顺序比较
- **用户 CEFR 等级**从 `users.learner_identity` 推断：
  - 高中生 → B1
  - CET-4 备考者 → B1-B2
  - 雅思备考者 → B2-C1

**接口**：
```
GET /api/article/:id/difficulty-report   # 返回文章难度报告（含生词列表）
```

**前端模块**：`frontend/static/js/articles/modules/vocab_highlight.js`

---

### 4.3 子功能 C：长难句拆解（Long Sentence Breakdown）

**设计要点**：
- 触发方式：用户点击句子右侧的「拆解」按钮
- 调用 AI 网关，使用定制 prompt 输出结构化 JSON：
  ```json
  {
    "structure_type": "complex",
    "main_clause": "主句内容",
    "subordinate_clauses": ["从句1", "从句2"],
    "grammar_points": ["定语从句", "状语"],
    "translation": "中文翻译"
  }
  ```
- 显示在句子下方的折叠面板中
- **结果可缓存在 `article_sentences` 表的 `analysis_json` 字段（需新增列），避免重复调用**

**接口**：
```
POST /api/article/:id/sentence/breakdown   # body: { sentence_id: int }
```

**前端模块**：`frontend/static/js/articles/modules/long_sentence_break.js`

---

### 4.4 子功能 D：原声音频播放（TTS Playback）

**设计要点**：
- **技术方案**：Web Speech API（`speechSynthesis`），免费、无需外部 API 调用、无需生成 MP3
- **句子级控制**：按 `article_sentences` 表逐句播放，当前句高亮（`onboundary` 事件）
- **语速控制**：0.5x ~ 2.0x，默认 1.0x
- **播放模式**：单句循环 / 自动连播 / 整篇朗读
- **进度条**：显示当前播放位置 + 总句数
- **备用方案**：当 Web Speech API 不可用时，降级为文字高亮无音频
- **不生成音频文件，不下载 MP3**（满足用户 Q3=A 的确认）

**接口**：
```
GET  /api/article/:id/sentences     # 获取分句列表（含 sentence_no, sentence_en, cefr_level）
```

> 注：TTS 完全在前端完成，不需要后端接口合成音频。

**前端模块**：`frontend/static/js/articles/modules/tts_player.js`

---

### 4.5 子功能 E：中英对照切换（Bilingual Toggle）

**设计要点**：
- 切换按钮：页面顶部工具栏
- 模式 1：**纯英文**（默认，适合精读训练）
- 模式 2：**中英对照**（英文在上，中文译文嵌入段落下方，灰色小号字体）
- 模式 3：**英文隐藏**（只显示中文，适合自测理解）
- 译文来源优先级：
  1. 本地 `content_cn` 字段（入库时已生成）
  2. 调 AI 网关实时翻译（按需，有缓存）

**接口**：
```
GET /api/article/:id/translation   # 获取中文译文（缓存命中直接返回）
```

**前端模块**：`frontend/static/js/articles/core/article_reader.js`（渲染引擎内置）

### 4.6 子功能 F：生词本联动（Vocabulary Book Sync）

**设计要点**：
- 阅读时，点击生词 tooltip → 「加入生词本」按钮
- 点击后调 `POST /api/wordbook/entries` 接口（**复用已有 API**，不新增）
- 同时更新 `article_vocabulary.is_new_word = 1`
- 读完文章后，弹出「复习本篇生词」按钮 → 跳转至播放复习页面
- **不修改 `user_learning` 遗忘曲线数据**（满足用户 Q5=A 的轻度联动确认）

**接口**：
```
POST /api/article/:id/add-vocab-to-book   # body: { word: string }
GET  /api/article/:id/new-words           # 获取本篇所有生词列表
```

**前端模块**：`frontend/static/js/articles/modules/vocab_book_sync.js`

---

### 4.7 子功能 G：配套阅读理解习题（Reading Quiz）

**设计要点**：
- AI 生成题型（4 种）：
  - `reading_comprehension`：细节理解题
  - `vocabulary_in_context`：语境猜词
  - `inference`：推理判断题
  - `literary_device`：修辞/手法识别（文学类文章特有）
- 题数：5 题（对标每日小测 3+1+1 的简化版）
- 用户作答后本地秒批（客观题），主观题提交后 AI 批改
- 答题结果**仅写入 `article_quizzes` 表，不联动 `user_learning`**（轻度联动）

**接口**：
```
POST /api/article/:id/quiz/generate   # AI 生成习题
GET  /api/article/:id/quiz            # 获取已有习题
POST /api/article/:id/quiz/submit     # 提交答案，返回得分
```

**前端模块**：`frontend/static/js/articles/modules/quiz_viewer.js`

---

### 4.8 子功能 H：文章背景知识（Article Context）

**设计要点**：
- **按需调用 AI**，结果缓存在 `articles.ai_analysis` JSON 字段中，下次直接返回
- **数据来源分层**：
  1. **时政/历史类**（`category = 'news' | 'history'`）：AI 生成背景摘要，优先引用 Wikipedia 风格表述
  2. **科学/专业类**（`category = 'science' | 'professional'`）：AI 解释关键概念，强调科普性
  3. **文学类**（`category = 'literature'`）：AI 提供简要背景，不展开赏析（赏析由子功能 I 单独处理）
  4. **文化类**（`category = 'culture'`）：AI 提供文化背景说明
- 显示位置：文章底部「背景知识」折叠面板
- **内容**：时代背景、作者介绍、事件概述、关键概念解释（不超过 200 字）

**接口**：
```
POST /api/article/:id/context/fetch   # 按需获取背景知识（首次调用 AI，后续返回缓存）
```

**前端模块**：`frontend/static/js/articles/modules/context_viewer.js`

### 4.9 子功能 I：专业/科学文章重点内容解析（Professional & Science Analysis）

**设计要点**（修改自原"文学赏析"）：
- **优先覆盖** `category = 'science' | 'professional'` 的文章（用户要求：专业文章科普优先）
- **同时支持** `category = 'literature'` 的文章（文学类文章也适用）
- AI 输出结构化解析 JSON（通用格式，根据文章类型适配输出）：
  ```json
  {
    "key_sentences": [
      {"sentence": "...", "analysis": "此句为文章核心论点，使用了...手法"}

  }
  ```
- 显示在文章底部的「解析」标签页
- **结果缓存在 `articles.ai_analysis` 中，避免重复调用 AI**

### 4.13 子功能 M：AI 推荐文章（AI Article Recommendation）【新增】

**设计要点**：
- **不直接生成文章**，而是从权威媒体/期刊杂志中**推荐**已有文章
- **参考 Adaptive English Teacher 的推荐逻辑**：根据用户 CEFR 等级 + 兴趣偏好，推送匹配难度的文章
- **数据来源**（按优先级，尽量减少 AI 调用）：
  1. **Currents API**（免费 600 次/天，14000+ 来源，78 语言）：获取最新英文新闻标题 + 摘要
  2. **Google News RSS**（免费无限制）：作为备用数据源
  3. **后端定时爬取**（Node.js 网关侧执行）：定期抓取优质英文文章 URL + 标题，存入推荐队列
- **推荐逻辑**：
  1. 根据用户 `learner_identity` 确定目标 CEFR 等级
  2. 筛选与用户已学词汇有重叠的文章（**结合正在学习的单词**）
  3. 返回文章标题、来源、URL、预览摘要、预估 CEFR 等级
- **用户点击推荐文章后**：
  1. 后端抓取文章全文（通过 `source_url`）
  2. 走完整处理流程（分句、CEFR 难度标注、习题生成）
  3. 写入 `articles` 表，标记 `import_method = 'ai_recommended'`
- **AI 调用最小化**：推荐列表本身不调 AI，仅用户点击后对单篇文章做一次全文分析

**接口**：
```
GET  /api/article/recommend          # 获取推荐文章列表（不调 AI，仅返回预抓取数据）
POST /api/article/recommend/fetch    # 手动触发一次推荐刷新（拉取最新头条）
POST /api/article/recommend/:id/save # 用户保存某篇推荐文章（触发完整处理流程）
```

**前端模块**：`frontend/static/js/articles/modules/recommend_viewer.js`

**前端展示**：文章列表页新增「AI 推荐」tab，展示推荐卡片列表（标题 + 来源 + 预估难度 + 摘要）

## 八、AI 调用优化策略（最小化 AI 用量）

### 8.1 核心原则

> **能缓存绝不重复调用，能查表绝不调 AI。**

### 8.2 调用时机矩阵

| 操作 | 是否调 AI | 条件 |
|------|---------|------|
| 文章录入（文本） | ❌ | 难度标注用 EFLLex 查表；分句用正则 |
| 文章录入（图片 OCR） | ✅ 仅 OCR 一次 | 其他处理用规则 |
| 点词查询 | ❌ 多数情况 | 知识库有则直接返回；EFLLex 有则返回等级 |
| 生词高亮 | ❌ | EFLLex 本地查表 |
| 长难句拆解 | ✅ 首次 | 结果缓存在 `article_sentences` 表 |
| 背景知识 | ✅ 首次 | 结果缓存在 `articles.ai_analysis` |
| 专业/科学解析 | ✅ 首次 | 结果缓存在 `articles.ai_analysis` |
| 作文素材 | ✅ 首次（仅非新闻类） | 结果缓存在 `articles.ai_analysis` |
| 阅读理解题 | ✅ 首次 | 结果缓存在 `article_quizzes` 表 |
| TTS 播放 | ❌ | 纯浏览器原生 API |
| AI 生成文章 | ✅ 生成时一次 | 后续处理用规则 |
| AI 推荐文章列表 | ❌ | Currents API 返回，不调 AI |
| 保存推荐文章 | ✅ 全文处理时一次 | 后续复用缓存 |

### 8.3 EFLLex 本地词频表加载

```
backend/src/articles_vocab_service.cpp
  ↓ 启动时调用
loadEfllExCache()
  ↓ 读取
backend/data/efllex.tsv  （部署时预置）
  ↓ 构建
std::unordered_map<string, string> word_cefr_map
  ↓ O(1) 查询
getWordCefrLevel(word) → "B1"
```

> 这是减少 AI 调用的关键：词汇难度判断完全本地化，无需任何网络请求。
