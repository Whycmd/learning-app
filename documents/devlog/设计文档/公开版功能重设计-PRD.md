## 1. 定位与变更

### 1.1 新定位

**主标语**：像私教一样陪你学英语。

能力层四件事（全部由 AI 承担「私教」角色，而非堆功能）：

1. 单词精读（六块结构化知识 + Markdown 精讲）
2. AI 实时训练（出题、批改、错因解释）
3. AI 阅读器（文章难度分级与分句，首发为预览版）
4. Word 纸质导出（把线上内容变成可打印的纸质材料）

### 1.2 目标人群与使用场景

| 维度 | 结论 |
|---|---|
| 核心人群 | 高中生（高考）、大学生（四六级/考研）、雅思考生 |
| 水平分布 | 全水平混合，不做分层门槛 |
| 使用场景 | 手机碎片时间 + 电脑长时间学习 + 打印纸质 |
| 收费 | 初期全免费，不设付费墙（规模不足，先做留存） |
| 部署 | 初期云主机单实例 + 多账号；后期分发安装包 |
| 隐私表述 | **弱化**「零数据上云」，只强调功能价值，隐私仅在条款中声明 |

### 1.3 双路径设计（不做用户分层、不做功能限制）

| 路径 | 适用对象 | 走法 |
|---|---|---|
| 全流程路径 | 【全流程学习者】 | 目标 → 本周课规（承接每日任务） → 精读/训练 → 错题重练 → 周报 |
| 单点路径 | 【内容消费型用户】 | 只进「AI 讲解」或「定制练习」或「小测」或「文章预览」，不设目标也能用 |
| 共同点 | 两类共用 | 同一套功能、同一套数据；**差异只体现在 AI 生成内容**（按 `learner_identity` 注入提示词），不体现在可用功能上 |

## 1.5 竞品参考与设计理念

> 调研方式：公开产品页、官方帮助文档与第三方竞品分析（2026-11 检索）。以下只提炼「设计理念 + 可借鉴/不借鉴」，不复制其内容与素材。

### 1.5.1 竞品一览

| 产品 | 一句话设计理念 | 关键机制 | 与本产品的关系 | 借鉴 / 不借鉴 |
|---|---|---|---|---|
| 墨墨背单词 | 用记忆算法把重复降到最少 | MM 记忆算法、记忆持久度、每日复习量控制 | **直接竞品**（同人群、同备考场景） | 借鉴：复习调度、每日量上限；不借鉴：纯词表无深度讲解 |
| 不背单词 | 单词不用背，融入语境自然会 | 影视/新闻原声例句、词根词缀、搭配、艾宾浩斯 | **直接竞品**，与本产品「精读」最接近 | 借鉴：例句优先、讲词根与搭配；差异：本产品按身份生成 + 可导出 |
| 百词斩 | 用图像和场景降低背词的枯燥 | 图文联想、看图选义、打卡与 PK | 直接竞品（高中/四六级重叠） | 借鉴：低门槛入门、连续打卡；不借鉴：选择题易停留于「被动识别」 |
| 扇贝 | 用社群与打卡维持长期动机 | 社区、小组、打卡、多模块矩阵 | 相邻竞品 | 借鉴：进度可视化；不借鉴：模块铺得广、焦点分散 |
| 多邻国 | 把学习做成游戏，降低启动阻力 | 连胜、段位、XP、每日目标、推送 | 机制参照（非同一应试人群） | 借鉴：连胜与即时反馈；不借鉴：强游戏化稀释备考严肃性 |
| Anki | 主动回忆 + 自己造卡，算法透明 | 间隔重复、卡片自建、插件生态 | 硬核机制参照 | 借鉴：主动回忆优先于识别、复习量可控；不借鉴：上手成本高、无讲解 |
| Quizlet | 卡片 + 多种测试模式 + 共享卡组 | 多题型自测、UGC 卡组 | 机制参照 | 借鉴：多题型自测；不借鉴：UGC 质量不可控 |
| Vocabulary.com | 语境优先，在真实语料中理解词义 | 真实例句、自适应难度 | 理念同源（深度理解） | 借鉴：真实语料与自适应；不借鉴：无中文讲解、无备考计划 |
| LingQ | 可理解输入：在感兴趣的真实内容里习得 | 点词查义、生词追踪、内容库 | 与本产品「AI 阅读器」同源 | 借鉴：点词即查 + 生词自动进复习；本产品阶段 2 顺延 |
| 欧路词典 | 用户自主定义学习体系的工具 | 划词/取词、生词本、多端同步 | **工具型参照**，非竞品 | 借鉴：查得快、随处可查、生词本沉淀；不借鉴：纯工具无学习闭环 |
| WordUp | AI 个性化知识图谱 + 多题型训练 | AI 词表排序、多题型、间隔重复 | **最接近「AI 私教」的直接竞品** | 借鉴：按目标定制词表；差异：讲解更深、纸质导出、错因归因与周报 |

### 1.5.2 赛道位置

现有产品集中在三条轴上：**记忆效率**（墨墨、Anki）、**语境理解**（不背单词、Vocabulary.com、LingQ）、**动机留存**（多邻国、扇贝、百词斩）。

本产品选择第四象限：**讲解深度 × 学习闭环 × 纸质交付**，由 AI 承担「私教」角色。空白位有五个：

1. **深度讲解**：多数产品只给「释义 + 例句」，不给「为什么、怎么用、易混辨析、文化背景」；本产品已有六块结构化 + Markdown 精讲。
2. **闭环**：多数产品停在「背完 / 测完」，不解释错因、不安排再练；本产品补「归因 + 重练」。
3. **纸质**：几乎无人做系统化 Word 导出；本产品把它作为交付层而非附赠功能。
4. **按人适配**：竞品多按「词书」分层，本产品按 `learner_identity` 注入提示词，内容随人变。
5. **AI 定制练习**：竞品多为固定题库/固定词书；本产品可由用户指定主题、难度、错题或正在学的内容，现场生成练习（入口与依据已由 R3/R6 确认）。

**不构成竞争壁垒**（也不作为首发目标）：内容库规模、社区、强游戏化、发音评分。

### 1.5.3 竞品带来的风险与对策

| 风险 | 来源 | 对策（已纳入设计） |
|---|---|---|
| 深度讲解单条成本高、生成慢 | 不背单词/WordUp 的深度内容同样重 | AI 分层队列：共用内容复用秒回，定制才排队（§3.7） |
| 手机端弱导致流失 | 主流竞品均以手机为主入口 | 独立移动精简端（§3.11） |
| 无社群、无强游戏化，留存弱 | 多邻国/扇贝/百词斩均靠动机机制 | 任务卡 + 周报 + 现有点金圣殿奖励；**不做连续天数、排行、断签惩罚、推送**（R2） |
| 阅读型用户不满足 | LingQ/Vocabulary 以阅读为核心 | 文章预览与点词、高亮一并后置（D65），首发以 AI 讲解承接输入型需求 |
| 用户把「查词」当唯一需求 | 欧路词典类工具习惯 | **不把查词作为核心功能**；查词作为「AI 讲解」的附带能力，核心入口是 AI 讲解与定制练习 |

### 1.5.4 登录门槛的竞品做法（2026-11 检索）

| 模式 | 做法 | 优点 | 缺点 | 代表产品 |
|---|---|---|---|---|
| 静默游客号 | 匿名 ID 先存进度，注册时合并 | 零摩擦、留存高 | 合并复杂、易丢数据 | 不背单词（待核实） |
| 软拦截 | 可浏览试学，保存/打卡时才提示登录 | 先见价值、转化高 | 时点难定、需回填原操作 | 多邻国、Vocabulary.com |
| 内联弹层 | 点收藏/加词本弹半屏登录，成功后原地生效 | 不打断浏览 | 状态回填成本 | 扇贝、百词斩（推断） |
| 硬门槛 | 未登录只见登录页 | 实现最简单 | 首访流失最大 | 墨墨 |
| 只读预览 | 列表可见、受限按钮加锁 | 预期清晰 | 界面偏冷 | Quizlet |

**结论（#77）**：采用「**软拦截 + 内联弹层**」——页面可浏览，保存类动作弹半屏登录，成功后原地继续。理由：与 R28（游客不写学习记录）不冲突，且比硬门槛少流失、比静默游客号少合并逻辑。

## 1.6 两类客户需求分析

### 1.6.1 需求对比

| 维度 | 【全流程学习者】 | 【内容消费型用户】 |
|---|---|---|
| 典型画像 | 有考试/明确目标与期限，愿意长期投入 | 无目标，随手提问、看懂一段内容、练几道题 |
| 单次时长 | 20–60 分钟，可跨天连续 | 1–10 分钟碎片，随时中断 |
| 主设备 | 电脑为主 + 手机 + 打印 | 手机为主 |
| 成功标准 | 按计划完成、错题变少、周报看到进步 | 这一次查清楚了、能保存或带走 |
| 放弃点 | 不知道今天学什么、学了没反馈、错题反复错 | 强制注册/强制计划、等待太久、入口太深 |
| 需要 | 目标拆解、每日任务、学情诊断、错因解释、周报、打印 | **AI 讲解（把任意输入讲透）**、**私人定制练习题**、可保存/导出、不被打扰 |
| 不需要 | 花哨游戏、社区攀比 | 计划、周报、任务提醒 |
| 关键页面 | 首页本周课规、`plan`、`weekly-report`、`wrongbook` | `kp-entry` / `kp-detail`（AI 讲解）、`review`（定制练习）、`wordbook`（词表库）、`articles` |
| 关键接口 | 本周课规（复用现有）、`goals`、`weekly-reports`、`retry-items` | `explanations`（L1/L2）、`custom-exercises`、`export-word` |

### 1.6.2 设计冲突与裁决原则

| 冲突 | 裁决 |
|---|---|
| 即时 vs 深度 | 先用 L1 复用给「够用的结果」，深度定制在后台生成，不阻塞当前页 |
| 流程 vs 自由 | 流程全部可选：不强制设目标、不强制看周报，单点路径始终可达 |
| 手机 vs 电脑 | 手机只做 AI 讲解/复习/小测，复杂操作明确提示电脑端 |
| 严肃 vs 游戏化 | 默认不加强游戏化，仅保留轻量进度（**已裁决：不加连续天数/排行/推送，R2**） |
| 讲解成本 vs 覆盖 | 共用内容跨用户复用，只有定制内容消耗生成 |
| 内容广度 vs 深度 | 首发不铺内容，先把「一个词讲透 + 错因讲清 + 能打印」做稳 |

### 1.6.3 由此推导的五条设计原则

- **P1 即时优先**：任一入口一次点击内给出结果，或给出明确进度与预计等待。
- **P2 深度可选**：先给结论，再给「展开精讲」，不默认灌满整页。
- **P3 流程可选**：不设强制目标与强制引导，两类用户共用同一套功能。
- **P4 纸质交付**：所有学习产物（精讲、词表、小测）都可导出打印。
- **P5 无负担退出**：随时停、随时续，中断不惩罚（不做断签惩罚、不做扣分）。

### 3.2 AI 导航（新增）【两类共用】

**目标**：把「不知道从哪开始」的用户接进流程；权限放宽到导航、排计划、答疑。

**权限边界（硬性）**

| 能力 | 是否可自动执行 |
|---|---|
| 解释功能、跳转页面、推荐下一步 | 可以 |
| 生成学习计划（目标 + 每日任务建议） | **只生成「提案」**，用户点「确认生效」才写入；24 小时未确认自动过期 |
| 自动往复习队列/任务卡塞内容 | 不可以 |
| 改已有目标 / 改学情数据 | 不可以（只能建议，用户手动改） |
| **自动写开发者计划 / Bug 列表** | **可以**：只记录，不改用户数据、不承诺上线时间（R44） |
| 生成词表 / 生成练习（带参跳转） | **P1 可选项**：用户确认后执行；是否纳入 P1 由开发前工作量评估决定（#56） |

**用户流程**

```
用户提问 → AI 回复（文本 + 可选动作卡片 + 可选回执）
            ├─ 动作=页面跳转 → 前端直接跳转
            ├─ 动作=计划提案 → 展示「目标 + 每日任务」→ 用户确认/修改/放弃
            │                    ├─ 确认 → 选生效日（今天 / 明天）→ 写 user_goals
            │                    │      ├─ 今天 → 当日补齐剩余任务
            │                    │      └─ 明天 → 次日 00:05 按新目标生成
            │                    └─ 放弃 → 仅存档，不生效
            └─ 内容=做不到的需求 / Bug → AI 分类（R45）
                                 ├─ 高置信 + 在范围内 → 写 dev_backlog / dev_bugs → 回执编号
                                 ├─ 低置信或范围不明 → 写 triage → 回执「待确认」编号
                                 └─ 明确超出范围 → 写 rejected（不进计划列表）→ 回复「暂不在本应用范围」
```

**页面（#54）**：**全站抽屉**——每个页面顶栏固定「AI 导航」按钮，点击从右侧滑出对话抽屉；不新增独立页、不做浮球。桌面端抽屉宽约 380px，移动端占满屏。

**提案生效（#57）**：确认时让用户选「今天」或「明天」；今天当日补齐剩余任务，明天次日 00:05 按新目标生成。

**开场与快捷问题（#72/#74）**：打开抽屉即显示固定欢迎语 + **3 个固定快捷问题**（今天学什么 / 怎么用这个功能 / 帮我排个计划），第 4 项按当前页面生成情境问题（如详情页给「讲讲这个词」）；点击快捷问题直接发送。

**文案维护（#76）**：欢迎语、快捷问题、空态与导出中心说明均落在 `config/copy.json`，改文件即生效，无需改前端代码。

**接口**

| Method | Path | 说明 |
|---|---|---|
| POST | `/api/ai-nav/messages` | 发送一条消息，返回回复 + 可选动作 + 可选回执（`receipt`） |
| POST | `/api/ai-nav/proposals/:id/confirm` | 确认计划提案（`:id` 即 `ai_nav_messages.id`，不另建提案表） |
| POST | `/api/ai-nav/proposals/:id/discard` | 放弃提案 |
| GET | `/api/ai-nav/messages` | 当前用户历史（单会话，用于刷新恢复） |

**状态**

- 会话（#55）：每用户仅**一个会话**，消息保留 **7 天**，超期由后台每日清理；
- 消息：`ok` / `ai_failed`（AI 失败时返回预设文案 + 重试按钮）
- 提案：`proposed` → `confirmed` / `discarded` / `expired`
- 回执（`receipt`）：`none` / `backlog` / `bug` / `triage` / `rejected`；随消息返回，不单独存表；回执含编号，**不含上线时间**

**异常兜底**

- AI 不可用 → 返回固定引导文案（「先做今日任务卡」+ 三个入口），不阻塞页面；
- AI 返回的动作 JSON 解析失败 → 丢弃动作，仅展示文本；
- 提案确认时目标解析失败 → 走 §3.3 兜底模板；
- 分类失败或置信度不足 → 写入 `triage`（`confidence=0`），仍返回「已记录」编号；
- 入库失败 → 不阻断对话、不显示编号，仅后端记日志，避免出现「假回执」。

**人工修改渠道**：`config/ai_nav.json`（可改引导文案、可用动作类型白名单、提案有效期）；`config/dev_intake.json`（分类阈值、可识别 Bug 关键词、回执文案、去重相似度）。

### 3.3 目标设定（新增）【全流程学习者】

**目标**：用分步提问或自由文本说清「我想在多长时间内达成什么」，系统转成可执行目标。

**用户流程（#46–#49）**

```
首页轻提示 / plan 页进入
 → 内置分步提问（3 步：① 目标类型与用途 ② 期限 ③ 每天可用时长）
    ├─ 也可直接输入自由文本（例：30 天后雅思 6.5，每天能学 30 分钟）由 AI 解析
    └─ 解析失败 → 保留原文 + 给 3 个模板（① 每天 10 分钟轻学 ② 每周 20 个新词 ③ 考前 30 天冲刺）
 → 表单式确认页：目标类型 / 期限 / 每日时长 / 建议日均新词 / 绑定主词表 全部可改
 → 确认生效
```

**多目标（#47）**

- 目标进度按**累计完成**计算，不要求当日完成，未完成部分顺延（与任务卡补交一致）。

**到期处理（#48）**

- 到期时提示三选一：**续期 / 归档（删除） / 新建**；
- 不选择则保持 `active`，目标页与任务卡显示「目标已到期」；
- **归档即删除**：删除目标记录与绑定关系；已生成的任务卡与周报快照保留，不回溯删除。

**页面**：`frontend/pages/plan.html`（新增，目标 + 任务卡 + 周报入口）。

### 3.6 错题归因与重练（新增）【两类共用】

**目标**：错题不只给答案，要说清「错在哪」，并自动排进再练队列。

**判定顺序（代码优先，AI 补充）**

```
1. 规则判定（本地、零 AI）
   - 拼写：编辑距离 ≤2 且首字母相同
   - 词义：选项与 correct 属同一词不同义项
   - 搭配：命中固定搭配表但介词/形式不符
   - 语法：词形变化/时态类题型
2. 规则未命中 → AI 归因（单次、超时 15s）
3. AI 失败 → 降级：只显示标准答案 + 已有解析 + 「再练」按钮
```

**计费归属**：归因 AI 属**辅助 AI**（R29）——不扣金桂、不计 L2 的 15 次，仅按 tokens 计入每日 50 万上限。

**判定时机（#40）**：错题提交时**立即判定**并写入；规则结果先出，AI 补充异步返回、不阻塞答题；用户可**手动修改归因类型**（修改后 `attribution_source='user'`，不触发重新归因）。

**用户流程**

```
答错 → 立即展示「规则归因」（有则显示）
```

### 3.7 AI 稳定性与分层队列（P0，新增）【两类共用】

**目标**：AI 慢/挂时，页面永远有结果或明确的等待与重试入口。

**分层规则（核心决策）**

| 层 | 命中条件 | 响应方式 |
|---|---|---|
| L1 共用内容 | 词典词条（内置/EFLLex）；`knowledge_points` 中 `is_solidified=1`、`standard_content` 归一化后相同、且 `identity_snapshot` 相同的通用内容（不含备注/个人定制） | **同步秒回**，不建任务、不排队 |
| L2 定制生成 | 新词条、按身份/备注定制的精讲、周报 AI 润色、AI 归因 | **建任务排队**，返回 `job_id` + 队列位置 + 预计等待 |
| L3 兜底 | L2 失败 2 次或总超时 | 返回已完成部分 + 重试入口 |

**复用判定键**：`identity_snapshot` + `standard_content` 归一化（去首尾空格、转小写、合并连续空白）后比较；复用不校验 `remark`/`difficulty`，且**不返回原作者信息与个人备注**（R30）。

**任务状态机**

```
queued ──取到 worker──> running ──成功──> done
   ↑                       │
   │                       ├─可重试失败──> retrying ──> queued（指数退避 2s/4s/8s）
   │                       └─不可重试──> failed（前端给重试入口）
   └──服务重启且 running 超时（>180s）──> queued（断点续跑）
```

**多模型切换**：`config/ai.json` 增加 `providers` 数组（主/备），单次请求失败一次即切下一个；连续失败 3 次标记该模型 `degraded` 10 分钟，`/api/health` 暴露 `ai_degraded`。

**进度与预计等待**：`position` = 同 `lane` 下 `queued` 且创建时间早于本任务的数量；`eta_sec` = `position × avg_cost`（`avg_cost` 为最近 20 次同类型任务均值，冷启动取 30s）。

**接口**

| Method | Path | 说明 |
|---|---|---|
| GET | `/api/ai-tasks/:id` | 统一进度（含 `lane`/`status`/`position`/`eta_sec`/`done`/`failed`） |
| POST | `/api/ai-tasks/:id/retry` | 手动重试失败项 |
| GET | `/api/ai-tasks` | 当前用户任务列表 |

存量 `/api/kp/solidify/jobs*` 保留，内部改为复用本队列；前端优先调用新接口，旧接口保留兼容。

**异常兜底**

- 队列满（>1024）→ 返回 429 + 建议稍后再试，不静默丢任务；
- 单任务超 180s → 标记 `failed`，保留已完成子项；
- 进程重启 → 启动时把 `running` 且超时的任务重置为 `queued`，已 `done` 子项跳过；
- 全部模型不可用 → 页面顶部显示 AI 降级徽章，精读详情仍可看已有内容。

**人工修改渠道**：`config/ai.json`（并发数、超时、模型列表、退避参数、`avg_cost` 冷启动值）。

### 3.13 开发者看板（P1，新增）【开发者】

**目标**：AI 导航自动沉淀「用户做不到的需求」与「Bug」，开发者在一个页面看到待办，不必翻聊天记录（R44–R47）。

**页面**：`frontend/pages/dev.html`，仅 `role='admin'` 可访问；非管理员 403。三个页签：

| 页签 | 内容 | 默认排序 |
|---|---|---|
| 开发计划 | `dev_backlog` 中 `status != rejected` | `occurrences` 降序 → `last_seen_at` 降序 |
| Bug 列表 | `dev_bugs` 中 `status != duplicate` | `severity` → `occurrences` 降序 |
| 待分拣 | 两张表中 `status='triage'` | `last_seen_at` 降序 |

**判定规则（R45/R47）**

| 用户输入性质 | 判定 | 落表与初始状态 | 回执 |
|---|---|---|---|
| 现有功能能回答 | `answerable` | 不记录 | 无 |
| 做不到，但与英语学习/讲解/练习/词表/导出/计划相关 | `feature_request` | `dev_backlog`，`status='new'`、`scope_fit='in_scope'` | `#B{id}` |
| 应用异常（报错、白屏、按钮无反应、数据不显示、导出失败、讲解内容错误） | `bug` | `dev_bugs`，`status='new'` | `#G{id}` |
| 与产品定位无关（日语、游戏、社交等） | `out_of_scope` | `dev_backlog`，`status='rejected'`、`scope_fit='out_of_scope'` | 无编号，回复「暂不在本应用范围」 |
| 置信度低于阈值或范围不明 | `triage` | 对应表 `status='triage'` | `#T{id}` |

- **Bug 与学习错误区分**：用户答错、不会做、要求换题**不算 Bug**；只有页面/接口/数据/导出/内容错误才算 Bug，`category` 取 `ui / api / data / export / content`。
- **去重**：`dedupe_key = sha1(kind + '|' + 归一化标题)`，两表各自 UNIQUE；重复只 `occurrences + 1`、更新 `last_seen_at`、保留原编号，不新增行。
- **回执**：只显示编号与「已记录」，**不承诺上线时间、不给优先级**；低置信回执写「已记录，待开发者确认」。

**字段**

| 表 | 字段 |
|---|---|
| `dev_backlog` | `id`、`source_message_id`、`user_id`、`title`、`detail`（触发消息片段 ≤500 字）、`category`（feature / enhancement）、`scope_fit`（in_scope / out_of_scope）、`confidence` DECIMAL(3,2)、`dedupe_key` UNIQUE、`occurrences`、`status`（new / triage / accepted / planned / shipped / rejected）、`priority`（P0/P1/P2，可空）、`admin_note`、`created_at`、`updated_at`、`last_seen_at` |
| `dev_bugs` | `id`、`source_message_id`、`user_id`、`title`、`detail`（触发消息片段 ≤500 字）、`category`（ui / api / data / export / content）、`page_path`、`error_code`（可空）、`severity`（blocker / major / minor）、`confidence`、`dedupe_key` UNIQUE、`occurrences`、`status`（new / triage / confirmed / fixing / fixed / closed / duplicate）、`duplicate_of`（自关联 id，可空）、`admin_note`、`created_at`、`updated_at`、`last_seen_at` |

**接口（仅 admin）**

| Method | Path | 说明 |
|---|---|---|
| GET | `/api/dev/backlog` | 列表，支持 `status` / `scope_fit` / `priority` 过滤 |
| PUT | `/api/dev/backlog/:id` | 改 `status` / `priority` / `admin_note` |
| GET | `/api/dev/bugs` | 列表，支持 `status` / `severity` / `category` 过滤 |
| PUT | `/api/dev/bugs/:id` | 改 `status` / `severity` / `admin_note` / `duplicate_of` |
| GET | `/api/dev/summary` | 各状态计数，用于页签徽标 |

**异常兜底**

- 列表为空 → 空状态「暂无记录」，不报错；
- 非 admin 访问页面或接口 → 403，不泄露条目数量；
- 更新失败 → 保留原状态并提示重试；
- 分类入库失败 → 对话不阻断、不显示编号（见 §3.2）。

**隐私边界**：只存触发消息片段（≤500 字）、页面路径、错误码与 `user_id`；**不存完整对话**，不在前端任何用户页面暴露这两张表。

**人工修改渠道**：`config/dev_intake.json`（置信度阈值、Bug 关键词、回执文案模板、去重相似度）；状态枚举固定在代码中，改动需走版本升级。

## 8. 验收标准

> **批次口径**：P0 验收以 AI 队列、讲解、练习、词表、导出、匿名会话、首页入口为主；P1 补齐目标、任务卡、错题、周报、导航、文章、移动端。全量回归在发布前统一执行。

### 8.1 首页与导航

1. 首页加载显示：今日到期复习数、当日小测状态、金桂余额/当前称谓（任一统计失败仅该卡显示「—」）；新词进度为 P1 字段。
2. 首页保留全部原有入口，**不新增一级入口**；AI 讲解在 `kp-entry`/`kp-detail` 可用，定制练习在 `review` 可用，词表库在 `wordbook` 可用；首页新增「导出中心」小卡；（P1）在本周课规卡内增加任务与三能力链接，不新增任务卡。
3. （P1）AI 导航提出的计划**必须**经用户确认后才写入 `user_goals`；未确认 24h 后自动过期。

### 8.2 目标与本周课规（P1，承接原任务卡）

4. 自由文本目标可解析为结构化目标；解析失败时返回 3 个可编辑模板。
5. 同一用户仅 1 个 `active` 目标；无目标时全站功能仍可用。
6. 任务卡按规则生成，**不调用 AI**；同日重复请求幂等（不重复生成）。
7. 任务卡数量受配置约束（复习上限 60、默认新词 10）。

### 8.3 周报与错题（P1）

8. 周报在无 AI 情况下可生成完整统计与规则建议；AI 润色失败仍为 `ready` 展示（`ai_summary` 为空）。
9. 答错后规则归因立即显示；规则未命中时 AI 补充；AI 失败降级为「答案 + 解析 + 再练」。
10. 错题自动进入重练队列，按遗忘曲线排期；同一知识点不产生重复待练行；可手动提前。

### 8.4 AI 队列（P0）

11. 已固化词条被任意用户请求时同步秒回，不创建任务。
12. 定制生成返回任务 ID、队列位置、预计等待；轮询可看到进度增长。
13. 失败**自动重试 1 次**；仍失败则切换备用模型再试 1 次（#92）；耗尽后前端给明确重试入口。
14. 服务重启后，超时的 `running` 任务自动回到 `queued`，已完成子项不重跑。
15. 主模型不可用时自动切换备用模型；`/api/health` 暴露降级状态。

### 8.5 内容与端

16. （后置，不纳入 P1 验收）文章预览版可展示列表、难度报告、分句；不出现点词/高亮/TTS/对照入口。
17. （后置，不纳入 P1 验收）个人文章仅本人可改删；公共文章仅管理员可改删；越权返回 403。
18. （P1）移动端仅提供 AI 讲解、复习、小测；导出与阅读提示「请在电脑端使用」。
19. 存量模块（小测、单词本、点金圣殿、播放复习）功能与入口不变。

### 8.6 工程

20. 新增接口符合「名词复数 + kebab-case」，参数路由注册顺序正确。
21. 新增表满足 InnoDB / utf8mb4 / 无外键 / `user_id` 归属；删除级联由 Service 实现。
22. 全量回归：现有套件全部通过 + 新增 8 套件全部通过；AI 相关失败需重跑区分网络抖动。

### 8.7 AI 讲解与定制练习（P0）

23. 输入任意英文单词/短语/句子/段落，可得到结构化讲解；单词级输入在 L1 命中时秒回。
24. 未命中时返回排队任务 ID、队列位置与预计等待，完成后讲解自动呈现（刷新不丢进度）。
25. 讲解结果区可「加入单词本」「导出 Word」「生成针对练习」；非英文与超长输入被明确拦截。
26. 定制练习支持主题/自定词表/错题/在学词四种依据；主题可指到「学段 + 教材 + 单元」，题量上限 20；客观题本地秒批，主观题 AI 批改，批改失败显示参考答案而非错误分数。
27. 定制练习**不固化、不入库为复习题**；同用户 24h 内相同参数直接复用，不重复生成。
28. 激励复用点金圣殿：金桂、朱砂印、称谓照常结算；**无新增排行榜、无断签惩罚、无推送**。
29. 导出支持两种模板：A4 精讲讲义、定制练习卷（答案另页）；导出前显示估算页数；不提供单词卡与周报打印。
30. 内置人教高中 7 册可直接按「教材 → 册 → 单元」组题；个人词表同样可标注教材、册、单元；范围包可跨单元合并；内置未收录的单元按 P0 两项引导（粘贴/上传、AI 现场生成）。
31. （P1）用户可自建词表，并发布为社区词表；他人可浏览并用于组题。
32. 文章讲解的输出形态不在本版验收范围，后续专题确认后再补。
