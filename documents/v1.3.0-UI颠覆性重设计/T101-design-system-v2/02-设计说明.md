## 二点五、顶部导航与激励指标入口

### 2.5.1 参考设计（WordNest 风格）

顶部栏右侧常驻**点金圣殿激励指标**，全部作为**圣殿宝库页面（`/pages/treasury.html`；对应数据 API 为 `/api/treasury`）入口**：

> 📌 **已改为抽屉（T103-v1.2，2026-10-02）**：本节以下「跳转 `/pages/treasury.html`」的记载均已作废——`frontend/pages/treasury.html` 已删除，宝库改为由 `nav.js` 全站注入的**抽屉浮层**（`#treasury-drawer`），激励区三项点击为**打开抽屉、不跳转**；抽屉内只保留「金桂余额 + 三统计 + 圣殿账册」。现行方案见 [T103-首页控制台/02-宝库页-简要设计.md](../T103-首页控制台/02-宝库页-简要设计.md) 第八节。

```
学习圣殿  学习▼  练习▼  文章阅读  学情中心 │ 🪙86 秀才 Lv.2  [头像]  ☀/☾
```

> 左侧不再单列「宝库」文字链接——右侧激励指标（🪙/称谓/头像）即为宝库入口，避免重复并缓解拥挤。
> 连续天数已去除，不作为导航区展示项（保留在圣殿宝库页内详细展示）。

| 指标 | 对应数据源 | 视觉呈现 | 点击行为 |
|------|-----------|---------|---------|
| 🪙 金桂余额 | `user_coin.balance`（真实列，经 `GET /api/treasury`） | 金色金币图标 + 数字，如「🪙 86」 | 跳转 `/pages/treasury.html`，显示账册 |
| 称谓等级 | `user_title.title_code`（真实列，经 `GET /api/treasury`） | 小字标签，如「秀才 Lv.2」，灰色 | 跳转 `/pages/treasury.html`，高亮「称谓段位」锚点 |
| 头像 | 当前用户（`/api/auth/me`） | 圆形头像占位，首字母缩写或真实图片 | 展开用户菜单（含退出登录） |

> **设计原则**：指标本身轻量、不喧宾夺主；视觉锚点统一指向 `treasury.html`，避免首页冗余信息。

### 2.5.2 连续天数的数据来源（事实核对，仅供宝库页内部展示）

> ⚠️ `user_coin` 表**没有** `streak_days` 列（其真实列为 `balance / total_earned / total_spent`）。连续天数**不新增存储列**，而由现有两张活动记录表**派生**：

| 活动来源 | 表 | 日期字段 | 计入条件 |
|----------|-----|---------|---------|
| 每日复习 | `review_logs` | `review_time` | 该用户该日存在复习记录 |
| 每日小测 | `daily_quiz` | `quiz_date` | 该日小测 `status='done'` |

**计算口径**：两表按用户取 `DISTINCT 日期` 合并，从今天（或最近一个活动日）向前数连续无间断的天数，即连续天数；同一结果同时驱动灯笼墙（取最近 7 个活动日逐日点亮）。

**返回方式**：在现有 `GET /api/treasury` 响应中**新增两个字段**（加法式、向后兼容，不新增路由）：
- `streak_days`（整数）→ 宝库页内部展示
- `active_days_7`（长度 7 的日期/布尔数组）→ 灯笼墙

> 该派生查询属后端只读新增（MINOR，响应加字段）；`user_coin_txn` 自 2026-09-28 起的 `review_done/quiz_done` 流水亦可作为旁证，但历史活动以 `review_logs` / `daily_quiz` 为准。

| 卷草纹 S 形曲线 / 巴洛克边角 | `.divider-ornament`、`.card--gold` 角标 | 几何描边，无 `<text>` |
| 印章图形 | `.seal-stamp`（`--bronze/silver/gold/gilt` 四色阶） | 徽章配色按令牌 |
| 希腊柱式几何分隔 | `.lc-col`、`.wing-card` 竖线 | 1px 线条 |

> 结论：**在线素材只承担「氛围图片」这 1 类角色**，其余装饰保持零依赖，天然满足「装饰不阻塞功能」与离线降级要求。

### 8.4 无网降级方案

1. **图片层之下必有同色系渐变打底**：CSS 先写 `background:linear-gradient(...)`，再用 `background-image` 叠加图片；图片请求失败时自动露出渐变，**不会出现白块或破图**。
2. **暗色下降低不透明度**：暗色主题将图片 `opacity` 再降一档（见 8.1），确保正文对比度不受影响。
3. **完全断网**：`background-image` 静默失败，页面退化为纯 CSS 圣殿风格（与当前线上现状一致），功能零影响。
