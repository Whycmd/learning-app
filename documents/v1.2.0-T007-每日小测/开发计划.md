# v1.2.0-T007 · 每日小测 开发计划

> 文档日期：2026-09-26
> 文档版本：v1.0
> 范围说明：AI 生成的每日 5 题客观小测，难度略低于正式练习；每日可测多次；词币奖励仅预留不实现；小测联动熟练度评定。

---

## 一、任务目标

1. **核心交付**：新增「每日小测」页面，每次由 AI 实时生成 5 道**全客观题**（四选一 / 答案唯一的简单填空），代码本地秒批，无需等待 AI 批改。
2. **题目构成（固定 3+1+1 结构）**：
   - 第 1–3 题【已学巩固】：考查当前用户**已固化知识点**，每题带 `knowledge_id`；
   - 第 4 题【熟词生义】：AI 自选低级别常见词，考查其不常见义项（如 run = 经营），题面带 `word / meaning / example`；
   - 第 5 题【新知拓展】：AI 自选贴近用户当前水平的陌生词考查基本含义，同样带 `word / meaning / example`。
3. **考后固化**：第 4、5 题出成绩后提供「固化该知识点」入口；固化对象是**知识点**（单词 + 该义项备注），不是裸单词；走现有 AI 固化管道。
4. **学情联动**：第 1–3 题的作答结果同步 `user_learning`（答错熟练度 −1、错误次数 +1；答对复习次数 +1），即参与熟练度评定；**不**重算遗忘曲线下次复习时间。
5. **多次测试**：每天可发起多套小测，`attempt_no` 记录当日第几测；词币奖励预留（提交响应含 `coins_earned: 0` 占位字段与递减规则说明），不写入 `user_coin`。
6. **测试**：新增 `stage11_daily_quiz.test.js`。

## 三、数据库变更（新建 `scripts/sql/04_daily_quiz.sql`）

```sql
SET NAMES utf8mb4;

-- 每日小测记录表：每次测验一条（每天可多次）
CREATE TABLE IF NOT EXISTS `daily_quiz` (
  `id`            INT NOT NULL AUTO_INCREMENT,
  `user_id`       INT NOT NULL,
  `attempt_no`    INT NOT NULL DEFAULT 1 COMMENT '当日第几测（未来词币递减依据）',
  `quiz_date`     DATE NOT NULL COMMENT '小测日期',
  `questions`     MEDIUMTEXT NOT NULL COMMENT '题目快照JSON（含答案，服务端留存）',
  `answers`       TEXT DEFAULT NULL COMMENT '用户作答JSON',
  `score`         TINYINT DEFAULT NULL COMMENT '得分0-100',
  `correct_count` TINYINT NOT NULL DEFAULT 0,
  `status`        VARCHAR(10) NOT NULL DEFAULT 'ongoing' COMMENT 'ongoing/done',
  `start_time`    DATETIME NOT NULL DEFAULT CURRENT_TIMESTAMP,
  `finish_time`   DATETIME DEFAULT NULL,
  PRIMARY KEY (`id`),
  KEY `idx_user_date` (`user_id`, `quiz_date`)
) ENGINE=InnoDB DEFAULT CHARSET=utf8mb4 COLLATE=utf8mb4_unicode_ci COMMENT='每日小测记录';

-- 词币账户表（v1.2.0-T007 仅建表预留，本期无任何读写逻辑）
CREATE TABLE IF NOT EXISTS `user_coin` (
  `id`           INT NOT NULL AUTO_INCREMENT,
  `user_id`      INT NOT NULL,
  `balance`      INT NOT NULL DEFAULT 0 COMMENT '当前余额',
  `total_earned` INT NOT NULL DEFAULT 0 COMMENT '累计获得',
  `updated_at`   DATETIME NOT NULL DEFAULT CURRENT_TIMESTAMP ON UPDATE CURRENT_TIMESTAMP,
  PRIMARY KEY (`id`),
  UNIQUE KEY `uk_user` (`user_id`)
) ENGINE=InnoDB DEFAULT CHARSET=utf8mb4 COLLATE=utf8mb4_unicode_ci COMMENT='用户词币账户（预留）';
```

**注销账号级联补充**（`auth_service.h` deregister 事务内追加）：
```sql
DELETE FROM daily_quiz WHERE user_id=<uid>;
DELETE FROM user_coin  WHERE user_id=<uid>;
```

## 四、后端 API（共 4 个新端点）

### 4.1 发起/生成小测

`POST /api/quiz/daily`，无请求体参数。

处理流程：
1. `uid = RequestContext::currentUserId()`；
2. `attempt_no = 当日该用户已有记录数 + 1`；`quiz_date = CURDATE()`；
3. 抽取已固化知识点池：
   ```sql
   SELECT id, standard_content, difficulty, master_require
     FROM knowledge_points
    WHERE user_id=<uid> AND is_solidified=1
    ORDER BY RAND() LIMIT 6
   ```
   复用 `KnowledgeService::detail()` 加载精简详情供 AI 出题；**池为空 → 返回 400**：`请先录入并固化至少 1 个知识点`；
4. 计算用户已固化词平均难度，作为第 5 题选词水平参考；
5. AI 提示词（`temperature=0.6`，`max_tokens=1600`，强制 JSON 返回）：

```
请生成一份5题英语每日小测。全部为客观题（四选一选择题 cloze_choice，或答案唯一的单词填空题 word_form_fill）。
整体难度略低于正式练习：句子简短、无生僻障碍词、填空题答案只含一个基础单词。
题目构成（严格按顺序与数量）：
- 第1-3题 category="solidified"：基于给定知识点列表出3题，knowledge_id 必须取自列表真实ID；
- 第4题 category="familiar_meaning"（熟词生义）：自选一个低级别常见词考查其不常见义项；
- 第5题 category="new_kp"（新知拓展）：自选一个难度贴近学习者平均水平(参考给定难度数值)的陌生词考查基本含义；
第4、5题必须额外提供 word（单词）、meaning（中文释义）、example（英文例句）字段。
严格只返回JSON：
{"questions":[{"no":1,"category":"solidified","type":"cloze_choice",
  "question":"题干","options":["A项","B项","C项","D项"],"answer":"B","knowledge_id":12},
 {"no":4,"category":"familiar_meaning","type":"cloze_choice",
  "word":"run","meaning":"经营；管理","example":"He runs a company.",
  "question":"...","options":[...],"answer":"C"}]}
```

6. 解析并校验：必须 5 题、`category/type/question/answer` 齐全、choice 含 4 选项；校验失败返回 500 并提示可重试；
7. **写 `daily_quiz` 记录**（status=ongoing，完整题目 JSON 含答案入库）；
8. 响应（题目列表**剥离 answer 字段**，提交批改后才回传答案）：

```json
{
  "quiz_id": 12,
  "attempt_no": 1,
  "quiz_date": "2026-09-26",
  "questions": [
    {"no":1,"category":"solidified","type":"cloze_choice","question":"...","options":[...],"knowledge_id":12},
    {"no":4,"category":"familiar_meaning","type":"cloze_choice","word":"run","meaning":"经营；管理","example":"...","question":"...","options":[...]}
  ]
}
```

### 4.2 提交批改

`POST /api/quiz/daily/submit`

```json
{ "quiz_id": 12, "answers": [ {"no":1,"user_answer":"B"}, {"no":2,"user_answer":"went"} ] }
```

处理流程：
1. 载入记录并校验归属（非本人 → 404）；状态必须为 ongoing，已完成 → 返回已有结果；
2. 本地批改（与 `QuestionService` 同规则）：
   - `cloze_choice`：trim 后大写比较选项字母；
   - `word_form_fill`：trim 后小写比较答案词；
3. 第 1–3 题（category=solidified 且 knowledge_id>0）逐题调用 `LearningService::onAnswerResult(kid, correct)`：
   - 答错：熟练度 −1（最低 0）、错误次数 +1；答对：熟练度不变；任答一题复习次数 +1、更新 last_review_time；
4. `score = round(100 × 答对数 / 5)`，更新记录：status=done、score、correct_count、answers JSON、finish_time=NOW()；
5. 第 4、5 题附带固化候选：
   ```json
   {"no":4,"category":"familiar_meaning","word":"run","meaning":"...","example":"...",
    "already_solidified": false}
   ```
   `already_solidified` 由 `knowledge_points` 中该用户是否已有同词（standard_content）已固化记录判定；
6. 响应：

```json
{
  "quiz_id": 12, "score": 80, "correct_count": 4,
  "results": [
    {"no":1,"correct":true,"correct_answer":"B","analysis":"回答正确。"},
    {"no":2,"correct":false,"correct_answer":"went","analysis":"回答错误，正确答案为 went。"}
  ],
  "solidify_candidates": [ {"no":4,...}, {"no":5,...} ],
  "coins_earned": 0,
  "coins_note": "词币系统即将上线；同日多次测试奖励将逐次递减"
}
```

### 4.3 固化熟词生义/新知

`POST /api/quiz/solidify-item`

```json
{ "quiz_id": 12, "no": 4 }
```

处理流程：
1. 载入测验记录（校验归属），定位对应题目；category 必须为 `familiar_meaning / new_kp`，否则 400；
2. 查重：该用户已存在同 standard_content 且已固化的知识点 → 直接返回 `{ok:true, duplicated:true, knowledge_id}`；
3. 新建知识点并走现有单条固化管道（一次 AI 六板块拓展）：
   - `user_input_content = word`；
   - `remark = 【每日小测·熟词生义】meaning` 或 `【每日小测·新知】meaning`
     ——保证固化的是「单词+目标义项」这个知识点，且 AI 拓展聚焦备注义项；
4. 响应：`{ "ok": true, "knowledge_id": 78, "word": "run" }`，前端可跳转 `kp-detail.html?id=78`。

### 4.4 历史记录

`GET /api/quiz/daily/history`

```sql
SELECT id, attempt_no,
       DATE_FORMAT(quiz_date,'%Y-%m-%d') AS quiz_date,
       score, correct_count, status,
       DATE_FORMAT(start_time,'%Y-%m-%d %H:%i') AS start_time,
       DATE_FORMAT(finish_time,'%Y-%m-%d %H:%i') AS finish_time
  FROM daily_quiz
 WHERE user_id=<uid>
 ORDER BY id DESC LIMIT 50
```

响应：`{ "data": [...], "today_count": N, "today_finished": M }`。

## 八、验收标准

1. 无已固化词时 `POST /api/quiz/daily` 返回 400 引导固化；有固化词时返回恰好 5 题、结构合规且不含答案；
2. 5 题为 3 solidified（带真实 knowledge_id）+ 1 familiar_meaning + 1 new_kp；后两者含 word/meaning/example；
3. 提交后秒级返回逐题批改与总分；选择/填空批改规则与正式练习一致；
4. 第 1–3 题答错使对应知识点熟练度 −1、错误次数 +1；答对复习次数 +1；`next_review_time` 不被改动；
5. 第 4、5 题可发起固化：生成带义项备注的知识点并完成 AI 拓展；重复固化返回已有知识点；
6. 同日再次开测 attempt_no 递增；历史接口返回全部测验记录及今日计数；
7. 响应含 `coins_earned: 0` 与递减说明，user_coin 表无任何读写；
8. 全量 12 套件回归通过；多用户隔离与注销级联正常。

## 九、风险与注意事项

- **AI 出卷稳定性**：AI 偶发不按 3+1+1 结构或返回非法 JSON；服务端做结构校验，失败不落库、提示重试，不产生脏记录；
- **填空题答案歧义**：提示词强制「答案唯一、单个基础单词」，并以 3 题选择题为主体，降低误判；
- **AI 耗时**：仅生成时一次 AI 调用（约 5–20s），前端按钮禁用并提示等待；批改零 AI 调用；
- **固化跨用户缓存**：固化备注义项时若命中他人同 standard_content 缓存，可能复制到泛化内容；属边缘场景，如出现再在固化查重中纳入备注维度；
- **网络依赖**：与现有固化/出题一致，AI 不可用时开测与考后固化不可用，页面明确提示。
