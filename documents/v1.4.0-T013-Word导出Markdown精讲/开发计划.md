## 一、目标

让 Word 导出包含 T010 新增的 `kp_extras(extra_type='markdown_content')` 精讲内容，保留旧格式导出逻辑，并支持 Markdown 中的 LaTeX 公式。

## 三、任务分解

- **T1 依赖**：`docx` 升级至 9.14.0，新增 `markdown-docx@1.7.1`，确认 `npm ls docx` 无重复副本。
- **T2 适配层**：新增 `scripts/md_to_docx.js`：
  - `renderMarkdownBlocks(md)`：去掉重复的 `# 单词精讲` 标题，调用 `MarkdownDocx.toSection()`；
  - `mergeMarkdownStyles(converters)`：合并 `paragraphStyles`、`characterStyles`、`numbering`，供多词文档共用；
  - `normalizeLatex(md)`：`\[...\]` → `$$...$$`，`\(...\)` → `$...$`；
  - 固定 `ignoreImage/ignoreHtml/ignoreFootnote`，公式使用 KaTeX（`throwOnError:false`、`libreOfficeCompat:true`）。
- **T3 生成器接入**：`gen_word_kp.js` 按词判断：
  - 有 `markdown_content`：标题行后只渲染 Markdown 精讲；
  - 无：走原有音标/词根/搭配/同义/补充结构；
  - 页眉、分页、末尾声明、单个/批量文件名不变。
- **T4 测试**：在 stage2 增加合成词条（含标题、粗体、列表、行内/块级公式），断言导出 XML 与批量导出。

## 四、验收标准

## 五、风险与应对

| 风险 | 应对 |
|---|---|
| docx 8→9 影响其他导出 | 先跑 stage1/2/7 导出用例；失败则回退版本或改用 markdown-docx 兼容范围 |
| 两个 docx 副本导致内容丢失 | 锁定同版本 9.14.0，`npm ls docx` 校验 |
| Markdown 样式未注册导致标题退化 | 合并转换器 `paragraphStyles/characterStyles/numbering` 注入 `Document` |
| KaTeX 遇到坏公式抛错 | `throwOnError:false`，并测试不规范分隔符 |
| 多词编号冲突 | 编号模板在各转换器一致，统一取第一份 `numbering` |
