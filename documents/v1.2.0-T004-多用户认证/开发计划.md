## 二、核心架构设计

### 2.1 请求身份上下文（解决 Service 全局单例问题）

**现状**：所有 Service 在 `main()` 中构造一次，`LearningService.userId_` 固定为 1；各 Service SQL 中硬编码 `user_id=1`。

**方案**：请求级 thread_local 身份上下文

```
浏览器请求（带 Cookie）
   ↓
HttpServer 工作线程（thread-per-connection）
   ↓
新增 beforeDispatch 前置回调（http_server.h 一处增强）
   ↓
解析 Cookie eng_session → 查 user_sessions → 设置 thread_local 当前 userId
   ↓
handler → Service（SQL 中 WHERE user_id=<上下文 userId>，未登录=1）
```

- 在 [http_server.h](file:///Users/junwang/Desktop/王浩源/英语/英语学习应用/backend/include/http_server.h) 增加一个 `beforeDispatch_` 回调槽，在路由 handler 调用前（当前第 209 行附近）执行；
- main.cpp 新增 `thread_local int t_currentUserId = 1;` + `currentUserId()` 访问函数；
- 全部硬编码 `user_id=1` 改为 `user_id=<currentUserId()>`（grep 已定位 15 处）；
- `LearningService.userId_` 成员废弃，改为读取上下文（构造签名不变，避免连锁改动）。

### 2.2 固化内容跨用户共享（不重复调 AI）

**关键语义调整**：现有 solidifyOne 发现他人类似词条时会 **DELETE 当前知识点再合并**。多用户后不能删除（各用户学情挂各自 knowledge_id），改为**保留自己的知识点 ID，复制对方固化内容**：

```
用户 B 录入 "apple"（B 的 knowledge_points 新记录，未固化）
   ↓ B 点击固化
全局查重（不限 user_id）：是否存在 standard_content='apple' 且 is_solidified=1 的记录？
   ├─ 命中（A 固化过）→ 本地复制，不调 AI：
   │    · UPDATE B 的知识点：standard_content/difficulty/master_require/is_solidified=1/solidify_time
   │    · 复制全部子表（definitions/collocations/synonyms/antonyms/extras）到 B 的 knowledge_id
   └─ 未命中 → 走原 AI 固化流程
```

- 复制在一个事务内完成；
- 该路径也写 `ai_tasks`，payload 标记 `source=cross-user-cache`，status=done；
- 学情仍按用户独立：`user_learning` 的 (user_id, knowledge_id) 链路完全不变。

### 2.3 密码哈希与随机数（零三方依赖）

| 用途 | 实现 |
|------|------|
| 密码哈希 | macOS 系统自带 CommonCrypto：`#include <CommonCrypto/CommonCrypto.h>`，`CC_SHA256`；算法 `SHA256(salt_hex + password)`，存 64 位 hex |
| Salt | 16 字节随机数，存 32 位 hex |
| Session token | 32 字节随机数，64 位 hex |
| 随机源 | 读取 `/dev/urandom`（系统设备，非三方依赖） |

### 2.4 会话管理

- 登录成功：生成 token，写入 `user_sessions`，有效期 **30 天**；
- 响应头：`Set-Cookie: eng_session=<token>; Path=/; HttpOnly; Max-Age=2592000`（本地 HTTP，不加 Secure）；
- 登出：删除 session 记录 + Cookie 置过期；
- 会话过期/无效：静默降级为游客（user_id=1），不报错。

## 三、数据库变更

**新增文件**：`scripts/sql/03_auth.sql`

```sql
-- 用户表
CREATE TABLE `users` (
  `id`           INT NOT NULL AUTO_INCREMENT PRIMARY KEY,
  `username`     VARCHAR(50) NOT NULL COMMENT '登录用户名',
  `password_hash` CHAR(64) NOT NULL COMMENT 'SHA256(salt+password) hex',
  `salt`         CHAR(32) NOT NULL COMMENT '随机盐 hex',
  `display_name` VARCHAR(50) DEFAULT NULL COMMENT '显示名',
  `created_at`   DATETIME NOT NULL DEFAULT CURRENT_TIMESTAMP,
  `last_login_at` DATETIME DEFAULT NULL,
  UNIQUE KEY `uk_username` (`username`)
) ENGINE=InnoDB DEFAULT CHARSET=utf8mb4 COLLATE=utf8mb4_unicode_ci COMMENT='注册用户表';

-- 注册用户 ID 从 2 开始：id=1 永久保留给"默认本地用户（游客）"，users 表不插入占位行
ALTER TABLE `users` AUTO_INCREMENT = 2;

-- 会话表
CREATE TABLE `user_sessions` (
  `token`      CHAR(64) NOT NULL PRIMARY KEY COMMENT '会话令牌 hex',
  `user_id`    INT NOT NULL,
  `expires_at` DATETIME NOT NULL,
  `created_at` DATETIME NOT NULL DEFAULT CURRENT_TIMESTAMP,
  KEY `idx_user_id` (`user_id`),
  KEY `idx_expires_at` (`expires_at`)
) ENGINE=InnoDB DEFAULT CHARSET=utf8mb4 COLLATE=utf8mb4_unicode_ci COMMENT='登录会话表';
```

变更性质：**加表（MINOR，兼容变更）**；现有表零改动（user_id 字段早已预留）。

## 四、API 设计

### 认证接口（新增 4 个）

| Method | Path | 请求体 | 响应 / 说明 |
|--------|------|--------|-------------|
| POST | `/api/auth/register` | `{username, password, display_name?}` | `{ok:true, user_id}`；用户名 3–20 字符、密码 ≥6 字符；重名 → 409 |
| POST | `/api/auth/login` | `{username, password}` | `{ok:true, user:{id,username,display_name}}` + Set-Cookie；失败 → 401 |
| POST | `/api/auth/logout` | – | `{ok:true}`；清除会话与 Cookie |
| GET | `/api/auth/me` | – | `{user_id:1, guest:true}` 或 `{user_id, username, display_name, guest:false}` |

### 既有接口行为

- 路径、请求/响应结构**全部不变**；
- 仅数据可见范围随身份变化：游客看到 user_id=1 数据；登录用户看到自己的数据。

1. 游客可正常使用全部既有功能，**现有 9 个套件无 Cookie 全部继续通过**；
2. 注册：成功创建；用户名重名 409；用户名/密码长度校验生效；

## 九、风险与对策

| 风险 | 对策 |
|------|------|
| thread_local 上下文遗漏设置点导致越权看到他人数据 | 注入点唯一（beforeDispatch），默认值=1；隔离场景在 stage9 重点覆盖 |
| CommonCrypto 链接问题 | macOS 上属 libSystem 系统库，通常零配置；编译验证，失败则降级手写 SHA-256 |
| 跨用户复制后源头知识点被删，产生孤儿数据 | 复制只在固化时发生；T009 一致性校验脚本会扫描；删除操作本就受 Service 层约束 |
| 忘记密码无法找回（本地软件） | 提供人工渠道：可直接操作 users 表重置；文档中说明 SQL 方法 |
