## 云主机（容器化）部署

> 适用：公网评审/演示，纯 IP + HTTP，使用 `docker-compose.prod.yml`。
> 首次落地见 `documents/devlog/当前版本迭代记录/v1.5.3-T002-COMPETE-READY/部署验收记录.md`。

### 必做

- 安全组最小化：只放行 `22`、`80`；删除 RDP `3389`、ICMP 等无关入方向规则。纯 IP + HTTP 无需 ICP 备案；固定带宽按带宽计费，不按流量计费。
- 2G 内存主机先建 2G swap，并设置 `Asia/Shanghai`。
- 云镜像通常未预装 Docker：`apt-get install -y docker.io docker-compose-v2`；不要只执行 `systemctl enable --now docker`。
- 写 `.env.prod` 后 `chmod 600`；不在对话、文档、提交材料中回显数据库密码与 AI Key。
- AI Key 先直连网关自测（期望返回 `{"choices":[...]}`）；智谱 Key 为 49 位、含一个点，长度或格式不对会返回 `401 令牌已过期或验证不正确`。
- 构建前确认容器内 Debian 源可达；不可达时在 `Dockerfile` 两阶段 `apt-get update` 前把 `deb.debian.org` 替换为 `mirrors.aliyun.com`（补丁需回写仓库，避免只在服务器生效）。
- 启动：`docker compose --env-file .env.prod -f docker-compose.prod.yml up -d --build`；确认 `80 → 8088`、3306 不映射、`restart: always`、日志 `10m × 3`。
- 演示数据：`docker compose --env-file .env.prod -f docker-compose.prod.yml exec app node scripts/seed_demo.js`，校验加 `--verify`。
- 演示账号统一使用评审期公开体验口令（登录页已预填主推账号），评审材料清单同步记录；3 个账号各自独立，避免评委互相干扰。
- 后续同机加站：不锁死端口，采用 Nginx 反向代理，本应用退回内网端口，代码不动（本期不做）。
- SSH 上禁止用会匹配自身命令行的 `pkill -f`（如 `pkill -f "docker compose"` 会断开当前连接）；改用 `pgrep -f "[d]ocker compose"`、`fuser -k 80/tcp`。
- 部署后清理临时探针与临时公钥（如 `/root/.ssh/authorized_keys` 中的部署公钥）。
