## 三、代码风格规范

### 3.1 通用原则

- **可读性优先**：代码是给人读的，其次才是给机器执行；命名清晰优于简短。尽量减少代码行数，意义明确且实现同一功能的代码可压缩至同一行。
- **一致性优先**：与既有代码风格保持一致，不引入混合格式。
- **最小化依赖**：不引入需求外的三方库；优先使用语言标准库。

### 3.2 C++ 后端规范

- 大括号风格：原有代码不变，**后续代码用 Allman 风格，左侧大括号换行（除非左右大括号在同一行）**。
- 命名约定：类名 PascalCase，函数/变量 camel_case，常量 UPPER_SNAKE_CASE，私有成员以下划线结尾。
- 头文件保护：使用 `#pragma once`，不使用 `#ifndef` guard。
- 包含顺序：系统头文件 → 第三方头文件 → 本项目头文件，每类之间空一行。
- 异常处理：关键路径使用 try-catch 捕获，不吞异常；错误信息经 `Db::escape()` 转义后输出。

### 3.3 JavaScript / Node.js 规范

- 使用 `const` / `let`，禁用 `var`。
- 异步代码使用 `async/await`，不嵌套回调。
- 错误处理：每个 async 函数末尾有 try-catch，错误统一 `return { ok: false, msg: '...' }`。
- 测试文件：每个测试套件顶部定义 `pass` / `fail` / `skipped` 计数器，输出格式统一为 `✓` / `✗` / `~`。

### 3.4 HTML / CSS 规范

- 页面结构：使用语义化标签（`<header>`、`<nav>`、`<main>`、`<section>`、`<footer>`）。
- 样式集中：所有设计令牌（颜色、圆角、阴影、间距）定义在 `frontend/static/style.css` 的 `:root` 中，页面内不散落魔法值。
- 字体：所有字体 woff2 文件存放于 `frontend/static/fonts/`，通过 `@font-face` 加载。
- 禁止行内样式：不使用 `style="..."` 属性。
## 五、数据库与接口变更规范

### 5.1 数据库

- 变更 SQL 统一存放 `scripts/sql/`，文件名按序号编号并具描述性。
- **加表/加列视为兼容变更（MINOR）**；正式版本完成后，删表/删列/改列确需则须提供数据迁移方案。
- 每次结构变更前后各做一次数据库备份（`backups/`）。
- 继续遵循现有约定：InnoDB、utf8mb4、**不设外键**，关联一致性由 Service 层保证；所有删除操作须做子表级联清理。

### 5.2 HTTP 接口

- 路由统一在 `backend/src/main.cpp` 注册；命名使用名词复数、kebab-case 多词连写。
- 新增接口 = MINOR；**删除、改名或改变既有响应结构 = MAJOR**。
- 面向未来如需多版本共存，使用 `/api/v2/...` 路径前缀（当前 `/api/...` 视为 v1）。
- **参数路由（`:id`）必须在具体路由之后注册**，否则具体路由永远匹配不到。

### 5.3 前端

- 保持原生 HTML + CSS + JS、由后端托管、无独立前端服务的现状。
- 颜色、字体、圆角、阴影等设计令牌集中在 `frontend/static/style.css`，页面内不散落魔法值。
- 字体保证离线可用；静态托管须配置正确 MIME。

## 六、AI 使用边界

1. 遇到安全问题时，必须向我询问。
2. 提示词整段一次发送：用户写好的完整提示词须原样构造为一次请求，禁止软件切割提示词、分段调用再拼接答案。
3. AI 对不适用的内容项应留空/省略，代码侧做空话过滤（"no/none/无"类）。
4. AI 返回内容中的关键判定（如"会读/会写"掌握要求）以代码规则为准，不盲信 AI。
5. AI 模型与网关配置变更须在任务文档中记录兼容性结论。
6. 对于非安全、格式问题，不给 AI 加强制性约束。
