## 一、目标

将 AI 固化输出改为「核心字段结构化 + 讲解内容 Markdown 整块存储」的混合模式：

- **保留结构化**：`definitions`、`collocations`、`synonyms`、`antonyms` 仍写子表，行为不变。
- **改为 Markdown**：`phonetic`、`root_analysis`、`word_family`、`allusions`、`synonym_analysis`、`phrase_analysis`、`key_points`、`frequency_note`、`register_note`、`cultural_note`、`related_words` 由 AI 整块输出，写入一条 `kp_extras`（`extra_type='markdown_content'`）。
- **兼容旧数据**：AI 未返回 `markdown_content` 时走旧逻辑逐条写 extras；旧条目详情继续用 `\n→<br>` 渲染。

## 三、任务分解

### T1：prompts.h 混合 schema

**文件**：`backend/include/prompts.h`

1. 新增 `KP_HYBRID_JSON_SCHEMA`：

```
{
  "standard_content": "单词/短语",
  "difficulty": 1-5,
  "definitions": [{"pos":"词性","meaning":"英文核心含义","example":"经典例句"}],
  "collocations": [{"collocation":"固定搭配","example":"例句"}],
  "synonyms": ["同义词"],
  "antonyms": ["反义词"],
  "markdown_content": "# 单词精讲\n\n## 词根与词源\n...\n## 同源词汇\n...\n## 典故、俗语与搭配说明\n...\n## 同义词辨析\n...\n## 短语解析（仅短语）\n...\n## 补充知识\n..."
}
```

2. 新增 `KP_MARKDOWN_RULES`：
   - 用 `##`/`###` 组织章节，不重复结构化字段已覆盖的释义/搭配/近反义词清单；
   - 关键术语用 `**粗体**`；
   - 例句用引用（`>`）或行内代码；
   - 保持连贯讲解，控制篇幅 (这里要求硬编码篇幅最大限制）；不适用章节省略，不写「无 / none」；
   - 展示性文本中文，目标词与英文例句保持英文。

3. `KP_SOLIDIFY_ONE_USER`、`KP_SOLIDIFY_BATCH_USER` 的 `{KP_JSON_SCHEMA}` 换成 `{KP_HYBRID_SCHEMA}`，并在规则区插入 `{KP_MARKDOWN_RULES}`。

4. `KP_SOLIDIFY_SYSTEM`、`KP_SOLIDIFY_BATCH_SYSTEM` 仅补一句：返回 JSON；`markdown_content` 字段值为 Markdown 文本。

5. 保留 `KP_JSON_SCHEMA` 常量与注释（回退参考，不再被模板使用）。

### T3：前端 Markdown 渲染

1. 下载 `frontend/static/marked.min.js`（v12.0.2，MIT）。
2. 新增 `frontend/static/md-render.js`：

## 五、风险与应对

| 风险 | 应对 |
|------|------|
| AI Markdown 格式不规范（无标题、纯段落） | `KP_MARKDOWN_RULES` 明确章节要求；CSS 对纯段落同样有基础排版 |
| AI 在 markdown 中夹带 HTML / 脚本 | 白名单消毒，危险标签整段移除，`on*` 属性剥离 |
| marked 静态文件缺失或损坏 | `renderMarkdown` 检测 `window.marked`，失败降级 `\n→<br>` |
| `kp_extras.content` 为 TEXT（约 64KB） | 提示词约束「控制篇幅」；单条精讲预计远小于上限；若实测超长再单独评估，不擅自改表 |
| 批量固化输出变长导致超时 | 现有单条/批量重试与 `failed_reasons` 保留；失败可重跑 |
| 旧数据与新数据共存 | 前端按 `extra_type` 分支；旧逻辑完全保留 |
| Word 导出未升级 | 本任务采用路径 C，导出仍读旧 extras；新格式条目导出内容会少于详情，已知并接受 |
