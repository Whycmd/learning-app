# 开发者使用指南

> 适用版本：v1.4.1 ｜ 更新日期：2026-11-06
> 读者：第一次接触本仓库的开发者、协作者，以及三个月后回来接手的人。
> 目标：读完能独立把项目跑起来、改代码、跑测试、看懂报错。

## 一、先搞清楚这个项目是什么

- 一个**本地运行**的英语学习软件：录入单词 → AI 生成精讲 → 存进自己的 MySQL → 按遗忘曲线复习 → AI 出题/批改/小测。
- 技术栈：C++17 后端（自研 HTTP 服务，端口 8088）+ 原生 HTML/CSS/JS 前端 + MySQL 8.0 + Node.js 20（AI 网关 5340）。
- 没有前端构建工具：改 HTML/CSS/JS 保存即生效，刷新浏览器就能看到。
- 学习数据全部在本机（或 Docker 卷），只有 AI 请求经本地网关发给智谱 `glm-4-flash`。

先建立这个认知，后面的目录和命令就都好理解了。

## 二、5 分钟跑起来（三种方式选一种）

### 方式 A：Docker（推荐，macOS / Linux / Windows 通用）

**前置**：装好 Docker Desktop（Windows 需要 WSL2）。首次打开可以不登录账号。

```bash
git clone https://github.com/Whycmd/learning-app.git
cd learning-app
cp .env.example .env          # 编辑填入 ZHIPU_API_KEY；先不填也能启动，只是 AI 功能不可用
docker compose up -d          # 首次 3-5 分钟（拉镜像 + 编译 C++ + 建库建表）
```

打开 <http://127.0.0.1:8088> 即可使用。

日常命令：

```bash
docker compose logs -f app    # 看应用日志（Ctrl+C 退出）
docker compose down           # 停止（数据保留在卷 mysql_data）
docker compose down -v        # 停止并清空数据（慎用）
docker compose up -d --build  # 改了后端 C++ 代码后重新编译
```

> 为什么首次慢？因为要在容器里编译 C++，还要下载 mysql:8.0 和 node:20-slim 两个基础镜像。
> 国内网络默认走 `docker.m.daocloud.io` 加速器；能直连 Docker Hub 时，把 `.env` 里的
> `MYSQL_IMAGE` / `BASE_IMAGE` 改回官方镜像名即可。

### 方式 B：本机模式（仅 macOS，适合改后端时快速迭代）

**前置**：Node.js 20、MySQL 8.0、C++ 编译器（Xcode Command Line Tools）、智谱 API Key。

```bash
cp config/ai.example.json config/ai.json   # 保持 api_key 留空
bash scripts/ai_key_store.sh set           # 按提示输入 Key，写入 ~/.config/eng-app/ai.key（0600）
bash scripts/build_backend.sh              # 编译后端，产物在 backend/build/eng_app_server
./dev up --host                            # 起本机 MySQL + AI 网关 + 后端
```

打开 <http://127.0.0.1:8088>。停止：

```bash
./dev down
```

> 本机模式的数据在 `~/.local/mysql`，socket 在 `~/.local/run/mysql.sock`，
> root 密码在 `~/.local/mysql/.root_pw`。换电脑时这些路径要一起改
> （`config/db.json` 或环境变量），这也是 Docker 模式更省心的原因。

### 方式 C：GitHub Codespaces（云端，什么都不用装）

仓库自带 `.devcontainer/devcontainer.json`，在 GitHub 上点「Code → Codespaces」创建，
启动后会自动构建并转发 8088 端口。把 Key 配到仓库 Secrets 或容器内的 `.env` 即可。

## 三、统一入口：`./dev`

所有常用操作都收敛到根目录一个脚本，不用记一堆命令名：

| 命令 | 作用 | 底层实际做的事 |
|---|---|---|
| `./dev up` | 启动 Docker 容器 | `docker compose up -d` |
| `./dev up --host` | 启动本机三件套 | `start_mysql.sh` + `start_localai.sh` + 后端 |
| `./dev down` | 停止所有服务 | `docker compose down` / `scripts/stop_all.sh` |
| `./dev debug` | 调试模式 | 数据库和网关在后台，后端日志直接打屏 |
| `./dev logs [行数]` | 看日志 | 容器在跑看容器，否则看本机三个日志文件 |
| `./dev doctor` | 环境自检 | 编译器、Node、配置、AI Key、数据库、端口、Docker、测试环境 |
| `./dev test` | 全量回归 | 自动发现 `tests/*.test.js`，17 个套件 |
| `./dev test 2` | 只跑 stage2 | 秒级反馈，改哪块先跑哪块 |

两个容易忽略的细节：

1. **`./dev test` 会自动选执行环境**：容器在跑就进容器跑，否则在本机跑。
   原因是两边的 MySQL 是两套数据，混跑会连不上库。
2. **`./dev doctor` 先跑一遍再提问**：它会把「编译器坏了」「Key 是中文」「端口被占」
   这类问题直接指出来，比看报错猜快得多。

## 五、配置怎么改

| 文件 | 关键字段 | 说明 |
|---|---|---|
| `config/app.json` | `name`、`version`、`host`、`port`、Word 临时目录与保留时间 | 应用元信息与端口 |
| `config/db.json` | `host`、`port`、`user`、`password_file`、`database`、`socket` | 本机模式数据库连接；Docker 模式由 entrypoint 覆盖 |
| `config/ai.json` | `model`、`request_timeout_sec`、`retry_times`、`max_concurrency` | 网关地址与模型参数；`api_key` 留空 |
| `~/.config/eng-app/ai.key` | AI Key 密钥文件 | 权限必须 600；用 `bash scripts/ai_key_store.sh` 维护；路径可用 `ENG_AI_KEY_FILE` 覆盖 |
| `config/rewards.json` | 金桂阈值、朱砂印等级、称谓等级、周规系数 | 点金圣殿规则 |
| `.env`（复制自模板） | `ZHIPU_API_KEY`、`MYSQL_ROOT_PASSWORD`、`APP_PORT`、`TZ` | 仅 Docker 模式；`.env` 不入库 |

三个安全约定：

1. 真实 Key 存于 `~/.config/eng-app/ai.key`（权限 600），`config/ai.json` 的 `api_key` 保持留空；读取优先级 密钥文件 → `ZHIPU_API_KEY` → 配置文件。
2. `config/db.json` 里 `password_file` 指向密码文件而不是密码本身，密码文件同样不入库。
3. 端口映射只写 `127.0.0.1:8088`：本机能用，局域网其他设备访问不到。要对外必须先改这里。

## 六、数据库与数据

- **表结构**：`scripts/sql/` 下 8 个 SQL，容器首次启动（数据卷为空）时由 MySQL 自动执行。
- **已初始化后再改表**：SQL 不会重跑。请手动执行，或把 SQL 放进 `scripts/sql/` 后
  先 `docker compose down -v` 清空再启动（会丢数据，慎重）。
- **Docker 数据**：命名卷 `mysql_data`。`down` 不删，`down -v` 才删。
- **本机数据**：`~/.local/mysql/`（数据目录）、`~/.local/run/mysql.sock`（连接）、
  `~/.local/mysql/.root_pw`（root 密码）。
- **备份**：`backups/`，应用内维护功能会生成；容器里的 Word 产物通过 `./word_tmp` 挂载到宿主机。
- **一致性巡检**：

```bash
node scripts/check_consistency.js          # 只报告，退出码 0/2
node scripts/check_consistency.js --fix    # 自动修复结构孤儿（不改用户归属）
node scripts/check_consistency.js --json /tmp/report.json
```

## 八、调试怎么做

### 后端断点式调试

```bash
./dev debug     # 数据库与网关在后台，后端日志直接打屏，Ctrl+C 停止
```

这比 `./dev up --host` 更适合改代码：改完重新 `bash scripts/build_backend.sh`，
再 `./dev debug`，日志就在眼前滚动。

### 日志在哪

| 位置 | 内容 |
|---|---|
| `~/.local/log/backend.out` | 本机后端 stdout/stderr |
| `~/.local/log/mysqld.err` | 本机 MySQL 错误日志 |
| `~/.local/log/localai.out` | 本机 AI 网关日志 |
| `~/.local/log/log_rotate.out` | 日志轮转事件（只记文件名、大小、时间） |
| `docker compose logs -f app` | 容器内后端 + 网关 |
| `docker compose logs -f db` | 容器内 MySQL |

`./dev logs` 会自动判断该看哪一组。

应用日志（`eng_app.out` / `backend.out` / `localai.out` / `log_rotate.out`）由 `scripts/log_rotate.js` 后台轮转：超过 10MB 切分为 `.1`~`.7`，每个文件保留 7 份；启动时清理超量归档。阈值、保留份数与检查间隔在 `config/log.json`，改完重启即可生效。手动执行一次：`node scripts/log_rotate.js --once --dir ~/.local/log`。

### 冒烟检查（比打开页面更快）

```bash
curl -s -o /dev/null -w '%{http_code}\n' http://127.0.0.1:8088/      # 期望 200
curl -s http://127.0.0.1:5340/readyz                                   # 网关就绪与 Key 状态
lsof -nP -iTCP:8088 -sTCP:LISTEN                                       # 谁占了 8088
```

## 九、排障手册

| 症状 | 原因 | 处理 |
|---|---|---|
| `clang++: error: 'string' file not found` / `No developer tools were found` | Command Line Tools 缺失或损坏 | 先 `./dev doctor` 确认；见附录 A |
| `xcode-select --install` 点「安装」后失败 | Apple CLT 安装器自身缺陷（Apple Silicon 上 `machdep.cpu.features` 为空） | 用附录 A 的组件包安装法 |
| `Can't connect to MySQL server on '127.0.0.1:3306'` | 本机 MySQL 没起，或起后被杀 | `bash scripts/start_mysql.sh`；确认命令会话没有退出 |
| 端口 8088 被占用 | Docker 容器与本机后端只能活一个 | `./dev down` 后再 `./dev up --host` |
| 容器里中文查出来是 `??` | `mariadb-client` 默认 latin1 | 客户端加 `--default-character-set=utf8mb4`（测试已由 `_mysql_tcp_shim.sh` 代劳） |
| 网关反复重启、固化任务全断 | `api_key` 含中文等非 ASCII 字符，Node 拼进 HTTP 头时报 `ERR_INVALID_CHAR` | `./dev doctor` 会标红；`bash scripts/ai_key_store.sh check` 检查密钥文件；换成真实 ASCII Key |
| `docker compose up` 卡在拉镜像 | Docker Hub 国内不可达 | 默认已走 daocloud 加速；必要时换其他镜像源 |
| 容器内 `Access denied for user 'root'` | MySQL 官方镜像 root 默认只允许 localhost | 已有数据卷时手动 `CREATE USER 'root'@'%'` 并 `GRANT ALL`；新卷已由 compose 处理 |
| `docker compose` 报 `project name must not be empty` | 目录名含中文 | compose 已显式 `name: english-learning-app`，不要删这一行 |
| 后台启动的服务很快消失 | 启动命令的会话结束会带走子进程 | 用 `./dev up --host`（脚本内 `nohup` + `disown`），或把「启动 + 测试」放在同一条命令里 |
| `stage14` / `stage15` / `stage16` 对不上文档 | 历史编号冲突 | 以仓库实际文件为准：14=一致性、15=HTTP 加固、16=对外资产 |

## 十、改代码的标准流程

1. **改前端**：直接编辑 `frontend/`，刷新浏览器，无需编译。
2. **改后端**：编辑 `backend/include/*.h` 或 `backend/src/*.cpp`，然后
   `bash scripts/build_backend.sh`（宿主机）或 `docker compose up -d --build`（容器）。
3. **改测试**：新增套件请用 `tests/stage{n}_{名字}.test.js`，n 取当前最大号 +1。
4. **跑回归**：先 `./dev test <改动相关的 stage>`，再 `./dev test` 全量。
5. **同步文档**：涉及接口、配置、命令的改动，必须同步更新文档（见第十一节）。

提交前的最低要求（与 `CONTRIBUTING.md` 一致）：

- [ ] 改动范围内自测通过
- [ ] `node tests/run_all.js` 17 个套件全部通过
- [ ] 没有把 Key、密码、本机绝对路径提交进仓库
- [ ] 文档与实际代码一致

## 附录 A：Apple Command Line Tools 安装失败的处理

适用于 macOS（尤其 Apple Silicon）。典型现象：

```text
clang++: error: unable to locate a suitable SDK for the system
xcode-select: error: Unable to get active developer directory
```

并伴随 `xcode-select --install` 弹出的安装器点「安装」后失败，
`/var/log/install.log` 出现：

```text
installation-check ... TypeError: null is not an object (evaluating 'cpuFeatures.split')
```

根因：安装包自带的检查脚本执行 `sysctl -n machdep.cpu.features`，该值在 Apple Silicon
上为空，脚本崩溃，安装还没开始就结束。和你的权限、网络无关。

绕过方法：跳过「产品级检查」，直接从 Apple 软件更新目录安装**组件包**。

1. 取当前系统的软件更新目录（例如 macOS 27 对应 `index-27-1.sucatalog`）：

```bash
curl -sS -o /tmp/c.sucatalog "https://swscan.apple.com/content/catalogs/others/index-27-1.sucatalog"
gunzip -c /tmp/c.sucatalog > /tmp/c.xml 2>/dev/null || cp /tmp/c.sucatalog /tmp/c.xml
python3 - <<'EOF'
import re
x = open('/tmp/c.xml').read()
for u in sorted(set(re.findall(r'https://[^\s<"]*CLTools[^\s<"]*pkg', x))):
    print(u)
EOF
```

2. 下载并逐个安装（会要求输入管理员密码）：

```bash
# 按上一步输出的地址下载以下四个包：
#   CLTools_Executables.pkg        （编译器本体）
#   CLTools_macOSNMOS_SDK.pkg      （当前系统 SDK）
#   CLTools_macOSLMOS_SDK.pkg      （兼容 SDK）
#   CLTools_SwiftBackDeploy.pkg    （Swift 兼容库）
for p in CLTools_Executables CLTools_macOSNMOS_SDK CLTools_macOSLMOS_SDK CLTools_SwiftBackDeploy; do
  sudo installer -pkg "/tmp/clt/$p.pkg" -target /
done
```

3. 验证：

```bash
xcode-select -p          # 应输出 /Library/Developer/CommandLineTools
clang++ --version        # 应输出 Apple clang 版本
echo '#include <string>' | clang++ -x c++ -fsyntax-only - && echo OK
./dev doctor
```

> 说明：`installer -pkg` 只执行单个组件的安装脚本，不跑那个会崩的产品级检查，
> 所以能绕过该缺陷。系统大版本升级后若再次清空 CLT，需要重复一次。

## 附录 B：常见环境变量一览

| 变量 | 作用 | 默认 |
|---|---|---|
