## 一、核心诉求

我们做对外开放，要解决三个真实诉求：

1. **收集建议**：让更多人看到并使用本项目，通过 GitHub Issues 提建议，我们逐个完善（当前 v1.4.0 的 P0 缺陷与改进项正是来自小范围用户反馈，这条路已被验证有效）；
2. **支撑团队协作**：项目已转为团队项目，新成员（Windows 为主）需要能低成本地把项目跑起来，才能读代码、改代码、参与开发；
3. **不分散精力、不花钱办大事**：我们仍处于功能快速迭代期（v1.4.0 进行中），开放工作不能喧宾夺主——投入要一次性、可复用，长期成本要锁死。

**一句话：让开发者"一条命令跑起来、提建议"，让普通用户"打开浏览器就能用"，且长期花费不超过 ¥99/年。**

## 二、为什么选这个方案

### 2.1 方案

| 阶段 | 受众 | 方式 | 花费 |
|------|------|------|------|
| 阶段一 | 开发者 | **Linux 移植 + Docker 化**：`docker compose up` 一键起；GitHub Codespaces 浏览器运行作备选 | **¥0** |
| 阶段二 | 普通用户 | 同一套 Docker 部署到云服务器，浏览器注册即用 | **¥99/年** |

### 2.2 选择理由

**为什么必须先做 Linux 移植（而不是绕开它）**

现状是硬约束：后端为 C++17 + Apple clang + Unix Socket 连 MySQL，脚本全部硬编码 `/Users/junwang/.local`。这意味着——
- Windows 开发者无法编译运行；
- 即使同为 macOS 用户，clone 下来也跑不起来；
- 云服务器全是 Linux（macOS 云主机 ¥500+/月，排除）。

所以"让别人能跑"的每一条路（Docker、Codespaces、在线服务）都汇聚于同一个前提：**移植到 Linux + 去硬编码**。这是一次性核心工作量，做完之后阶段一、阶段二全部受益，没有返工。

**为什么开发者侧主推 Docker（而不是写部署文档让人手工装环境）**

我们的依赖链很长：C++ 编译环境 + MySQL 8.0 + Node.js 20 + 智谱 API Key。写成文档让 Windows 开发者手工配，90% 的人会在中途放弃。Docker 把整条依赖链封进 `docker-compose.yml`，开发者只需装 Docker Desktop（个人免费）后执行一条命令——环境差异、路径问题、初始化流程全部被消灭。

**为什么不移植 Windows 原生版 / 不做桌面安装包**

- Windows 原生移植：Unix Socket、Apple clang 特性、mysql 客户端库都要改造，工程量大且后续每行代码都要维护两个平台，排除；
- 桌面安装包：需要 MySQL→SQLite + 后端改单进程嵌入，等于半重写。在线服务即本项目的最终形态（参照 TypeWords，它对普通用户也只提供网页版）。

**为什么在线服务选阿里云 99 元档（而不是新客促销机或免费方案）**

- 新客促销机（首年 ¥28-68）续费贵，需每年迁移一次，Docker 化后迁移虽只要 1–2 小时，但年年折腾 + 数据搬迁风险，省几十元不值；
- Oracle Cloud 永久免费（4核24G）很诱人，但注册需外币信用卡、ARM 架构适配、账号有回收风险，必须每日异地备份——可作为备选，不作为主力；
- 阿里云"99计划"：**¥99/年且续费同价**，最长锁定至 2030 年，是国内唯一把长期成本锁死的方案。2核2G + 3M 带宽对纯文本学习应用绰绰有余。

**参照 TypeWords**

它验证了同类产品的开放路径：在线站零门槛体验 → README 写清运行方法 → Issues 收建议 → 社区贡献。它靠纯前端架构把成本压到 ¥0；我们架构更重，¥0 做不到，但 **¥99/年 + 一次性 Linux 移植**可以达到同等的对外效果。

## 三、实现后的效果

**对开发者（阶段一完成后）**

- 任何一台 Windows/Mac 电脑：装好 Docker Desktop → `git clone` → `docker compose up` → 浏览器打开 `http://127.0.0.1:8088`，完整功能可用（MySQL 自动初始化、AI 网关自动启动）；
- 不想装任何环境：在 GitHub 仓库页点 Codespaces 按钮，浏览器里直接运行、调试、改代码；
- 有想法或发现问题：直接在 Issues 里提（附模板分类），我们按优先级排进开发计划；
- README 对齐成熟开源项目：定位、功能、运行指南、AI Key 申请指引、Issue/PR 邀请，一目了然。

**对普通用户（阶段二完成后）**

- 无需任何技术背景：打开链接 → 注册账号 → 直接使用全部学习功能，数据按用户隔离（多用户认证已上线，天然支持）；
- 我们先发邀请链接小范围试用，稳定后再公开。

**对我们自己**

- 建议渠道从"熟人截图反馈"升级为 GitHub Issues，可追踪、可分类、可闭环；
- Docker 化同时解决我们自己的环境问题：新成员加入、换电脑、部署服务器，都是同一套镜像；
- 长期成本锁死：阶段一 ¥0，阶段二 ¥99/年至 2030 年。

## 四、开发者如何使用（阶段一完成后的完整流程）

```bash
# 前提：已安装 Docker Desktop（Windows/Mac 均免费）
git clone https://github.com/Whycmd/learning-app.git
cd learning-app

# 填入自己的智谱 API Key（免费申请，README 附指引）
cp config/ai.example.json config/ai.json   # 编辑填入 Key

# 一条命令启动全部服务（MySQL 初始化 + AI 网关 + 后端）
docker compose up
```

浏览器打开 `http://127.0.0.1:8088` 即可使用。之后：

- **读代码**：目录结构、模块说明见 README 与 `documents/`；
- **跑测试**：`npm test`（容器内已含测试环境）；
- **改代码**：开分支 → 提交 → 提 PR（流程见 [CONTRIBUTING.md](../../CONTRIBUTING.md)）；
- **提建议/报 Bug**：GitHub Issues，按模板选「功能建议 / Bug / 体验反馈」。

无 Docker 的备选：仓库页 **Code → Codespaces → Create**，浏览器内获得同款环境（用开发者本人每月 120 核时的 GitHub 免费额度）。

## 五、现状约束（方案依据的事实）

| 事实 | 影响 |
|------|------|
| 后端 C++17，Apple clang 编译，手写 HTTP 服务器 + Unix Socket 连 MySQL | Windows 无法直接编译；仅设计监听 127.0.0.1，未经公网安全考验 |
| 脚本/配置硬编码 `/Users/junwang/.local/...`，MySQL 为便携版解压安装 | 同 macOS 用户也无法直接运行 |
| 依赖链：C++ 编译环境 + MySQL 8.0 + Node.js 20 + 智谱 API Key（免费，需国内手机号） | 手工部署门槛高 → 必须 Docker 化 |
| 数据库初始化脚本 `scripts/sql/*.sql`（7 个）已具备 | 初始化可脚本化，Docker 化直接复用 |
| 多用户认证已上线（users/user_sessions） | 在线服务无结构性障碍 |
| 后端代码为 C++17 + POSIX socket + 嵌入式 Crow（header-only） | 移植 Linux 大概率只需小改，真正未知点在 mysql 客户端库链接与脚本适配 |

## 六、阶段一：向开发者开放（¥0）——工作内容

1. **Linux 移植 + 去硬编码**（核心前提）：Linux 下编译通过；路径改相对项目根目录/环境变量；MySQL 连接、AI 网关地址参数化；
2. **Docker 化**：`docker-compose.yml` 编排 MySQL 8.0（自动执行 `scripts/sql/` 初始化）+ AI 网关 + C++ 后端；
3. **Codespaces 备选**：`.devcontainer` 配置；
4. **README 重写**：定位 → 功能清单 → 运行指南 → AI Key 申请指引 → Issue/PR 邀请；
5. **建议收集渠道**：GitHub Issues 模板（功能建议 / Bug / 体验反馈）。

**明确不做**（本轮共识）：Windows 原生移植、桌面安装包、演示视频/截图。

## 七、阶段二：向普通用户开放（¥99/年）——工作内容

1. **邀请制体验**：同一套 `docker compose` 部署到阿里云，发邀请链接/访问密码小范围试用；
2. **公开访问**：开放注册，配套：
   - Caddy/Nginx 反向代理（HTTPS + 隔离手写 HTTP 服务器，不直接暴露公网）；
   - AI 配额制（防单人刷光免费额度），或用户在设置页填自己的智谱 Key（成本转移）；
   - 数据库每日备份；
3. **安全前提**：上线前完成手写 HTTP 服务器加固（与已有任务 v1.2.0-T008 合并考虑）。

## 八、风险与对策

| 风险 | 对策 |
|------|------|
| Linux 移植工作量未知（mysql 客户端库链接、系统差异） | 先做一次 Spike 验证编译，再排正式计划 |
| 手写 HTTP 服务器公网暴露风险 | 反代隔离 + 阶段二前完成 T008 加固；邀请制先行 |
| AI 免费额度被刷 | 配额制 + 用户自带 Key 出口 |
| 密钥泄露 | `config/ai.json` 已在 .gitignore 且从未进入 git 历史，持续保持 |
| 阿里云 99 元档共享型 CPU 性能有限 | 本应用轻负载适用；长期高负载再升配 |
