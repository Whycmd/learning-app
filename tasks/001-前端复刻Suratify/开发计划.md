## 一、需求来源（《主要问题.docx》两个核心问题）

1. **UI 视觉设计完全没有** —— 需要做成 Suratify 那样精美、有质感的设计；
2. **AI 提示词被软件切割、分段回答再拼接** —— 必须把用户写好的**整段提示词原样一次扔给 AI**，得到一个完整、前后逻辑连贯的输出。

---

### 2.2 页面结构（实测）

- **顶部控制台横幅卡**：「SURATIFY · 控制台」胶囊徽章 + 衬线大字「欢迎回来」+ 学习/愿景切换 + 词币胶囊 + 用户中心按钮 + 图标行（深色模式/重建巴别塔/语言包市场/备份导入/退出）+ 账号胶囊；右上角有青色径向光晕，135° 暖色渐变底，22px 圆角，分层阴影。
- **信息栏卡**：更新日志（可折叠）+ 统计行（已创建语言包/累计用户/单词条数/近24h 活跃）。
- **主要功能卡**：2×2 大按钮（我想…/语境翻译/播放复习/每日答题·赚词币），圆形图标。
- **今日待办卡**：今日 n（青徽章）· 探索 n（琥珀徽章），可折叠。
- **语言包卡**：提示条（渐变描边）+「新建与导入」渐变主按钮 + 搜索；语言包内层白卡（衬线标题 + 编辑/分享/更多 +「共 n 条」「AI 未改 · 共 n 条」徽章）。
- **练习模式卡**：顶部四色渐变描边；练习语言包多选下拉；朗读语言下拉；听力/口语/阅读/写作四个彩色描边按钮。
- **悬浮反馈按钮**：左下，圆形对话图标。

### 2.3 现状盘点（本项目真实代码）

- C++ 后端 30 个 REST API（知识点/学情/习题/维护）+ 本地 MySQL（10 表）+ 智谱 GLM-4-Flash 网关。
- 前端：1 首页 + 5 页（kp-entry / kp-detail / review / learning-center / articles），原生 HTML，style.css 仅 33 行，确无视觉设计。

### 2.4 功能映射（Suratify 概念 → 本项目真实功能）

| Suratify | 本项目 |
|----------|--------|
| 欢迎回来控制台 | 首页（健康/统计/快速入口）|
| 语言包 + 新建导入 + AI 未改徽章 | 知识点列表 + 录入 + AI 固化状态 |
| 语言包词条（外文/母语/听说掌握度条）| 知识点释义/搭配/近义反义 + 熟练度 |
| 练习模式：听·说·读·写 | 每日复习 + AI 出题（6 题型，实际为读/写类）|
| 用户中心/备份导入 | 学情中心：统计 + 备份 + 重置 |
| 今日待办 | 待复习候选数量 |

> 说明：忠实复刻**视觉与交互范式**；页面内业务数据全部对接本项目既有真实 API，不伪造、不新增未实现后端能力（如词币/市场无后端则不做假数据）。

## 四、验收标准

1. 6 个页面在浏览器中与 Suratify **视觉一致**：配色、字体（Fraunces 衬线标题 + Karla 正文）、圆角、渐变、分层阴影、按钮/徽章/卡片质感、悬浮反馈；
2. 所有交互对接**真实后端 API**，功能闭环不回退（录入→固化→复习→出题→批改→学情）；
3. AI 调用为**整段提示词一次请求、一次完整返回**，无切割拼接；
4. 字体本地化，断网时界面视觉不退化；
5. 阶段五前端测试更新并通过，全量 7 套件回归通过。

## 五、风险与回退

- 风险：Suratify 为窄视口（592px）移动优先设计，桌面宽屏需做容器约束（保持单列卡片居中，不擅自改版）。
- 回退：改动均在 `frontend/` 与后端提示词函数内；保留现有 git 工作区，必要时按文件回退，不做破坏性删除。
